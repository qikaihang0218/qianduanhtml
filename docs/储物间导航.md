# 储物间导航 · 操作文档

> 源文件：[../储物间导航.html](../储物间导航.html)
> 页面标题：`阿虚同学 · 森系储物间导航`（页面内主标题为 `阿虚同学 · 储物间导航`）
> 一句话定位：一个**可增删改、可用 Excel 批量导入导出的个人网址导航页**，数据存在浏览器本地，森系毛玻璃外观。
>
> 本文所有键位、取值范围、格式清单与存储键均基于当前仓库源码核对。

## 1. 工具简介

它不是一个「小工具」，而是一个**能长期用下去的起始页**：左侧栏放常用分类、顶部放实用查询入口、下方放酷站大全，三类内容都能在线编辑，改完自动存本地；攒够了可以一键导出成 Excel 备份，换电脑时把那份 Excel 拖回页面即可完整迁移。

三段结构是**固定**的，不能改布局、不能加第四段：

| 区域 | 数据字段 | 组织形式 | 能改什么 |
| ---- | ---- | ---- | ---- |
| 左侧栏 | `sidebar` | 分类 → 链接（`title` + `items`） | 加/删链接、改链接、改分类名、加分类 |
| 顶部实用查询 | `query` | **扁平链接列表**（无分类） | 加/删链接、改链接 |
| 酷站大全 | `directory` | 分类行 → 链接（`label` + `items`） | 同左侧栏 |

适合谁用：想把自己那几十个常用站点收进一个本地页面、又**不希望账号和收藏躺在某个云上**的人；以及习惯用 Excel 批量整理数据的人 —— Excel 往返是它区别于普通导航页的核心能力。

**不适合的场景 / 明确没有的能力**：

- ❌ **不能删除分类**。只能改名和新增。空分类会一直留在页面上（详见 FAQ）。
- ❌ **不能拖拽排序**，链接只能追加到组末尾，顺序调整只能靠「删了重加」或改 Excel。
- ❌ **无撤销**。删链接有 `确定` 弹窗拦一下，但**导入 Excel 是「直接覆盖全部」且没有任何确认**（`:1001`），这是本工具最危险的一处。
- ❌ 无文件夹/书签导入（Netscape 书签格式、Chrome/Edge 导出都不支持），只认自己导出的那套 Excel 列。
- ❌ 无暗色主题、无图标/标签/收藏排序、无点击统计、无多用户多配置、无同步。
- ⚠️ **两处联网**：SheetJS 走 CDN，每个链接的 favicon 走 DuckDuckGo。与根 README「零依赖」表述不一致，见第 7 章。

## 2. 快速开始

1. 双击 `储物间导航.html`，用 Chrome / Edge / Firefox 打开。
2. **首次打开必须联网**（要下 SheetJS，见第 7 章）。离线首次打开时，页面正常显示、能浏览和编辑，但**导出/导入按钮点了会报错**（`XLSX is not defined`）。
3. 首屏是内置的 **48 个示例站点**（左侧 13 + 顶部 8 + 酷站大全 27），标题右侧会显示 `共 48 个站点`。
4. **试编辑**：鼠标悬停任意链接 → 右上角浮出 `✏️` 和 `✕`。点 `✏️` 改名/改网址，点 `✕` 删除（有确认）。
5. **加链接**：点右上 `＋ 添加` → 选分类 → 填名称和链接 → 确认。网址忘了写 `https://` 会自动补。
6. **搜索**：按 `/` 聚焦搜索框，输入关键词，左侧栏/顶部/酷站大全**三处同时过滤**，不匹配的整组隐藏。
7. **备份**：点 `⬇️ 导出` → 得到 `我的导航数据.xlsx`。这份文件就是你的全部数据。
8. **换电脑**：把那份 xlsx **拖到页面任意位置**（或点 `⬆️ 导入` 选文件）→ 提示 `Excel 数据导入成功！`。

⚠️ 第一次用先点一次导出。因为导入会**无条件覆盖**当前全部内容，手边有备份才敢试。

## 4. 功能操作详解

### 4.1 浏览与打开链接

所有链接 `target="_blank"` 新标签打开。每个链接名前有一个 14×14 的 favicon，来自

```
https://icons.duckduckgo.com/ip3/<hostname>.ico
```

（`:664-667`）。URL 无法被 `new URL()` 解析时不显示图标；图标加载失败时 `onerror` 把它 `visibility:hidden`（保留占位，`:671`）。

> 48 个链接 = 48 次 DuckDuckGo 请求（`loading="lazy"` 有缓解）。**离线时图标全部消失但不影响使用。**

### 4.2 搜索（唯一的全局过滤）

`applyFilter`（`:791-810`）逐条判断，匹配范围是 **链接文字 + `href` 属性**，忽略大小写、忽略首尾空格：

```js
const txt = (a.textContent + ' ' + (a.getAttribute('href') || '')).toLowerCase();
```

- **不匹配分类名** —— 搜「影视」匹配不到 `📺 影视` 这个分组标题本身（除非组内有链接含这两个字）。
- 三段同时过滤；某组内所有链接都被隐藏时，**整组隐藏**（`:799-806`）→ 搜索时页面会「缩」掉一大片，这是设计如此。
- 实时过滤（`input` 事件，`:1057`），无需回车。
- **搜索框是纯视图状态，不写入 localStorage** —— 刷新即清空，但重新渲染后会自动套用当前框内关键词（`:782-783`）。
- 清空关键词 = 恢复全部（空串视为不过滤）。

### 4.3 添加链接

两个入口，行为相同：

1. 顶部 `＋ 添加` → 分类下拉默认停在第一项（`左侧栏 - 影视动漫`），需自己选。
2. 酷站大全某行的 `+ 添加链接` → 下拉**自动预选该行分类**（`:823-825`）。

规则（`:864-886`）：

- 名称和链接**任一为空** → 弹 toast `名称和链接不能为空！`，弹窗不关。
- 链接若不以 `http://` 或 `https://` 开头（正则 `/^https?:\/\//i`），**自动补 `https://`**（`:868`）。所以填 `baidu.com` 会变成 `https://baidu.com`。
- **除此之外零校验**：不检查是否合法域名、不查重。填 `https://` 加任意字符串都能存；同一个站可以重复加 N 次。
- 新链接 `push` 到目标组**末尾**，无法指定位置。
- 成功后立即 `saveData()` + 全量重渲染 + 关弹窗。

### 4.4 编辑链接

`✏️` → 弹窗标题变「编辑链接」，**分类下拉隐藏**（`:833`）。改完点确认即覆盖原条目 `{ name, url }`（`:872-874`）。

**想「移动」到别的分类**：只能在新分类里重新添加一条，再删掉原来那条。

### 4.5 删除链接

`✕` → 原生 `confirm('确定要删除这个链接吗？')`（`:904`）。确认即 `splice` 删除并存盘。**无撤销**，误删只能靠重新添加或回滚到上次导出的 Excel。

### 4.6 分类：改名与新增

- **改名**：悬停分类标题 → `✏️ 改名`（左侧栏）或 `✏️`（酷站行）→ 弹窗预填当前名 → 确认。左侧栏写 `title` 字段，酷站大全写 `label` 字段（`:897-898`）。
- **新增**：`+ 新增左侧分类` / `+ 新增酷站分类行` → 填名字（可带 Emoji）→ 创建**空分类**（`items: []`）。
- 名称为空 → toast `分类名称不能为空！`。
- **不做重名检查**：可以建两个同名分类，导出/导入时同名分类会被**自动合并成一组**（`:975-982`）—— 有时是好事，有时不是。

### 4.7 导出 Excel

`⬇️ 导出`（`:933-956`）把三段**拉平成一个表**，固定 4 列：

| 所在位置 | 分类名称 | 网站名称 | 网站链接 |
| ---- | ---- | ---- | ---- |
| `左侧分类` | 分类的 `title` | 名称 | 网址 |
| `顶部查询` | 固定 `实用查询` | 名称 | 网址 |
| `酷站大全` | 分类的 `label` | 名称 | 网址 |

- **空分类会导出一行「名称/链接为空」的记录**（`:936-937`、`:944-945`）—— 作用是**保住这个空分类不丢**；导入时该行只建组不加链接（`:992` 的 `if (siteName && siteUrl)`）。
- 列宽固定 `15 / 20 / 25 / 40`（`:952`），工作表名 `导航数据`。
- 文件名**固定** `我的导航数据.xlsx`（`:955`）—— **不含时间戳**，重复导出会覆盖同名下载文件（或产生 `(1)` 副本，取决于浏览器）。想要多版本备份必须自己改名。
- 导出的是**当前全部数据**，与搜索框是否过滤无关（导出读 `navData`，不读 DOM）。

### 4.8 导入 Excel（⚠️ 覆盖式）

两种方式：点 `⬆️ 导入` 选文件，或**把文件拖到页面任意位置**。

流程（`:959-1013`）：

1. 扩展名检查：文件名必须以 `.xlsx` 或 `.xls` **结尾（区分大小写）**，否则 `alert('请上传正确的 Excel 文件 (.xlsx 或 .xls)')`。
2. `FileReader.readAsArrayBuffer` → `XLSX.read`。
3. **只读第一个工作表**（`workbook.SheetNames[0]`，`:970`），其余 sheet 忽略。
4. 按 `所在位置` 分派：`左侧分类` / `顶部查询` / `酷站大全`，**这三个值必须一字不差**；其它值（包括空、拼错、多余空格）的行**被静默丢弃**，不报错也不计数。
5. 分类名缺失 → 归入 `未命名分类`（`:986`）。
6. 同分类名的行自动归到同一组（`:975-982`）。
7. **`navData = newData`**（`:1001`）→ **整份替换，不合并、不确认、不可撤销**。原有数据当场消失。
8. 成功 toast `Excel 数据导入成功！`；解析抛错 → `alert('导入失败，请确保文件格式正确（需为导出的 .xlsx 文件）。')`，错误详情进 console。

**导入的破坏性是本工具最大的坑**：一个空 Excel 就能把几百个收藏清光。养成习惯 —— 导入前先点一次 `⬇️ 导出`。

### 4.9 拖拽导入的判定

- 只有 `dataTransfer.types` 含 `Files` 时才显示遮罩（`:1032`）→ 拖文字/链接不会误触发。
- `dragenter/dragover/dragleave/drop` 在 body 上统一 `preventDefault + stopPropagation`（`:1023-1028`），阻止浏览器默认的「打开文件」行为。
- 遮罩隐藏条件较宽松：`relatedTarget === null` 或 `clientX/clientY` 全为 0（`:1041`）。
- `drop` 只取 `files[0]`（`:1051`）→ **多文件拖入只处理第一个**。
- 文件输入框在 `finally` 里清空 `value`（`:1009`）→ 同一个文件可以连续导入两次（否则 `change` 不触发）。

## 5. 快捷键一览

全文只有 **1 个** `keydown` 监听器（`:918-930`），共 2 条规则：

| 按键 | 生效条件 | 动作 | 源码 |
| ---- | ---- | ---- | ---- |
| `/` | 焦点**不在** `INPUT` / `TEXTAREA` / `SELECT` 内，且两个弹窗都未打开 | `preventDefault` 并聚焦搜索框 | `:923-929` |
| `Enter` | `#linkModal` 处于 `.active` | 等效点「确认」提交链接表单 | `:920` |
| `Enter` | `#categoryModal` 处于 `.active` | 等效点「确认」提交分类表单 | `:921` |

**注意点**：

- `Enter` 分支**没有焦点判断**，只要弹窗开着，焦点在任何地方按回车都会提交。两个弹窗同时打开不会发生（入口互斥），但**在弹窗里按回车 = 提交**，无法用回车做别的。
- 输入框内打字时 `/` 正常输出斜杠（守卫已排除 INPUT），设计正确。

未在源码中确认的键位（均**不存在**）：

- ❌ **`Esc` 关闭弹窗** —— 只能点「取消」或点弹窗外的黑色遮罩（`:912-916`）。这是最容易踩的一条。
- ❌ `Esc` 清空搜索、`Ctrl+F` 聚焦搜索、`Ctrl+K`、`A` 新增、`E` 导出、`I` 导入、`↑↓` 选择链接、`Delete` 删除、`Ctrl+Z` 撤销。

鼠标类：

| 手势 | 目标 | 动作 |
| ---- | ---- | ---- |
| 悬停 | 链接 | 浮出 `✏️` `✕` |
| 悬停 | 分类标题 / 酷站标签 | 浮出 `✏️ 改名` |
| 单击 | 弹窗黑色遮罩空白处 | 关闭该弹窗 |
| 拖文件 | 页面任意位置 | 导入 Excel |

## 6. 支持的输入 / 输出格式

### 输入

| 项 | 接受 | 限制 |
| ---- | ---- | ---- |
| Excel 文件 | `.xlsx`、`.xls` | 按**文件扩展名**判断且**区分大小写**（`file.name.endsWith`，`:961`）→ `数据.XLSX` 会被拒；实际解析能力取决于 SheetJS 0.18.5，`.csv` 因扩展名不符也被拒 |
| Excel 结构 | **只读第一个工作表**；表头必须含 `所在位置`、`分类名称`、`网站名称`、`网站链接` 四个中文列名 | 列名必须与导出时**完全一致**（`:985-988`）。多一列无害，少一列该列变 `undefined` → 该行被跳过 |
| `所在位置` 取值 | 仅 `左侧分类` / `顶部查询` / `酷站大全` 三个精确字符串 | 其它值整行静默丢弃 |
| 网站链接 | 任意文本，缺协议时自动补 `https://` | 无域名合法性校验、无重复检查 |
| 分类名 | 任意文本，**支持 Emoji**（占位符明确鼓励） | 不能为空；不查重 |

**不接收**：Netscape 浏览器书签 HTML（Chrome/Edge/Firefox 的「导出书签」）、JSON、CSV、Markdown、URL 列表 txt、其他导航工具的备份格式、图片/图标文件。

### 输出

| 输出 | 形态 |
| ---- | ---- |
| Excel 文件 | 单 sheet `导航数据`，4 列（所在位置 / 分类名称 / 网站名称 / 网站链接），文件名固定 `我的导航数据.xlsx` |
| 本地存储 | `localStorage['myNavData_v7']` = `JSON.stringify(navData)`，结构 `{ sidebar:[{title,items:[{name,url}]}], query:[{name,url}], directory:[{label,items:[…]}] }` |
| 页面显示 | 站点总数、搜索命中过滤、toast 文案 |

**没有的输出**：Markdown 导航页、HTML 静态页导出、JSON 备份文件、CSV、浏览器书签文件、二维码、PDF。**唯一的可携带备份就是那份 xlsx**（或手动从 DevTools 里复制 localStorage 值）。

> 想手工备份 JSON：F12 → Application → Local Storage → `myNavData_v7` → 复制值。恢复时也只能手工粘回去，页面没有 JSON 导入入口。

## 7. 数据与隐私

**这是本工具集中少数「确实会联网」的页面，且是数据最重（几百条个人收藏）的页面，请重点看这一章。**

### 7.1 本地存储

| 项 | 值 |
| ---- | ---- |
| 存储方式 | `localStorage`（**不用** IndexedDB / sessionStorage / Cookie / Service Worker） |
| 键名 | **`myNavData_v7`**（`:649`、`:656`） |
| 内容 | 全部导航数据的 JSON，含**所有站点名称与网址** |
| 写入时机 | 每次增/删/改链接、改分类、导入 Excel 之后（`saveData()`） |
| 写入失败 | `saveData` 里 `catch(e) {}` **静默吞掉**（`:656`）→ 隐私模式或配额满时，你的编辑**当场丢失且毫无提示** |
| 读取失败 | JSON 解析异常时**静默重置为内置示例数据**（`:651-653`）→ 不会覆盖，但旧数据也读不出来 |

**关键推论**：

- 数据**只存在于这台电脑的这个浏览器 profile**。无痕窗口关闭即全丢；清浏览器数据 = 清导航；换浏览器/换电脑/换 profile 都看不到。
- **`v7` 是硬编码版本号**（`:649`）。若将来改数据结构，把键名 bump 成 `v8` 会让旧数据「看起来消失」（其实还在旧键下），需要自己写迁移。
- 浏览器对 localStorage 有域名维度隔离：`file://` 打开与 `http://localhost` 打开**算两个不同来源，数据互不相通**。如果你有时双击打开、有时用本地服务打开，会出现「数据突然变回示例」的错觉 —— 见 FAQ。

### 7.2 网络请求（两处，均非可选）

| 请求 | 地址 | 用途 | 时机 |
| ---- | ---- | ---- | ---- |
| 脚本 | `https://cdnjs.cloudflare.com/ajax/libs/xlsx/0.18.5/xlsx.full.min.js` | SheetJS，Excel 读写 | 每次页面加载 |
| 图标 | `https://icons.duckduckgo.com/ip3/<hostname>.ico` | 每个链接的 favicon | 每个链接渲染时（`loading="lazy"`） |

**隐私含义（重要）**：

> **打开这个页面时，DuckDuckGo 会收到你列表里每一个站点域名的请求。** 也就是说，你存在本地的那份「我收藏了哪些网站」清单，会以域名列表的形式发给第三方。

这是「数据不上传」这句话的边界：**内容确实不出本机，但域名通过 favicon 请求泄露了。** 若清单里有不便外泄的内网/私人站点地址，请把 favicon 相关代码去掉（第 10 章①，一行改动）。

**离线行为**：

- 首次离线打开：SheetJS 拉不到 → 页面正常显示与编辑，`⬇️ 导出` / `⬆️ 导入` 抛 `XLSX is not defined`（无友好提示，只在 console）。已有数据不受影响。
- 之后打开：浏览器磁盘缓存可能命中 CDN，则导出仍可用。
- 图标全部加载失败 → 自动隐藏，页面照常。
- **浏览、搜索、增删改全程离线可用**，只有 Excel 往返需要 SheetJS。

**与根 README 的差异**：README 写「纯 HTML/CSS/JavaScript 实现，无第三方运行时依赖」（`:50-51`），但本页**依赖 SheetJS CDN**；README 也未提及 favicon 外链。以源码实际行为为准。

### 7.3 无埋点

源码内无 `fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` / 统计脚本。除上表两类资源请求外，无任何数据出本机。**不使用** `navigator.geolocation`、剪贴板、麦克风、摄像头。

### 7.4 安全提示（本地 XSS）

渲染时 `item.name` 与 `item.url` **未做 HTML 转义**直接拼进 `innerHTML`（`:673`、`:701`、`:721`、`:746`）。手工敲键盘没事，但**导入一份来路不明的 Excel 时，`网站名称` 列可以携带 `<img src=x onerror=…>` 之类的标签并在你机器上执行**。

因此：**不要导入别人给你的 xlsx，除非你确认它的来源。** 若确有这个需求，先按第 10 章②加一行转义。

## 8. 常见问题（FAQ）

**导入 Excel 把我原来的数据全冲没了，能找回吗？**

大概率不能。导入是 `navData = newData` 整份替换（`:1001`），无撤销、无自动备份。**唯一机会**：如果替换后**还没有触发过任何一次写入**（你没再增删改过任何东西），立刻用 F12 → Application → Local Storage 看 `myNavData_v7` 是否已是新值 —— 导入成功即已写盘，所以通常已被覆盖。**唯一可靠的防线是导入前先点 `⬇️ 导出`。**

**想删掉一个分类，但找不到删除按钮。**

因为**没有这个功能**。`deleteCategory` 在源码中不存在，UI 只提供「改名 + 新增」。变通办法（按推荐度排序）：

1. **导出 Excel → 删掉该分类的所有行（含那行空记录）→ 重新导入**。这是最干净的办法。
2. 把分类改成 `🗑️ 已废弃` 之类，眼不见心不烦。
3. 改源码加一个删除按钮（第 10 章③）。

**点导出/导入按钮完全没反应，也没报错提示。**

十有八九是 **SheetJS 没加载上**（首次打开时断网、CDN 被墙或被广告拦截插件拦了）。F12 Console 里应能看到 `XLSX is not defined`。解决：联网重开；或按第 10 章④改成把 SheetJS 内联进文件，从此彻底离线可用。

**我的 `.XLSX`（大写扩展名）文件被拒绝。**

`file.name.endsWith('.xlsx')` 区分大小写（`:961`）。把文件改名为小写扩展名即可。

**导入明明成功了（提示成功），但数据是空的/少了一大半。**

按顺序查：

1. **列名对不对** —— 必须是 `所在位置`、`分类名称`、`网站名称`、`网站链接` 四个中文列名，一字不差。自己手搓的表最容易在这栽了。
2. **数据在不在第一个工作表** —— 只读 `SheetNames[0]`，放在第二个 sheet 里的内容会被忽略。
3. **`所在位置` 的值** —— 只能是 `左侧分类` / `顶部查询` / `酷站大全`，多一个空格都不行，其它值整行静默丢弃。
4. **`.csv` 改后缀成 `.xlsx`** —— 扩展名检查过了但解析失败或读出乱码。用 Excel 真正「另存为 xlsx」。
5. 打开 F12 Console 看有没有抛错。

**数据丢了/变回默认示例了，但我明明存过。**

三个常见原因：

1. **换了打开方式**：`file://` 双击打开 和 `http://localhost` 打开 是**两个不同的 localStorage 来源**，数据互不可见。固定用一种方式。
2. **用了无痕/隐私窗口**：关闭即清空。
3. **`saveData` 静默失败**：写入异常被 `catch(e){}` 吞掉（`:656`），你以为存了其实没存。无痕模式、存储配额满、部分企业策略都会触发。

**换了电脑 / 重装系统，怎么迁移？**

在旧机器点 `⬇️ 导出` → 把 `我的导航数据.xlsx` 拷到新机器 → 拖进页面。就这两步。没有云同步。

**为什么手机上没法编辑（没有 ✏️ 和 ✕）？**

操作按钮靠 CSS `:hover` 显示（`:316`），触屏没有真正的 hover。**当前实现在触屏上只能浏览和搜索。** 需要手机可编辑请按第 10 章⑤改。

**搜索搜不到某个明明存在的站点。**

搜索只匹配**链接名称文字 + 网址**（`:796`），不匹配分类名。想按分类浏览只能靠肉眼。另外它是**子串包含**匹配，不是分词/模糊搜索，`“阿里网盘”` 搜不到 `阿里云盘`。

**每次导出都叫 `我的导航数据.xlsx`，我想留历史版本。**

文件名硬编码（`:955`）。要么每次下载后手动改名，要么按第 10 章⑥加时间戳。

**链接顺序能调吗？我想把最常用的排前面。**

不能。新链接一律 `push` 到末尾，界面没有拖拽或上下移动。**批量重排的正确做法**：导出 → 在 Excel 里排序 → 重新导入。

**能不能把某个链接挪到别的分类？**

不能，编辑弹窗里分类下拉是隐藏的（`:833`）。只能「目标分类重新添加一条 + 删除原条目」。

**为什么每个站点名字前的小图标都没显示？**

图标来自 DuckDuckGo（`icons.duckduckgo.com`）。离线、被拦截、或该域名本身没有 favicon 时不显示，`onerror` 会自动隐藏它（`:671`）。不影响链接本身。

**链接点开后没有 `https://` 或协议不对。**

只有在**新增/编辑时**才会自动补 `https://`（`:868`）。内置示例里有一条 `http://www.yinghuadm.com`（`:598`、`:620`）就是 http 的，需要手动改。

**能在同一个浏览器里存多套导航（工作/生活）吗？**

不能，单键 `myNavData_v7` 全局唯一。变通：用两个不同浏览器，或按第 10 章⑦做配置切换。

## 9. 技术实现要点（开发者）

**结构**：1061 行单文件。`<style>` `:10-498`（约 488 行），DOM `:500-590`，脚本 `:592-1059`。**脚本是全局作用域，不包 IIFE** —— 所有函数（`renderAll`、`navData`、`saveData`…）都挂在 `window` 上，可直接在控制台调用改数据（这也是快速调试的最大便利）。

**用到的 Web API**：`localStorage`、`FileReader.readAsArrayBuffer`、`DataTransfer`（拖拽）、`XLSX`（SheetJS 0.18.5，全局）、原生 `confirm` / `alert`、`new URL()`。

**不使用**：`fetch` / `XMLHttpRequest`、`IndexedDB`、`crypto`、`navigator.clipboard`、Canvas、`requestAnimationFrame`、Web Components、任何框架。

**数据模型**（三态并列，字段名不统一 —— 这是理解全部代码的关键）：

```js
navData = {
  sidebar:   [ { title: "分类名", items: [{ name, url }] } ],   // 用 title
  query:     [ { name, url } ],                                  // 扁平，无分组
  directory: [ { label: "📺 影视", items: [{ name, url }] } ]    // 用 label
}
```

`sidebar` 用 `title`、`directory` 用 `label`，代码里到处是 `type === 'sidebar' ? .title : .label` 的三元判断（`:849`、`:897-898`、`:976-978`）。二次开发时这是最容易漏改的地方。

**渲染**：`renderAll()`（`:777-789`）→ `renderSidebar` + `renderQuery` + `renderDirectory` + `renderSelectOptions` → 重新套用搜索过滤 → 重算总数。**任何数据变更后一律全量重渲染**，没有增量 diff、没有虚拟列表。数据量到几千条时输入框过滤会开始卡（`applyFilter` 遍历所有 `.link-wrapper` DOM）。

**字符串定位**：所有增删改都靠 `(type, groupIndex, itemIndex)` 三个坐标（`:831`），**索引即身份** —— 没有 id 字段。副作用：一旦渲染与数据不同步（比如中途 `splice` 而没重渲染），坐标就会指错条目。目前代码总是「改完立刻 `renderAll()`」，所以安全；你加功能时必须守住这个约定。

**分类下拉的 value 编码**：`sidebar-0` / `directory-2` / `query`（`:769-773`），用 `target.split('-')[1]` 取索引（`:878`、`:882`）。**分类名里带 `-` 不影响**（编码用的是索引不是名字）。

## 10. 二次修改指引（开发者）

按需求频率排序，每条都给了确切行号。

**① 关掉 favicon 外链（强烈建议，一行）**

隐私最实用的改动。`:665` 改成直接返回空串即可：

```js
function siteFavicon(url) { return ''; }
```

`linkInner` 已经处理了空值（`:670`），不会有残留占位。改完这个页面就**只剩 SheetJS 一处联网**。

**② 修 XSS：渲染时转义**

`linkInner`（`:668-674`）和三处 `<a href="${item.url}">`（`:701`、`:720`、`:746`）都要过一遍。加一个工具函数并全包：

```js
function esc(s) {
  return String(s == null ? '' : s).replace(/[&<>"']/g,
    c => ({ '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' }[c]));
}
// linkInner: '<span class="link-text">' + esc(item.name) + '</span>'
// href: <a href="${esc(item.url)}" target="_blank" rel="noopener">
```

顺手补上 `rel="noopener"`（现在三处 `target="_blank"` 都没有）。

**③ 加「删除分类」**

现在只有改名和新增。在 `renderSidebar` 的 `titleHTML`（`:693-697`）和 `renderDirectory` 的 `labelHTML`（`:738-742`）各加一个按钮，再写：

```js
function deleteCategory(type, gIdx) {
  const g = type === 'sidebar' ? navData.sidebar[gIdx] : navData.directory[gIdx];
  const n = g.items.length;
  if (!confirm(`删除分类「${type === 'sidebar' ? g.title : g.label}」及其 ${n} 个链接？`)) return;
  if (type === 'sidebar') navData.sidebar.splice(gIdx, 1);
  else navData.directory.splice(gIdx, 1);
  saveData(); renderAll();
}
```

**必须注意坐标失效**：`splice` 掉第 0 个分类后，所有 `sidebar-1`、`sidebar-2` 下拉项和 `openEditLinkModal('sidebar', 1, …)` 的索引全部左移。因为末尾有 `renderAll()`，坐标会重建，所以安全 —— **但绝不能在 `splice` 和 `renderAll` 之间插入任何依赖旧索引的逻辑。**

**⑨ 数据校验与去重**

```js
if (exists && !currentEditLink) return showToast('该链接已存在');
```

`new URL()` 能拦住 `https://` 后面空、含空格这类明显错误。

**⑩ 支持浏览器书签导入**

Netscape 书签格式是 `<!DOCTYPE NETSCAPE-Bookmark-file-1>` 的 HTML，`<A HREF="…">名称</A>` 嵌在 `<H3>` 文件夹下。思路：新增一个 `accept=".html"` 的入口 → `DOMParser` 解析 → 递归 `<DL>` 生成 `directory` 分组。注意 `<DL>` 嵌套层级要压平或只取两层，否则分组会爆炸。

**⑪ 别踩的坑**

- **`sidebar` 用 `title`、`directory` 用 `label`** —— 新增涉及分类名的逻辑必须同时处理两个字段（现有 6 处三元判断可参考 `:849`、`:897`、`:976`）。想统一字段名就一并写数据迁移，否则老 `myNavData_v7` 会渲染成 `undefined`。
- **`saveData` 的 `catch(e) {}` 会掩盖真实故障**（`:656`）。调试存储问题时先把它改成 `console.error`。
- **`applyFilter` 操作的是 DOM 不是数据**（`:793-798`）。任何「在过滤结果上做批量操作」的想法都是错的 —— 应该读 `navData`。
- **索引即身份**：没有 id 字段。任何绕过 `renderAll()` 的原地 `splice` 都会让已渲染按钮的 `onclick` 参数集体错位。守住「改数据 → 立刻 `renderAll()`」。
- **`openNewLinkModal()` 无参调用时**（顶部按钮，`:537`）`type` 为 `undefined`，`:823` 的判断为假，下拉停在第一项 —— 不是 bug，但如果你改成「记住上次选择的分类」，要在这里补逻辑。
- **拖拽遮罩的隐藏条件偏脆弱**（`:1041`）：`relatedTarget === null || (clientX === 0 && clientY === 0)` 在快速划出窗口时偶尔残留。更稳的做法是 `dragleave` 计数器，或监听 `document` 的 `dragend`。
- **`drop` 只处理 `files[0]`**（`:1051`），若要支持多文件合并导入，循环调用 `handleExcelFile` 会因 `navData = newData` 互相覆盖 —— 必须先改成合并语义。
- **导入解析在 `reader.onload` 异步回调里**，期间用户还能继续编辑。若导入完成前又改了数据，那次修改会被 `:1001` 覆盖。稳妥做法是解析期间盖一层 loading。
- `Enter` 提交无焦点判断（`:919-922`）：如果将来在弹窗里加多行文本框，回车会误提交，届时需要补 `e.target.tagName !== 'TEXTAREA'` 守卫。
