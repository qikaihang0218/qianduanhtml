## 2. 快速开始

### 2.1 打开

双击 `全能格式化工具箱url.html` 即可。无外部 CDN、无构建步骤，`file://` 直开可用。

### 2.2 主线场景：把 20 个 JSON 一键变成 20 条 cURL

这是这个文件被造出来的理由，路径最短：

1. 点模式条上的 **🌐 cURL**。
2. 点子模式 **📦 批量生成**。
3. 填 **🔹 公共 URL**，例如 `http://127.0.0.1:80/orderReverse/third/boss/order`。
4. 选方法（默认 POST），在 **Headers** 框每行写一条 `Key: Value`，如 `Content-Type: application/json`。
5. 把 20 个 JSON **整坨粘进「📋 智能拆分粘贴区」**——不用管它们之间是换行、逗号还是夹着日志文字。
6. 点 **✂️ 一键智能拆分** → 下方立刻出现 20 个独立 JSON 输入卡片，每个可单独微调。
7. 点 **⚡ 批量生成 cURL** → 结果区逐条列出，每条右侧有独立复制按钮，顶部有「复制全部」。

拆分靠平衡括号扫描（`extractJSONsFromText`），能容忍尾随逗号等轻微非法 JSON；生成时 Body 会先美化再单引号转义。

### 2.3 普通格式化场景

切到 JSON / XML / CSS / SQL → 左侧粘贴 → **什么都不用点**，约 400ms 后右侧自动出结果（「自动执行」默认勾选，`:2190`、`:6749-6756`）。

### 2.4 独立面板场景

Diff / Crontab / 时间戳 / 正则 这些是"输入即算"，不需要按执行按钮。顶部四个通用按钮会自动接管该面板的导出：

- **📋 复制** → 复制该模块当前报告文本
- **⬇️ 下载** → 下载该模块报告（后缀按模块而定）
- **✨ 执行** → 按钮文案在面板模式会自动变成「🔍 重新对比」/「⏰ 刷新预览」/「🔄 重新计算」（`:6688-6690`）

## 4. 功能操作详解

### 4.1 格式化五件套（JSON / XML / HTML / CSS / SQL）

实现与 8 合1 版同源，行为一致，这里只列要点：

- **JSON**：`JSON.parse` 校验 → 递归展开嵌套 JSON 字符串（上限 20 层）→ 可选按键名排序 → `JSON.stringify` 美化。
- **XML / HTML**：浏览器内置 `DOMParser` 解析后重新缩进输出。⚠️ HTML 模式**不是无损的**：文本节点里的 `<` `>` `&` 会被重新转义，属性引号统一成双引号，自闭合标签被展开。
- **CSS**：自写 tokenizer，保留注释与字符串。⚠️ 输出缩进固定 1 空格，**不跟随缩进下拉**。
- **SQL**：关键字大写 + 主要子句换行，保留字符串与注释，不做语法解析。

### 4.2 cURL · 解析（默认子模式）

把浏览器 DevTools 里 "Copy as cURL" 的整段粘进左栏即可。解析规则（`:2409` 附近及 curl 解析段）：

- 自动合并 `\` 续行。
- 识别长/短两种写法：`--location` / `-L`、`--request` / `-X`、`--header` / `-H`、`--data-raw` / `--data` / `-d`、`--url`。
- 未带 `--url` 时，把以 `http` 开头的裸 token 当作 URL。
- Body 尝试 `JSON.parse`，成功后按当前选项做嵌套展开 / 排序 / 缩进美化。

### 4.3 cURL · 单条生成

表单字段：`curlUrl`、`curlMethod`（POST/GET/PUT/DELETE/PATCH）、`curlHeaders`（每行 `Key: Value`）、`curlBody`。

输出格式固定为：

```
curl --location --request POST 'http://...' \
--header 'Content-Type: application/json' \
--data-raw '{ ... 美化后的 JSON ... }'
```

Body 内的单引号按 shell 规则转义为 `'\''`。`↺ 重置表单` 清空 URL/Headers/Body/输出。

### 4.4 cURL · 批量生成（本文件的主打能力）

| 控件 | id | 说明 |
| ---- | ---- | ---- |
| 公共 URL | `batchCommonUrl` | 所有条目共用 |
| 方法 | `batchMethod` | POST/GET/PUT/DELETE/PATCH |
| Headers | `batchHeaders` | 每行一条，所有条目共用 |
| 智能拆分粘贴区 | `batchPasteArea` | 整坨粘进来 |
| ✂️ 一键智能拆分 | `splitJsonBtn` | 调 `extractJSONsFromText` |
| ＋ 手动添加 | `addJsonItemBtn` | 追加一个空白 JSON 卡片 |
| ⚡ 批量生成 cURL | `curlBatchGenerate` | 生成全部 |
| ↺ 重置批量表单 | `curlBatchReset` | 清空 |

拆分逻辑要点：

- 平衡括号扫描 `{}` / `[]`，能处理嵌套与字符串内的括号。
- 容忍尾随逗号等轻微非法 JSON（解析失败会降级处理而非整体报错）。
- 拆分结果渲染成可编辑卡片列表，**拆分后仍可逐条手改再生成**。

生成结果区支持逐条复制、复制全部、清空结果。

### 4.5 cURL · 简化命令

把长 cURL 重组成短参数形式（`-X` / `-H` / `-d`）。超长命令按 **200 / 120 / 110** 三档字符阈值决定是否折行。结果区有独立 `📋 复制结果` 按钮。

### 4.6 URL / Base64

- URL：`encodeURIComponent` / `decodeURIComponent`，支持中文等 Unicode。
- Base64：走 `TextEncoder` + `btoa`/`atob` 路径，支持中文，解码时自动忽略换行与空白。
- 两者都靠 3.3 的编码/解码切换按钮决定方向，切方向时若输入非空且自动执行开着会立刻重跑（`:6721`）。

### 4.7 MySQL AES（`aes`）

**纯 JS 实现，兼容 MySQL 默认 `block_encryption_mode = aes-128-ecb`。**

- 密钥折叠：把 `key_str` 按 UTF-8 编码后**循环 XOR 折叠到 16 字节**，与 MySQL `AES_ENCRYPT` 行为一致。
- 加密：明文 → 密文 → Base64。等价于 `TO_BASE64(AES_ENCRYPT(明文, key))`。
- 解密：Base64 → 明文。等价于 `CAST(AES_DECRYPT(FROM_BASE64(密文), key) AS CHAR)`。

**「解析 / 生成 MySQL 语句」勾选（默认开）** 带来的两个能力：

1. 输入框可以直接粘整条 MySQL 语句 —— 粘 `AES_DECRYPT(FROM_BASE64('...'),'key')` 会自动抠出密文和 key 并解密；粘 `TO_BASE64(AES_ENCRYPT('...','key'))` 同理反向。
2. 输出下方额外生成一段**可直接粘进 MySQL 客户端执行**的等价语句，带 `📋 复制 SQL` 按钮（`:6767-6770`）。

### 4.8 MySQL 加密方式大全（`mysqlenc`）

一个"文档 + 计算器"混合面板，`mencMethod` 下拉 12 项，分 4 组（`:2110-2131`）：

| 分组 | 选项 | 能否本地算 |
| ---- | ---- | ---- |
| 对称可逆 | `aes`（默认 aes-128-ecb） | ✅ 实时计算 |
| | `aesmodes`（AES 全模式 18 种组合） | 说明 + SQL |
| | `des` / `3DES`（8.0 已移除） | 仅 SQL |
| | `encode`（ENCODE/DECODE，8.0 已移除） | 仅 SQL |
| | `encrypt`（ENCRYPT()，8.0 已移除） | 仅 SQL |
| 非对称 | `rsa`（仅企业版） | 仅 SQL |
| 单向哈希 | `md5` / `sha1` / `sha2`（256/384/512） | ✅ 实时计算 |
| 机制层 | `tde` / `tls` / `keyring` | 说明 + SQL |

选「仅 SQL」的项时给出精确可复制语句与适用版本说明，需要自己去客户端执行。

### 4.9 文本对比（`diff`）

**算法**：Myers O(ND) 求行级 LCS，再对变更行做行内 token 级高亮。

**硬限制常量**（`:3552-3554`）：

| 常量 | 值 | 含义 |
| ---- | ---- | ---- |
| `DIFF_MAX_D` | 1500 | 最大编辑距离，超出降级为快速对齐 |
| `DIFF_FALLBACK_LINES` | 20000 | 左右总行数超过此值直接走快速对齐 |
| `DIFF_RENDER_LIMIT` | 3000 | 单次最多渲染行数，超出提示「复制 / 下载可获得完整差异报告」 |

**视图**：`▥ 并排` / `≡ 统一` / `⌄ 内联`。

**忽略选项**（`:1466-1471`）：忽略大小写、忽略空白、忽略行尾空格、忽略空行、**折叠相同行（默认勾选）**、只看差异。

**工具按钮**：`⇄ 交换`（左右内容互换）、`✎ 示例`、`🗑️ 清空`、`↑ 上一处` / `↓ 下一处`（中间 `diffCounter` 显示 `当前 / 总数`）。

**拖入文件**：`diffA` / `diffB` 各自支持拖入本地文件（`bindFileDrop`，`:4026-4043`）。⚠️ 注意这条路径**没有** 8MB 大小校验，与其它面板的 `tkBindDrop` 不同。

**复制 / 下载**：导出的是 **unified diff 格式报告**，下载后缀 `.diff`。

### 4.10 Crontab（`cron`）

**仅支持 Linux crontab 标准 5 字段**，不支持 6 字段 Quartz 秒位。

- 默认表达式：`0 9 * * 1-5`（`:1511`）。
- 字段范围（`:4046-4050`）：分 `0-59`、时 `0-23`、日 `1-31`、月 `1-12`、周另有定义。
- 支持 `*` `,` `-` `/`、英文月份与星期缩写、`@` 别名。
- **双向**：点选择器生成表达式 / 直接输入表达式反填选择器。
- 实时中文释义 + **未来 5 次执行时间**预览（基于本机时区）。
- 预设共 6 组 26 条（`:4060-4080`）：分钟级 4 条、小时级 4 条、每天 4 条、每周/工作日 4 条、每月/每季度 4 条、`@` 别名 6 条（`@hourly @daily @weekly @monthly @yearly @reboot`）。
- `@reboot` 特殊处理：状态栏显示 `Cron 表达式有效（@reboot 开机触发）`，不推算时间。
- **复制** → 只复制表达式本身；**下载** → `.cron` 文件，内容含表达式、中文含义、未来 5 次时间、以及一行 `表达式 + /path/to/your-command.sh` 的可直接用示例。
- **清空** → 重置为 `* * * * *` 并提示「已重置为每分钟」（`:6621-6625`），不是清空成空串。

### 4.11 时间戳（`ts`）

- 输入形式：Unix 秒、Unix 毫秒、`2024-01-01 08:00:00`、`2024/1/1`、`2024年1月1日`（中文年月日与 `/` 会被预处理成 `-`）、ISO 8601。
- 单位下拉 `tsUnit`：`自动识别` / `秒（10 位）` / `毫秒（13 位）`。自动识别规则：绝对值 `>= 1e11` 判为毫秒，否则判为秒（`:4537`）。
- 时区下拉 `tsTz` 共 9 项：本机时区、UTC、Asia/Shanghai、Asia/Tokyo、Asia/Kolkata、Europe/London、Europe/Berlin、America/New_York、America/Los_Angeles。基于 `Intl.DateTimeFormat`，时区不可用时回退本机并标注「（时区不可用）」。
- 单行输入 → 键值对明细（Unix 秒 / 毫秒 / 所选时区 / UTC / ISO 8601 / 相对现在）；多行输入 → 自动切表格，**无法识别的行单独标红而不是整体失败**。
- 相对时间只到"分钟"粒度，60 秒内显示 `刚刚`（`:4514-4523`）。
- **日期加减**：以第一行为基准，单位可选 天/小时/分钟/秒/月/年，结果追加在页面下方并进入导出报告。
- 顶部有本机实时钟（秒 / 毫秒），`🕐 取当前时间` 一键填入。
- 支持拖入文件（限 8MB）。
- 下载 → `时间戳报告.txt`。

### 4.12 文本批处理（`txt`）

### 4.15 安全工具（`sec`）

四个子 Tab：`JWT` / `哈希` / `HMAC` / `随机串`。**全部纯 JS 手写实现，不用 `crypto.subtle`**（因此 `file://` 下也能算，不受 SecureContext 限制）。

**JWT**：

- 必须正好 3 段，否则报错并告知当前几段。
- Base64URL 解码 header / payload 并美化。
- `exp` / `iat` / `nbf` 按秒解析成可读时间，并标注「未过期 / 已过期」「尚未生效 / 已生效」。
- 填密钥后可验签 **HS256 / HS384 / HS512**，用**定长比较**防时序侧信道（`:5707-5712`）。
- 非 HS* 算法（RS256 等）明确提示"非对称/不支持的算法，仅解码不验签"。
- 页面固定警示：**解码 ≠ 可信：未验签的 payload 可任意伪造。**

**哈希**：一次算 6 种 —— MD5、SHA-1、SHA-256、SHA-384、SHA-512、CRC32，并显示耗时。输入可以是文本，**也可以直接把本地文件拖进文本框**按字节计算。

**HMAC**：算法 `HMAC-SHA256`（默认）/ `HMAC-SHA1` / `HMAC-SHA512` / `HMAC-MD5`；输出格式 `Hex`（默认）/ `Base64`。消息与密钥任一为空则不计算。

**随机串**：

| 项 | 说明 |
| ---- | ---- |
| UUID v4 | 数量 1–200，默认 5 |
| ULID | Crockford Base32，48 位毫秒时间戳 + 80 位随机 |
| NanoID | 固定 21 位，字母表 `A-Za-z0-9_-` |
| 随机密码 | 长度 4–128，默认 16 |

密码字符集**刻意剔除易混字符**：大写去掉 `I` `O`，小写去掉 `l` `o`，数字去掉 `0` `1`；符号集为 `!@#$%^&*()-_=+`。至少勾一类，否则报错。ULID/NanoID/密码各最多生成 10 条（不随 UUID 数量增长）。随机源为 `crypto.getRandomValues`。

### 4.16 分库分表定位（`dbloc`）

**逐字复现线上 Java `DbAndTablesLocateUtil`**，用于排查"某个手机号/订单号的数据落在哪个库哪张表"。

路由公式（`:6004-6011`）：

```
h        = String.hashCode(key)          // Math.imul(31, h) + charCodeAt，32 位溢出
abs      = Math.abs(h)                   // h == Integer.MIN_VALUE 时仍返回负数，逐字保留
库号      = abs % 32
商        = trunc(abs / 32)
表号      = 商 % N                        // N = 32 或 8
```

- 常量：`DB_DBS = 32`；库表名前缀校验 `^[A-Za-z_][A-Za-z0-9_]*$`；手机号校验 `^1[3-9]\d{9}$`。
- 路由规则二选一：`32库×32表`（实例表，默认）、`32库×8表`（订单表）。
- 表名前缀默认 `inst_commodity_base_info`，库名前缀默认 `hboss_order`。
- 类型选择：`手机号·校验格式` / `虚拟号·不校验`。选订单规则（8 表）时类型下拉**自动禁用**并提示不做校验。

> ⚠️ **最重要的使用规则：输入不做任何清洗。**
> 不 trim、不去 `+86`、不去空格、不改大小写 —— 这些都会改变 `hashCode` 从而算出完全不同的库表。手机号模式**只判断格式、不改写**。空串会被拦截（会恒定落到 0 库 0 表）。

能力：单个定位（大号显示命中库表 + 分步计算过程）、**32 库 / N 表拓扑网格命中高亮**、一键复制路由、批量定位（按空白/逗号/分号切分，统计命中库数、命中库表数、单表最大条数）、**导出 `db-location.csv`**（带 UTF-8 BOM，Excel 直开不乱码）、示例手机号 / 示例虚拟号 / 边界用例三个演示按钮。

### 4.17 清空按钮的模式差异（易踩坑）

`doClear`（`:6619-6639`）按模式分支：

- `json` 等编辑器模式 → 清输入框 + 输出框。
- `cron` → **重置为 `* * * * *`**（不是清空）。
- `diff` → 清空 A/B 并重置折叠状态。
- 各独立面板 → 调各自 `xxx`Clear()`，如 `sec` 会连 JWT 密钥、HMAC 密钥一起清掉。

### 7.2 剪贴板行为的 `file://` 注意点

`copyText`（`:6561-6566`）的逻辑是：**只在 `window.isSecureContext` 为真时才用 `navigator.clipboard.writeText`**，否则直接走 `document.execCommand('copy')` 降级路径。

## 8. 常见问题（FAQ）

**Q1：为什么 `Ctrl+Enter` 没反应？**
本页没有快捷键（见第 5 章）。你可能把它和 `全能格式化工具箱.html` 搞混了。

**Q2：粘进去没自动出结果？**
检查「自动执行」是否被取消勾选；另外独立面板模式（Diff/Crontab/时间戳/正则等）不走主编辑器的自动执行，但它们本身是输入即算的。

**Q3：cURL 批量拆分只拆出 1 条 / 0 条？**
拆分基于**平衡括号扫描**。如果 JSON 里含未转义的裸 `"` 或括号不配对，扫描会失败。先在 JSON 模式把每段单独格式化验证一遍，或点「＋ 手动添加」手填。

**Q4：生成的 cURL 在 Windows CMD 里跑不通？**
生成的是 **bash 风格**（单引号包裹、`'\''` 转义），适用于 macOS/Linux/Git Bash/WSL。CMD 需要双引号转义体系，PowerShell 也有差异。请在 Git Bash 或 WSL 中执行。

**Q5：AES 解出来的明文和 MySQL 不一致？**
按顺序排查：① 数据库 `block_encryption_mode` 是否为默认 `aes-128-ecb`（若是 `aes-256-*` 本页对不上）；② key 是否完全一致（多一个空格结果就完全不同）；③ 密文是否被 Base64 换行折行过（本页解码会忽略空白，一般没问题）；④ 明文是否含 `\0`。

**Q6：diff 显示「结果过长，仅显示前 3000 行」，结果不全怎么办？**
这是 `DIFF_RENDER_LIMIT` 的渲染保护。**点复制按钮或下载 `.diff` 文件拿完整报告**（`:3894` 已明确提示）。或者先裁剪输入。

**Q7：diff 结果看起来"对齐得很粗糙"？**
左右总行数超过 20000 行、或编辑距离超过 1500 时，会从 Myers 精确解降级为快速对齐算法，配对可能不是最优。拆小一点再比。

**Q8：分库定位算出来的库表和线上不一致？**
最高频原因是**输入被清洗过**：带了空格、带 `+86`、大小写不同、或者从 Excel 复制时被转成了科学计数法。`hashCode` 对每一个字符敏感。本页刻意不做任何清洗，请确保粘进去的字符串与线上参与计算的**完全一致**。

**Q9：分库定位提示"手机号格式不正确"，但我确定它是合法号码？**
说明它不匹配 `^1[3-9]\d{9}$`（11 位、1 开头、第二位 3-9）——很可能就是首尾带了不可见空白。若确实是虚拟号/测试号，切到「虚拟号 · 不做校验」。

**Q10：JWT 显示"未验签"？**
只有 `HS256/384/512` 支持验签，且必须在密钥框填 secret。`RS256` 等非对称算法只能解码，页面会明确提示。

**Q11：拖文件进去没反应？**
独立面板的拖入有 **8MB** 上限（`:4428`），超限会 toast 提示「文件超过 8 MB，请先截取片段」。**例外：Diff 的两个输入框走另一条路径，无大小校验**，超大文件会把浏览器卡住——请自行控制。

**Q12：CSS 格式化后缩进还是 1 空格，改下拉没用？**
已知缺陷，与 8 合1 版一致：CSS 格式化器输出缩进硬编码，不读 `indentSelect`。

**Q13：HTML 格式化后内容"变了"？**
它不是无损格式器：文本节点里的 `<` `>` `&` 会被重新转义、属性引号统一为双引号、自闭合标签被展开成 `<br></br>` 形式。要保真请直接用 Diff 或文本批处理。

**Q14：JSONPath 的 `[?(@.age>18)]` 报错？**
过滤表达式不在支持范围内（见 4.14 表格）。可以用 `..age` 递归取出来再自己筛。

**Q15：Crontab 下载下来为什么是 `.cron` 不是 `.txt`？**
这是 `extMap` 特意配的。内容本身就是纯文本，改后缀即可；里面已经附带了能直接粘进 `crontab -e` 的完整行。

```js
const isPanel  = isDiff || isCron || isTk;
```

然后依次控制：`actionRow` / `aesKey` / `aesSqlToggle` / `curlActionRow` / `sortKeysOption` / `expandNestedOption` / 各模块容器显隐、`formatBtn` 文案、`optionsRow` 显隐。**新增模式必须在这一个函数里登记**，否则面板不会显示。

三条导出通道同样按模式分派：

- `tkRefresh(mode)` → 面板重算（`:4447-4455`）
- `tkExport()` → 面板导出 `{ text, ext, label }`（`:4456-4465`）
- `tkClear(mode)` → 面板清空（`:4466-4474`）

`doCopy` / `doDownload` / `doClear` 在入口处分三层：面板模式 → `tk*`；`diff`/`cron` 特判；其余走 `outputArea`。

### 9.3 自动执行

```js
let autoTimer = null;
function scheduleAutoProcess() {
  if (!autoFormat.checked) return;
  if (autoTimer) clearTimeout(t);
  autoTimer = setTimeout(() => { if (inputArea.value.trim()) doProcess(); }, 400);
}
```

主编辑器统一 400ms 防抖；独立面板各自用 `tkDebounce(fn, ms)`（`:4440-4446`）自己控制，如时间戳是 250ms。

### 9.4 嵌套 JSON 展开

`expandNestedJson(value, depth = 0)`（`:2361-2383`）：字符串值 trim 后若首尾是 `{}` 或 `[]` 就尝试 `JSON.parse`，成功则递归，`depth > 20` 时原样返回。`catch` 静默忽略。作用于 JSON、cURL（解析/批量）、日志三处。

`sortObjectKeys`（`:2351-2359`）递归 `Object.keys().sort()`，数组保序。

### 9.5 Diff 引擎

- `myersDiff`（`:3609` 附近）：`const maxD = Math.min(N + M, DIFF_MAX_D)`，用 `Int32Array(2 * DIFF_MAX_D + 5)` 做 V 数组。超过 `maxD` 未收敛 → 降级快速对齐。
- 行内二次高亮：对配对上的变更行再跑一次 token 级 diff。
- `diffPrepare` 按四个忽略选项预处理行。
- 折叠状态用 `diffExpanded = new Set()` 记录手动展开的行段。
- 三个视图共用同一份 diff ops，只是渲染函数不同。
- `buildDiffReport()` 输出 unified 格式，是复制/下载的唯一数据源。

### 9.6 密码学实现

全部手写、无依赖，位于 `:5600-5760` 区间：

- `scMd5` / `scSha1` / `scSha256` / `scSha512(bytes, variant)`（`sha384` 走同一函数的不同初始向量）/ `scCrc32`。
- `scHmac(alg, key, msg)`（`:5682-5690`）：标准 ipad/opad 结构，块大小 SHA-512/384 用 128、其余 64，key 超块长先哈希。
- MySQL AES：`aes-128-ecb`，密钥按 UTF-8 循环 XOR 折叠至 16 字节。
- `scConstEq`（`:5707-5712`）：`diff |= a[i] ^ b[i]` 定长比较，JWT 验签使用。
- `scRand(n)`：优先 `crypto.getRandomValues`，不可用时回退 `Math.random`（仅影响随机串生成，不影响验签正确性判断）。

### 9.7 分库路由的 Java 语义保真

```js
function dblocHash(s) {                       // Java String.hashCode
  let h = 0;
  for (let i = 0; i < s.length; i++) h = (Math.imul(31, h) + s.charCodeAt(i)) | 0;
  return h;
}
function dblocAbs(h) {                        // Java Math.abs(int) 的 MIN_VALUE 陷阱
  return h === -2147483648 ? -2147483648 : Math.abs(h);
}
function dblocZero(v) { return Object.is(v, -0) ? 0 : v; }
```

三处细节都是刻意为之：`| 0` 模拟 32 位溢出、`MIN_VALUE` 取绝对值仍为负、`-0` 归一化避免结果里出现 `-0`。改动这段请先用 `示例边界用例` 按钮回归。

### 9.8 XSS 防护面

所有把用户输入写进 `innerHTML` 的地方都过 `tkEsc`（`:4410-4412`，转义 `& < > "`）：正则高亮区、匹配明细表、时间戳表格、cURL 解析结果、Diff 渲染。分库定位的批量表格和树视图改用 `document.createElement` + `textContent` 构建，从根上规避注入。**新增渲染逻辑请沿用这两种方式之一，不要直接拼 `innerHTML`。**

### 9.9 文件拖入的两条路径

| 函数 | 用于 | 大小限制 |
| ---- | ---- | ---- |
| `tkBindDrop(ta, cb)`（`:4420-4439`） | 时间戳 / 文本批处理 / 正则 / JSON 进阶 / 安全工具哈希 | **8 MB**，超限 toast 拒绝 |
| `bindFileDrop(ta)`（`:4026-4043`） | Diff 的 A / B 两框 | **无** |

两者都以 UTF-8 `readAsText`（哈希 tab 例外，那里按字节读），读取后 `dispatchEvent(new Event('input'))` 触发重算。

## 10. 二次修改指引（开发者）

### ① 新增一个模式（最完整的改动清单）

以加一个 `yaml` 模式为例，需要动 5 处：

1. **DOM**：在 `:1303-1323` 的模式条加 `<button class="mode-btn" data-mode="yaml"><span>🧾</span> YAML</button>`。
2. **提示文案**：在 `modeHints`（`:6661` 前）加 `yaml: '...'`。
3. **处理逻辑**：写 `formatYaml(text)`，并在 `doProcess()` 的 `switch (currentMode)` 里加 `case 'yaml'`。
4. **下载后缀**：在 `extMap`（`:6604`）加 `yaml: 'yaml'`。
5. **（可选）独立面板**：若需要自己的面板，加 `tkModules` 注册 + `tkRefresh` / `tkExport` / `tkClear` 三个分派 + `switchMode` 里的显隐控制。

> 提醒：`switchMode` 的 `isPanel` 判定是硬编码的 `isDiff || isCron || isTk`，走面板路线必须进 `tkModules`，否则不会被隐藏/显示逻辑接管。

### ② 修 CSS 格式化不跟随缩进

定位到 CSS tokenizer 的输出函数，把硬编码的单空格缩进换成读 `indentSelect.value`（注意 `\t` 选项的值是字面两字符 `"\t"`，需要 `value === '\\t' ? '\t' : value` 转换 —— 参考 JSON 分支已有的处理方式）。

### ③ 给 Diff 的拖入也加大小限制

`bindFileDrop`（`:4026`）缺 `f.size` 校验，直接复用 `tkBindDrop` 的写法加一句即可：

```js
if (f.size > 8 * 1024 * 1024) return showToast('⚠️ 文件超过 8 MB，请先截取片段', 'error');
```

### ④ 补全局快捷键

全文当前只有一处 `keydown`。若要恢复 8 合1 版的键位，在 `bindEvents()`（`:6758`）末尾加一个 `document.addEventListener('keydown', ...)`，注意：

- 判断 `e.ctrlKey || e.metaKey` 以兼容 macOS。
- 面板模式下要跳过（各面板输入框里的 `Ctrl+Enter` 语义未定义）。
- `Tab` 插入空格只应绑在 `inputArea` / `outputArea` 上，否则会破坏面板内表单的键盘导航。

### ⑤ 加下载模式（Minify）

JSON 压缩只需在 `doProcess` 的 json 分支按当前动作选择 `JSON.stringify(parsed)`（无第三参）。若要给 CSS/JS 也加，建议单独一个模式按钮而不是复用 `encodeBtn`，避免与 URL/Base64/AES 的方向切换语义冲突。

### ⑥ 调 Diff 性能阈值

三个常量集中在 `:3552-3554`，改完记得同步改 `:3894` 的提示文案（目前 `DIFF_RENDER_LIMIT` 的数字是模板拼接进文案的，会自动跟随；但 `DIFF_FALLBACK_LINES` 的降级没有用户提示，改了阈值用户无感知，建议补一条 `setStatus` 提示）。

### ⑦ 移植独立面板到别的页面

独立面板模块（时间戳 / 文本批处理 / 正则 / JSON 进阶 / 安全 / 分库定位）耦合点只有四个：

- `$tk(id)` 取元素
- `setStatus(msg, type)`
- `showToast(msg, type)`
- `tkErr(id, msg)` / `tkEsc` / `tkDebounce` / `tkBindDrop` / `copyText`

把这些抽成 30 行左右的 shim，即可把单个模块整段摘出去复用。
