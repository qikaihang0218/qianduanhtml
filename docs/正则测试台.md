> 源文件：[../正则测试台.html](../正则测试台.html)
> 页面标题：`正则测试台 · Regex Lab`
> 一句话定位：实时高亮测试正则表达式，展开每个捕获组的位置与内容，预览替换结果，内置 27 条常用正则速查

## 1. 工具简介

写正则时最痛的不是写不出来，而是**不知道它到底匹配了什么**。在浏览器控制台里试要来回打印、数下标、拼 `exec` 循环；写完的替换结果对不对，还得再跑一遍才知道。

本工具把这条回路压成「输入即结果」：左边放文本，上面写正则，右侧同时给出三样东西——

1. **高亮视图**：所有命中处着色，奇偶交替底色便于区分相邻匹配
2. **匹配详情表**：每条匹配的起止位置、`$0`、`$1…$n`、命名组，一一对应
3. **替换预览**：直接显示 `String.replace` 的全文结果，可复制或下载

另外解决三个控制台里很难受的点：

- **捕获组的精确位置**。若浏览器支持 `d` flag（`hasIndices`），工具会**自动附加**它，于是详情表能给出每个组自己的字符区间，点一行还能在高亮区按颜色把组拆出来看。
- **回溯卡死**。`(a+)+b` 这类嵌套量词遇到长串会指数爆炸，把整个页面冻住。本工具把匹配放进 **Web Worker**，主线程永不参与计算；超过 3 秒直接 `terminate()` 重建线程，页面始终可操作。
- **flags 要手敲**。`g` `i` `m` `s` `u` `y` 做成开关按钮，点一下就重算。

**适合谁用**

- 写校验正则（手机号、邮箱、身份证、URL、日期）时反复验证边界
- 做批量文本替换，先看清会命中哪些内容再落地
- 学正则：配合内置的「符号」速查与「常用正则」库，改一个字符看结果怎么变

**什么时候不该用它**

- **需要 PCRE / Python `re` 的专有语法**：这里跑的是 **JavaScript `RegExp`（ES2018+）**。后顾断言 `(?<=)` `(?<!)` 可用，但 PCRE 的 `\K`、条件组 `(?(1)...)`、命名组反向引用写法差异等一律不支持
- **需要正则引擎行为完全一致的后端环境**：JS 与 Python/Java 引擎在 `\d` 是否含全角数字、空匹配推进策略等细节上存在差异，跨语言落地前请在目标环境复测
- **超大文件全文检索替换**：输入上限 20 万字符，匹配上限 5000 条。这是「测试与验证」工具，不是编辑器批量替换

## 2. 快速开始

1. **双击 `正则测试台.html`**。单文件，无同级依赖，不需要起服务器。
2. 首次打开自带一段演示：正则是 `(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})`，文本含两个日期，右侧已显示 2 处匹配。
3. **正则不要写两侧的斜杠**。直接写 `\d+`，不要写 `/\d+/`——工具自己负责拼 `new RegExp(pattern, flags)`。
4. 把左侧文本换成自己的内容，点工具栏**「示例文本」**可载入一段覆盖手机号、邮箱、IP、颜色码、日期、版本号、UUID、驼峰字段、重复单词的综合样例。
5. 点顶部 **「匹配详情」** 标签，任意点一行 → 切回 **「高亮」**，那一处会按颜色展开成捕获组。
6. 点 **「替换预览」**，在替换框里写 `$1` 或 `$<year>`，下方实时显示全文结果；点 **「复制」** 或 **「下载」** 导出。

| 帮助 | 弹使用说明与快捷键 |

### 3.3 左侧：测试文本

纯文本域，支持直接粘贴与**拖入 `.txt` 文件**。右上角实时显示字符数。

### 3.4 右侧：三个标签页

| 标签 | 内容 |
| ---- | ---- |

## 4. 功能操作详解

### 4.1 flags 开关

| 开关 | 含义 | 典型场景 |
| ---- | ---- | -------- |
| `g` | 全局搜索。**关闭时只匹配第一处**，状态栏与提示条会明确告知 | 只想验证单点匹配 |
| `i` | 忽略大小写 | 匹配 `HTTP`/`http` |
| `m` | 多行：`^` `$` 匹配**每一行**首尾而非整段首尾 | 行首行尾空白、按行校验 |
| `s` | 单行：`.` 也匹配 `\n` | 跨行抓取 `<div>…</div>` 内容 |
| `u` | Unicode：按码点处理并启用严格模式，非法转义会直接报错 | 处理 emoji、`\u{1F600}` |
| `y` | 粘性：必须**正好**从 `lastIndex` 处开始匹配 | 手写词法扫描器调试 |

`d` flag **不在界面上**：若内核支持，工具在语法校验通过后自动追加，仅用于取组位置。

### 4.2 匹配详情表

- 每行可点。点中后该行高亮，同时高亮视图里对应片段变蓝并展开捕获组；再点一次取消选中。
- 「位置」列格式为 `起–止`，零宽匹配显示为 `N 零宽`。
- 未参与的组显示灰色 `未参与`，参与但为空串显示 `空`——两者不同，别混淆。
- 命名组在数字组之后列出，形如 `$<year> 2024`。

### 4.3 替换语法

替换框走原生 `String.prototype.replace` 的 `$` 语义：

| 记号 | 含义 |
| ---- | ---- |
| `$&` | 整个匹配 |
| `` $` `` | 匹配**之前**的全部文本 |
| `$'` | 匹配**之后**的全部文本 |
| `$1` – `$99` | 第 n 个捕获组 |
| `$<name>` | 命名组 |
| `$$` | 一个字面 `$` |

例：正则 `(?<h>\d{2}):(?<m>\d{2})`，替换 `[$<h>时]`，文本 `time 09:30 and 23:59` → `time [09时] and [23时]`。

> 替换预览**始终基于全文**计算，不受高亮 20,000 字符渲染上限影响。

### 4.4 字面量化

把正则框当前内容中的正则元字符全部加反斜杠，用于「我要搜的就是这几个带特殊含义的字符」。原正则会被覆盖，但**原串已进历史**，点「历史」可取回。

### 4.5 拖入文件

把 `.txt` 拖到页面任意位置即可载入，上限 **4 MB**；内容含 `\u0000`（判定为二进制）会拒绝。

## 7. 数据与隐私

- **零网络请求**。全文无 `fetch` / `XMLHttpRequest` / `WebSocket`，不引用任何外部 CSS、JS、字体、图片。双击本地文件即可完整工作。
- **文本不出本机**。测试文本、正则、替换串只在浏览器内存与本机 `localStorage` 之间流动。
- **存储键**：`regexlab.prefs.v1`，字段为 `pat` / `flags` / `rep` / `tab` / `hist` / `text`。其中 `text` 仅在长度 ≤ 50,000 字符时写入（避免撑爆配额）；写入防抖 400 ms。
- **清除数据**：在浏览器里删除该站点存储即可。`file://` 打开时，数据挂在浏览器的本地文件域下。
- 敏感文本（密钥、内部数据、他人隐私）测试完后建议点「历史 → 清空历史」并清空文本框，正则会留在本地记录里。

## 8. 常见问题（FAQ）

**Q：明明匹配不上，本地却像是对的？**
最常见是**多写了两侧斜杠**。输入框要填 `\d+`，不是 `/\d+/`——`/` 本身会被当成正则字符。

**Q：状态栏显示「匹配 1 处」，但文本里明显有多处。**
`g` 没开。未开启 `g` 时只取第一处，提示条也会写明「未开启 g，仅匹配到第一处」。

**Q：`^` 不能匹配每行开头。**
需要开 `m`。JS 里默认 `^` `$` 只锚定整段文本的首尾。

**Q：`.` 匹配不到换行。**
开 `s`。

**Q：状态栏显示「已中断：疑似灾难性回溯」。**
你的正则在当前文本上发生了指数级回溯，典型形态是**嵌套量词**（`(a+)+b`、`(.*)*`）或**重叠分支**（`(a|a)*`）。工具在 3 秒时强制终止并重建了计算线程，页面不会假死。改法：把内层量词收窄（`a{1,10}`）、加边界（`\b`），或用占有量词语义的替代写法（JS 无占有量词，可用 lookahead 手工模拟）。

**Q：为什么提示「匹配超过 1200 ms 已中断，结果不完整」却没被强制终止？**
那是软预算：匹配**之间**能检查到超时并正常收尾，已找到的结果仍然可用。硬终止只发生在单个 `exec` 内部卡死时。

**Q：详情表只有 800 行，是不是只匹配到 800 条？**
不是。800 只是渲染上限，状态栏的数字才是真实条数（上限 5000）。「复制匹配」导出全部。

**Q：捕获组那一列全是空的 / 没有位置。**
说明当前内核不支持 `d` flag（标题栏胶囊会显示「内核较旧 · 组位置不可用」）。组**内容**仍来自 `exec` 结果，只是拿不到组的独立位置。

**Q：高亮区显示 `∅` 是什么？**
零宽匹配（如 `a*` 在 `b` 前匹配到空串）。工具会自动把 `lastIndex` 前进一位，因此不会死循环。

**Q：拖入 `.json` / `.csv` 没反应？**
只有文本内容能被读进来；判定为二进制（含 `\u0000`）或超过 4 MB 会被拒。`.json` `.csv` 这类纯文本实际可用。

**Q：换台电脑设置没了。**
`localStorage` 不跨设备同步，`file://` 下也不会走账号同步。要长期保留正则请用「历史」面板手工复制走。

## 9. 技术实现要点（开发者）

### 9.1 双端共用的匹配内核

`matchKernel(pattern, flags, src)`（`:388`）是**唯一**的匹配实现，主线程与 Worker 共用：

- Worker 源码用 `matchKernel.toString()` 字符串拼接生成（`:421` 的 `WORKER_SRC`），改内核不用改两处。
- 循环内处理三个坑：
  - **零宽匹配**：`m[0].length === 0 && (global || sticky)` 时手动 `re.lastIndex = m.index + 1`，否则 `g` 模式下死循环。
  - **非全局提前退出**：`!g && !st` 时取第一个结果即返回。
  - **软预算**：每 32 次迭代（`(++guard & 31) === 0`）检查一次 `Date.now()`，超 `TIME_BUDGET` 就带 `trunc` 收尾。
- 组位置来自 `m.indices[k]`，仅在 `d` flag 存在时非空。

### 9.2 防卡死的 Worker 模型

```
主线程 --postMessage--> Worker（同步跑 RegExp，可能卡死的是它）
   ^                        |
   └---- onmessage ---------┘   正常返回，按 seq 校验
   └---- setTimeout(3s) -----   超时则 terminate() + makeWorker() 重建
```

关键点：

1. **`terminate()` 是唯一能打断同步 `RegExp` 执行的手段**，JS 层没有任何办法中断一个正在回溯的正则，只能杀掉线程。
2. **`seq` 序号防串扰**：每次计算自增序号，回包序号不匹配直接丢弃。否则「旧的正则慢返回」会覆盖「新正则的快结果」。
3. **Worker 用 Blob URL 创建**，实测在 `file://` 下可用（`isSecureContext` 为 `true`）。若 `new Worker` 抛错，`computeViaWorker` 返回 `false`，主线程退回同步计算路径。

### 9.3 flags 与 `d` 的自动追加

`validate()`（`:539`）先用界面上的 flags 试构造 `new RegExp`，失败即返回错误消息给错误条；成功后若 `CAN_D` 且当前 flags 无 `d`，再试构造 `flags + 'd'`，成功才追加。这样既拿到组位置，又不会在不支持 `d` 的内核上炸掉。

### 9.4 捕获组拆色

`groupSpans()`（`:713`）把选中匹配按 `m.gi` 的区间拆成 `.g1` / `.g2` 交替着色的 span。**先做重叠检测**：若任意两个组区间重叠（如嵌套组 `(a(b))`），直接放弃拆色退回整体高亮，否则嵌套 span 会让区间渲染错乱。

### 9.5 渲染截断策略

`renderHL()` 用 `DocumentFragment` 一次性拼接，避免逐节点重排；`notesFor(box, overLen)` 负责提示条，替换预览传的是**替换结果长度**而不是原文长度，避免「原文 18k 但结果 40k」时漏掉截断提示。

### 9.6 转义与 XSS

所有来自用户输入的正则、文本、匹配内容、组内容一律过 `esc()`（`:644`）再进 `innerHTML`，替换串里的 `$<name>` 也走文本节点。唯一直接写 `innerHTML` 的用户相关内容是错误条里的 `esc(v.msg)`。

## 10. 二次修改指引（开发者）

1. **改上限只改常量**（`:360` 附近）。但注意三者有耦合：`MATCH_CAP` 决定「复制匹配」的最大条数，`ROW_CAP` 只影响表格；`HL_LIMIT` 同时管高亮与替换预览的渲染，改大会让 20k+ 文本的首屏明显卡顿。
2. **`WORKER_SRC` 是字符串拼接的独立作用域**（`:421`）。内核里新引用的任何常量必须在拼接头部显式注入（如现在的 `MATCH_CAP`、`TIME_BUDGET`），否则 Worker 里 `ReferenceError`，表现为「执行失败」。同理**内核函数内不要引用任何外部变量**。
3. **新增常用正则**：往 `LIB`（`:913`）对应分类的数组里加一条 `['名称', '正则', 'flags', '示例文本']` 即可，弹层自动渲染。注意正则在 JS 源码里要**双写反斜杠**。
4. **新增元字符按钮**：往 `SYM`（`:989`）加 `['插入内容', '说明']`。插入位置依赖 `patIn.selectionStart`，若把正则框换成富文本组件需要重写这段。
5. **新增 flag**：在工具栏加 `<button class="flag" data-flag="x">x</button>`，其余全走 `currentFlags()` 自动收集，无需改计算逻辑。
6. **偏好字段扩展**：`loadPrefs()` 对每个字段都做 `typeof` 校验后再赋值，新增字段请沿用这个防御写法——旧版本残留的 JSON 结构不可假设。
7. **提示条文案**：所有截断/中断提示统一走 `truncated` 变量与 `notesFor()`，不要在渲染函数里另起一套提示逻辑，否则会出现「状态栏说中断、结果区说无匹配」的不一致。
