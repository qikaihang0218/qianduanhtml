# 二维码工坊 · 操作文档

> 源文件：[../千问代码_专属二维码工坊.html](../千问代码_专属二维码工坊.html)
> 页面标题：`高级二维码生成器`（页面内主标题为 `✨ 专属二维码工坊`）
> 一句话定位：填文字 → 挑颜色尺寸 → 生成二维码 → 一键导出**带白色圆角边框和底部引导语**的成品海报图。
>
> 本文所有键位、取值范围、格式清单与存储键均基于当前仓库源码核对。

## 1. 工具简介

它是本工具集里**最轻的一个**（317 行），做一件很具体的事：把一段网址或文字生成二维码，然后在导出时**自动加一层「适合发朋友圈/打印张贴」的包装** —— 白色圆角底、四周 60px 留白、底部一行灰色引导语「长按识别二维码 · 获取更多信息」和一条分割线。中间可以叠一个圆形 Logo。

编码工作全部交给第三方库 **qrcode.js 1.0.0**，纠错等级**硬编码为 `H`**（`:191`，约 30% 容错），所以中心盖 Logo 后仍能被扫出来 —— 这不是巧合，是刻意选的。

适合谁用：

- 要做「扫码进群 / 扫码看菜单 / 扫码关注公众号」这类**成品图**的人，导出即用，不用再开 PS 加边框。
- 需要在二维码中心放一个小 Logo 的人。

**不适合的场景**：

- ⚠️ **它不是离线工具**。页面通过 `<script src>` 从 `cdnjs.cloudflare.com` 加载 qrcode.js（`:7`）。**断网或 CDN 被墙时，整个工具完全不可用**（点生成会报 `QRCode is not defined`）。这与根 README「无第三方运行时依赖」的表述冲突，详见第 7 章。
- **没有快捷键、没有历史记录、不保存配置**。刷新即回默认。
- **不能控制的东西很多**：底部文字固定不可改、Logo 大小固定 22%、纠错等级固定 H、导出格式只有 PNG、边框颜色强制白色。
- **不支持批量**：一次一条内容。要批量请自己写脚本，或先把数据整理成一行一条再逐个生成。
- 不适合对二维码有**规范级要求**的场景（如需要指定版本/掩码/精确静区、需要 SVG 矢量输出、需要 `NaNq` 之外的码制）。

## 2. 快速开始

1. **先确认能联网**（关键，见第 7 章）。
2. 双击 `千问代码_专属二维码工坊.html` 用 Chrome / Edge 打开。
3. 页面一打开就会**自动生成**一次默认二维码（`window.onload = generateQR`，`:313`），内容是默认的 `https://www.example.com`。看到预览区出现二维码，说明库加载成功。
4. 把「请输入网址或文字内容」改成你自己的链接。
5. 点 **`立即生成`**。
6. 约 0.3 秒后，`💾 保存精美图片` 按钮出现（`setTimeout(...,300)`，`:197-199`）。点它 → 下载 `专属二维码_<时间戳>.png`。

想加 Logo：在第 5 步之前点 `📤 点击上传 Logo 图标` 选一张**正方形**图（原因见 4.4），预览会自动重新生成。

## 3. 界面与功能分区

单张居中的毛玻璃卡片（`width:420px; max-width:90vw`，`:39-40`），悬停会上浮 5px。背景是 15 秒循环的四色流动渐变动画（`:18-28`）。卡片内自上而下 5 块：

### 3.1 内容输入（`:117`）

`<input type="text" id="text-input">`，默认值 `https://www.example.com`。**单行**输入框 —— 多行文本里的换行无法输入，只能靠 URL 编码。

### 3.2 参数行 `.settings`（`:119-132`，三列 flex，窄屏自动换行）

| 控件 | id | 类型 | 源码属性 | 默认 |
| ---- | ---- | ---- | ---- | ---- |
| 🎨 前景色 | `color-dark` | `color` | 无 | `#000000` |
| 🖼️ 背景色 | `color-light` | `color` | 无 | `#ffffff` |
| 📏 尺寸 (px) | `qr-size` | `number` | `min="100" max="800"` | `300` |

> ⚠️ **`min`/`max` 只是 HTML 校验提示，JS 完全不做钳制**。取值代码是 `parseInt(...) || 300`（`:177`）—— 手动敲 `50` 或 `2000` 会被原样采用（点上下箭头时浏览器才会拦）。填 `0`、`abc`、清空 → 回落 300。

> 前景/背景色**只作用于二维码本体**。导出的外框永远是白色（`:217` 硬编码 `#ffffff`），见 4.5。

### 3.3 Logo 上传（`:134-137`）

一个伪装成按钮的 `<label>` + 隐藏的 `<input type="file" id="logo-upload" accept="image/*">`。**只能选一个文件**（无 `multiple`），代码只取 `e.target.files[0]`（`:162`）。

### 3.4 按钮组（`:139-143`）

| 按钮 | id | 初始可见 | 处理函数 |
| ---- | ---- | ---- | ---- |
| 立即生成 | `generate-btn` | ✅ | `generateQR()` |
| 💾 保存精美图片 | `download-btn` | ❌ `display:none` | `downloadQR()` |
| 清空重置 | `clear-btn` | ✅ | `clearAll()` |

三个都用**内联 `onclick`** 绑定（不是 `addEventListener`）。

### 3.5 预览区（`:146-150`）

白色圆角盒子 `#preview-area`，内部 `#qrcode` 是 qrcode.js 的挂载容器（库会往里塞 `<canvas>` 和一个 `<img>`）。`#logo-preview` 是一张**绝对定位居中**的 `<img>`，`max-width/max-height:22%`、`border-radius:50%`、白底 `padding:3px`、带阴影（`:103-109`）—— 所以**预览里的 Logo 是等比缩放的正圆**，这点和导出不一致（见 4.4）。

## 4. 功能操作详解

### 4.1 生成 / 重新生成（`generateQR`，`:175-200`）

1. 读四个值：内容、尺寸、前景色、背景色。
2. 内容为空 → `alert("请先输入需要生成的内容哦！")` 并**中止**，预览保持上一次的结果。
3. `qrcodeContainer.innerHTML = ""` 清空容器，再把 `#logo-preview` 节点塞回去（`:184-185`）。
4. `new QRCode(container, {text, width:size, height:size, colorDark, colorLight, correctLevel: H})`。
5. 300ms 后显示下载按钮。

**没有「输入即生成」**：改颜色、改尺寸、改文字后**必须点 `立即生成`** 才生效，滑块/取色器不会自动重绘。

**容错等级固定 `H`**：同样的内容，H 级比 L 级能装的字数少很多。内容偏长时优先把纠错需求让位 —— 但本工具**没有纠错等级下拉框**，只能改代码（见第 10 章①）。

### 4.2 内容能写什么

qrcode.js 用 **UTF-8 字节模式**编码，所以中文、emoji、`?a=1&b=2` 查询串、`weixin://` 之类自定义协议都能正常编进去并被扫出。

但**没有任何长度上限提示**。内容超出二维码 v40-H 容量时，库内部会抛异常，而容器**已经在上一步被清空** → 表现为「点了生成，预览区一片空白，什么提示都没有」，只有 F12 控制台有红色报错（形如 `code length overflow`）。经验值：**中文约 200 字以内、URL 约 600 字符以内**比较稳；一旦超过先删字试。这是本工具最容易踩的坑，见 FAQ。

### 4.3 尺寸与导出尺寸的关系

设「尺寸」为 `S`（默认 300），导出的 PNG 实际尺寸是：

```
宽 = S + 120        // 左右各 padding 60（:209, :211）
高 = S + 200        // 上下 padding 60×2 + 底部文字区 footerHeight 80（:210, :212）
```

默认 300 → **480 × 500** 像素。想让成品更清晰，把「尺寸」手动改成 `600` 或 `800`（导出即 720×800 / 920×1000）；库不会按 DPR 自动放大，**所见像素 = 所得像素**。

二维码本体绘制在 `(60, 60)` 处（`:221`）。

### 4.4 Logo（`:161-173` 预览 / `:224-249` 导出）

1. 点 `📤 点击上传 Logo 图标` → 选图 → `FileReader.readAsDataURL` 读成 base64 存进 `uploadedLogo`。
2. **读取成功后会自动调一次 `generateQR()`**（`:169`），不用手点生成。
3. 预览里 Logo 以正圆显示在二维码正中。
4. 导出时**重新绘制**（不是把预览 DOM 截图）：白色圆形底座（半径 `logoSize/2 + 5`）→ 带阴影描边 → 叠 Logo 图（`:231-242`）。

**必须用正方形图的两个原因**：

- 导出走 `drawImage(img, x, y, logoSize, logoSize)`（`:242`），**强行拉成正方形**，非正方形 Logo 会被压扁。
- 预览用 `max-width/max-height:22%` 是**等比**的，导出是**强制等宽等高**的 → 非正方形图会出现「预览好看、导出变形」。

Logo 大小**固定为二维码宽度的 22%**（`:227`），界面上无滑杆可调。想改只能改源码（第 10 章②）。

**换 Logo**：再次上传即覆盖。**去掉 Logo**：只能点 `清空重置`（会连内容一起清掉），或改源码加个移除按钮。

> 预览与导出的一个可见差异：导出时圆形底座那句 `ctx.stroke()`（`:238`）用的是**默认黑色描边**（此处只设了 `fillStyle`，没设 `strokeStyle`），所以成品里 Logo 外圈有一圈很细的黑边，预览里没有。

### 4.5 导出图片（`downloadQR`，`:203-255`）

流程：取容器里的 `<canvas>` → 新建更大的画布 → 画白色圆角底（圆角半径 20）→ 画二维码 → （有 Logo 则等 `img.onload` 再画 Logo）→ 画底部引导语和分割线 → `toDataURL("image/png")` → 造 `<a download>` 点击下载。

导出图固定包含的元素（**均无 UI 可关**）：

| 元素 | 参数 | 源码 |
| ---- | ---- | ---- |
| 白色圆角底 | `#ffffff`，圆角 20px | `:217-218` |
| 四周留白 | 60px | `:209` |
| 底部引导语 | 文案 `长按识别二维码 · 获取更多信息`，`bold 24px 'Microsoft YaHei'`，`#999999`，居中 | `:259-263` |
| 分割线 | 宽 200px（左右各 100），`#eeeeee`，粗 2px | `:266-271` |

兜底：容器里没有 canvas（生成失败/还没生成）→ `alert("二维码还没生成好，请稍等~")`。

### 4.6 清空重置（`clearAll`，`:300-311`）

清空内容框（**变成空白，不是恢复成 `https://www.example.com`**）、前景回 `#000000`、背景回 `#ffffff`、尺寸回 `300`、移除 Logo 并重置文件控件、隐藏下载按钮、预览区清空。

## 5. 快捷键一览

**本工具没有任何键盘快捷键。**

源码中不存在 `keydown` / `keyup` / `keypress` 监听器。三个按钮全靠鼠标点击。

需要特别说明两点（容易误以为有）：

- **输入框里按 `回车` 不会生成**。输入框不在 `<form>` 内，也没有 `keydown`/`change` 绑定，按回车没有任何反应。
- **取色器和尺寸框改完不会自动重绘**，必须点 `立即生成`。

## 6. 支持的输入 / 输出格式

**输入**：

| 项 | 接受 | 限制 |
| ---- | ---- | ---- |
| 内容 | 任意单行文本：URL、中文、emoji、查询串、自定义协议 | 无 `maxlength`；超出二维码 v40-H 容量会静默失败（见 4.2）；**不支持换行** |
| 前景 / 背景色 | `<input type=color>` 的 `#rrggbb` | 只接受 6 位十六进制；**不支持透明度**，`rgba`/`transparent` 无法输入 |
| 尺寸 | 整数像素 | 界面提示 `min=100 max=800`，但 JS **不钳制**（见 3.2）；非数字回落 300 |
| Logo | `accept="image/*"`（PNG / JPG / GIF / WebP / SVG 等浏览器可解码的图） | 只取第一个文件；**强制按正方形拉伸**；无体积上限，超大图会转成很长的 base64 |

**不接收**：多文件、批量文本、vCard / 名片模板、图标字体、透明通道配置、配置文件导入。

**输出**：

| 项 | 说明 |
| ---- | ---- |
| 格式 | **仅 PNG**（`canvas.toDataURL("image/png")`，`:291`） |
| 文件名 | `专属二维码_<毫秒时间戳>.png`（`:294`），如 `专属二维码_1748231567890.png` |
| 尺寸 | `(S+120) × (S+200)`，S 为「尺寸」输入值 |
| 内容 | 白底圆角 + 二维码 + 可选圆形 Logo + 固定引导语 + 分割线 |

**没有的输出**：SVG / 矢量、JPG / WebP、透明背景 PNG、原始二维码裸图（不带边框）、Base64 复制到剪贴板、批量打包 zip、名片 vCard 文件。

> 如果只需要**不带任何装饰**的纯二维码：把「尺寸」设大、导出后自行裁剪，或用浏览器开发者工具把 `#qrcode` 里的 `<canvas>` 另存 —— 源码没有提供这个开关。

## 7. 数据与隐私

**⚠️ 本工具是本仓库中唯一带第三方运行时依赖的页面。**

```html
<script src="https://cdnjs.cloudflare.com/ajax/libs/qrcodejs/1.0.0/qrcode.min.js"></script>  <!-- :7 -->
```

由此产生三个必须知道的事实：

1. **必须联网才能用**。库文件加载失败时，`window.QRCode` 不存在，`generateQR()` 第一行有效代码就抛 `QRCode is not defined`，页面看起来一切正常但**永远生成不出东西**（连 `alert` 都不会弹，因为异常发生在 `alert` 之前）。`window.onload = generateQR` 同样会静默失败。
2. **每次打开都会向 `cdnjs.cloudflare.com` 发起请求**，你的 IP 与所请求的页面 URL（作为 `Referer`，取决于浏览器与站点的引用策略）会到达该第三方 CDN。
3. 与根 README 的表述**存在冲突**：README 的「技术说明」写着「纯 HTML / CSS / JavaScript 实现，无第三方运行时依赖」，并把联网项限定为「个别页面通过 `<link>` 引入 Google Fonts 字体」。**本页不属于该情况** —— 它引的是第三方 **脚本**，且缺了就不可用。以源码为准。

**内容本身不外传**：全文没有 `fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon`，也没有任何埋点。你输入的网址、文字、上传的 Logo 全程只在浏览器内存和 `data:` URL 里流转，编码在本地完成。

**零持久化**：

- 不使用 `localStorage`、`sessionStorage`、`IndexedDB`、Cookie、Service Worker。
- **刷新页面 = 全部回默认**，内容、颜色、尺寸、Logo 全丢。**没有历史记录，也没有「上次内容」记忆**。重要的内容请自己先存在别处。
- 上传的 Logo 以 base64 存在变量 `uploadedLogo` 里（`:157`），不落盘。

**导出文件**：纯 PNG 位图，不含 EXIF 之外的隐私信息；文件名里的时间戳是你本机时间。

**离线使用建议**（三种，任选）：

1. 把 `qrcode.min.js` 下载到同目录，把 `:7` 改成 `<script src="./qrcode.min.js"></script>`（第 10 章③）。
2. 在有网时打开页面后**不要关标签页**（库已缓存在内存里）。
3. 接受不可用，改用离线方案（如本地起服务 + 自研编码器）。

## 8. 常见问题（FAQ）

**点「立即生成」完全没反应，控制台报 `QRCode is not defined`。**
CDN 没加载到 —— 断网、被代理拦截、或防火墙拦了 `cdnjs.cloudflare.com`。按 F12 → Network 刷新看那个 `qrcode.min.js` 的状态码。彻底解决见第 10 章③（本地化）。

**内容稍长一点，点生成后预览区一片空白，也不报错。**
超出纠错等级 H 的容量，库抛异常，但容器**已经被清空**（`:184`），所以你只看到空白。处理顺序：① 缩短内容 / 改用短链；② 把纠错等级从 `H` 改成 `Q`/`M`/`L`（`:191`，见第 10 章①）容量立刻上浮一大截；③ 看控制台确认是不是 `code length overflow`。

**扫不出来 / 识别率很低。**
按可能性排序：① **前景背景色对比不足** —— 比如深灰底 + 深蓝码，或选了浅色前景；保持黑码白底最稳。② **尺寸太小** —— 100px 装中文基本扫不出，建议 ≥ 300，长内容 ≥ 500。③ **Logo 遮挡** —— 纠错等级 H 也只容约 30%，Logo 已占 22% 宽度（实际遮挡约 5% 面积），若再叠加低对比色就会失败。④ 打印时缩小导致模块小于打印机精度。

**导出图很糊。**
「尺寸」就是最终像素数，不做任何放大。把尺寸手动改成 `600`–`800` 再导出。

**Logo 在导出图里变形了。**
已知行为：导出强制等宽等高（`:242`）。**换成正方形源图**即可。

**Logo 外面为什么有一圈黑边？**
`:238` 的 `ctx.stroke()` 之前没设 `strokeStyle`，用了默认黑色。想白边：在 `:238` 前加 `ctx.strokeStyle="#ffffff";`。

**改了颜色但导出图的外框还是白的。**
设计如此 —— 外框在 `:217` 硬编码白色，`color-light` 只影响二维码本体那一块。想让外框跟背景色一致，见第 10 章④。

**底部那句「长按识别二维码」能改吗？**
界面上不能。`drawFooter` 里是常量（`:259`）。改法见第 10 章⑤（含直接去掉整条 footer 的做法，注意同时改画布高度）。

**按回车没反应 / 有没有快捷键？**
都没有（见第 5 章）。只能点按钮。

**刷新后我刚才填的东西没了。**
本工具**完全不保存任何数据**（第 7 章）。这不是 bug。

**想一次生成一批。**
不支持，没有队列/表格界面。

**`min="100" max="800"` 为什么拦不住我输入 50？**
`min`/`max` 只在表单提交和数字框上下箭头时生效，本页没有表单校验逻辑，`parseInt` 直接采用输入值（`:177`）。

**上传的 Logo 会被传到服务器吗？**
不会，本页无任何网络上传（唯一外联是加载 CDN 脚本）。但请注意：**导出/分享图片时，二维码指向的内容和 Logo 版权由你自己负责**。

## 9. 技术实现要点（开发者）

**文件结构**：317 行单文件。`<style>` 在 `:8-110`，DOM 在 `:112-151`，脚本在 `:153-314`（无模块、无严格模式、全部 `var` 全局函数 + 内联 `onclick`）。

**用到的 Web API**：`FileReader.readAsDataURL`、Canvas 2D（`drawImage`、`arc`、`quadraticCurveTo`、`fillText`、`shadowBlur`、`toDataURL`）、`<a download>` 触发下载、CSS `backdrop-filter` + `@keyframes`。**没有** `localStorage` / `fetch` / `crypto` / `URL.createObjectURL`。

> 注意它用的是**自实现 `roundRect`**（`:275-288`），不是原生的 `ctx.roundRect()`，所以不需要较新内核；真正的门槛只有那个 CDN 脚本。

**依赖库**：`qrcodejs 1.0.0`（cdnjs）。用到它的公开面只有三处：构造函数 `new QRCode(el, opts)`、`QRCode.CorrectLevel.H`、以及它塞进容器的 `<canvas>`。库自身的行为（模块尺寸取整、静区处理、UTF-8 字节模式编码、超长抛 `code length overflow`）都在库内，**本仓库源码未包含其实现**，改动需改库文件或换库。

**函数索引**：

| 函数 | 行号 | 作用 |
| ---- | ---- | ---- |
| `logo-upload` 的 `change` 监听 | 161-173 | 读文件 → `uploadedLogo` → 显示 → 自动 `generateQR()` |
| `generateQR()` | 175-200 | 读参 → 校验非空 → 清容器 → `new QRCode` → 300ms 后亮下载钮 |
| `downloadQR()` | 203-255 | 建外框画布 → 画底 → 画码 →（异步）画 Logo → 画 footer → 下载 |
| `drawFooter()` | 258-272 | 引导语 + 分割线 |
| `roundRect()` | 275-288 | 圆角矩形路径 + 可选填充 |
| `triggerDownload()` | 290-298 | `toDataURL` → `<a download>` → 点掉 |
| `clearAll()` | 300-311 | 复位全部控件与状态 |
| `window.onload` | 313 | 首屏自动生成 |

**全局状态**：`uploadedLogo`（Logo 的 base64 或 `null`）、`qrcodeObj`（QRCode 实例，**赋值后从未被读取**，`:158`、`:188` —— 属于预留/死变量）。

**数据流**：

```
输入控件 ──(点「立即生成」)──▶ generateQR()
                                ├─ #text-input.value / #qr-size.value / 两个 color.value
                                ├─ #qrcode.innerHTML = ""   ← 先清空（异常时不可回滚）
                                ├─ new QRCode(#qrcode, {...correctLevel:H})
                                │     └─ 库在 #qrcode 内生成 <canvas> + <img>
                                └─ setTimeout(300) → 显示 #download-btn

点「保存精美图片」 ──▶ downloadQR()
                        ├─ #qrcode.querySelector("canvas")        ← 取库生成的码图
                        ├─ 新建 finalCanvas (S+120) × (S+200)
                        ├─ 白底圆角 → drawImage(canvas, 60, 60)
                        ├─ uploadedLogo? → new Image(); img.onload ─┐
                        └───────────────────────────────────────────┴─▶ drawFooter() → triggerDownload()
```

**两处值得注意的实现细节**：

1. **`innerHTML = ""` 在 `new QRCode` 之前**（`:184`）。库抛异常时容器已经空了，这就是「空白无提示」的成因。
2. **有 Logo 时导出走异步 `img.onload`**（`:226-248`），无 Logo 时同步。两条分支都以 `triggerDownload` 收尾，但只有 `if/else` 保证互斥 —— 若将来给 `uploadedLogo` 加了加载失败处理，`onload` 不触发会导致**静默不下载**。

**性能**：`padding`/`footerHeight`/`logoSize` 全是常量，无循环热点；唯一的开销是超长 base64 Logo 的重复解码（每次导出都 `new Image()` 一次）。

## 10. 二次修改指引（开发者）

改造成本很低（317 行、无框架），下面按需求频率排序。

**① 加纠错等级下拉（同时解决「长内容失败」）**

`:191` 的 `correctLevel: QRCode.CorrectLevel.H` 改成读控件：

```html
<select id="qr-level">
  <option value="L">L · 容量最大</option>
  <option value="M" selected>M · 均衡</option>
  <option value="Q">Q</option>
  <option value="H">H · 可放 Logo</option>
</select>
```

```js
// generateQR 内
correctLevel: QRCode.CorrectLevel[document.getElementById("qr-level").value] || QRCode.CorrectLevel.H
```

**注意**：中心带 Logo 时不要用 `L`/`M`，遮挡会导致扫不出。默认给 `M` 并在带 Logo 时提示切回 `H`。

**② 让 Logo 大小可调**

`:227` 的 `canvas.width * 0.22` 和 `:106` 的 `max-width:22%` 是**两处独立常量**，必须一起改，否则预览与导出不一致。加一个 `<input type=range id="logo-scale" min="10" max="30" value="22">`，然后：

```js
var r = (parseFloat(document.getElementById("logo-scale").value) || 22) / 100;
// 导出：var logoSize = canvas.width * r;
// 预览：logoPreview.style.maxWidth = logoPreview.style.maxHeight = (r*100) + "%";
```

顺手修等比变形：把 `:242` 换成按源图比例计算 `dw/dh` 后居中绘制。

**③ 离线化（推荐优先做）**

把 `https://cdnjs.cloudflare.com/ajax/libs/qrcodejs/1.0.0/qrcode.min.js` 下载到项目根目录，`:7` 改为 `<script src="./qrcode.min.js"></script>`。这样才真正符合根 README「无第三方运行时依赖」的承诺。改完记得同步更新本文第 7 章。

**④ 让导出外框跟随背景色**

`:217` 的 `ctx.fillStyle = "#ffffff"` 改为 `document.getElementById("color-light").value`。**副作用**：Logo 的白色圆形底座（`:234`）仍是白的，在非白底上会露出一个白圆 —— 要么一起改色，要么接受这个观感。

**⑤ 改/删底部引导语**

改文案：`:259` 的 `text`。想让它可输入，在卡片里加一个 `<input id="footer-text">`，`drawFooter` 第一行改成 `var text = document.getElementById("footer-text").value;`，并配合 `clearAll` 复位。

彻底删掉 footer：把 `drawFooter` 的调用（`:245`、`:252`）删掉，**同时**把 `:210` 的 `footerHeight` 改成 `0`，否则成品底部会多一条 80px 空白。

**⑥ 加尺寸钳制（消除 3.2 的坑）**

`:177` 改成：

```js
var raw = parseInt(document.getElementById("qr-size").value, 10);
var size = isNaN(raw) ? 300 : Math.min(800, Math.max(100, raw));
```

**⑦ 捕获生成异常，给出人话提示**

把 `:188-192` 包起来，避免「空白无提示」：

```js
try {
    qrcodeObj = new QRCode(qrcodeContainer, { /* … */ });
} catch (err) {
    qrcodeContainer.innerHTML = "";
    qrcodeContainer.appendChild(logoPreview);
    alert("内容太长，二维码放不下（当前纠错等级为 H）。请缩短内容或降低纠错等级。");
    return;
}
```

**⑧ 加一个「移除 Logo」按钮**

```js
function removeLogo() {
    uploadedLogo = null;
    document.getElementById("logo-upload").value = "";
    logoPreview.style.display = "none";
    generateQR();
}
```

**⑨ 支持回车生成**

```js
document.getElementById("text-input").addEventListener("keydown", function (e) {
    if (e.key === "Enter") generateQR();
});
```

若要往本文第 5 章补快捷键，记得同时说明「焦点在输入框内」这个生效条件。

**⑩ 加 localStorage 记忆（本工具目前完全没有存储）**

```js
var KEY = "qrWorkshop.v1";
function saveCfg() { try { localStorage.setItem(KEY, JSON.stringify({
    text: textInput.value, dark: colorDark.value, light: colorLight.value,
    size: sizeInput.value, level: levelSel && levelSel.value })); } catch (e) {} }
```

读取放在 `window.onload` 里、`generateQR()` 之前。**注意**：Logo 的 base64 可能几百 KB，**不要**塞进 `localStorage`（配额一般 5MB）。若要做，务必在本文第 7 章登记这个新键名。

**⑪ 输出裸二维码 / SVG**

裸图：`:291` 前把 `triggerDownload(finalCanvas)` 换成 `triggerDownload(canvas)` 即可跳过全部装饰。
SVG：qrcodejs 1.0.0 **不提供** SVG 输出，需要换库（如 `qrcode` npm 版的浏览器打包产物）或自己从库的模块矩阵重绘 —— 属于换依赖而非改几行，动手前先确认值得。

**⑫ 别踩的坑**

- `#logo-preview` 这个 DOM 节点会被 `innerHTML=""` **销毁又复用**（`:184-185`）。任何缓存了它子节点/位置引用的代码都会失效；`clearAll` 里重新 `getElementById` 再赋值（`:308-309`）就是为此。
- `qrcodeContainer` 里除了你关心的 `<canvas>`，库还会放一个 `<img>`。用 `querySelector("canvas")` 而不是 `firstChild` —— 而且 `logoPreview` 是**先被 append 的**，`firstChild` 会拿到它。
- 三个按钮用内联 `onclick`，函数必须是**全局**的。若你给文件加 `<script type="module">`，`generateQR` 等函数会从全局消失，三个按钮**全部失灵**。
- 页面 CSS 用了 `backdrop-filter`（`:33-34`），老 Firefox 无毛玻璃效果但不影响功能。
