# 数字签名工坊 · 操作文档

> 源文件：[../数字签名.html](../数字签名.html)
> 页面标题：`🔏 数字签名工坊 · 加密签名 + 手写签名`
> 一句话定位：一个页面装两套互不相干的工具——基于 Web Crypto 的 RSA-2048/SHA-256 签名验签，以及一个手写签名画板导出图片。
>
> 本文所有键位、取值范围、格式清单与存储键均基于当前仓库源码核对。

## 1. 工具简介

页面用两个 Tab 分成完全独立的两个工具（`:97-100`）：

**① 加密数字签名**（`#pane-crypto`）：用 Web Crypto API 生成 RSA-2048 密钥对，用私钥对一段**文本**做 `RSASSA-PKCS1-v1_5 / SHA-256` 签名，输出 Base64；任何人拿公钥 + 原文可验证是否被篡改。附带一个亮点：页内藏了一份**独立可下载的 `DigitalSignature.js` 工具类**，下载后可直接在别的项目里复用。

**② 手写签名**（`#pane-hand`）：Canvas 画板，鼠标/触控笔书写，导出 PNG / JPG 图片。

适合谁用：

- 想直观理解「签名/验签/防篡改」是怎么回事的人（改一个字立刻验签失败，演示效果很好）。
- 需要一份干净的 RSA 签名工具类塞进自己项目（点 `下载工具类` 拿 `DigitalSignature.js`，浏览器与 Node.js 17+ 通用）。
- 需要一张手写签名图片贴到文档里的人。

**不适合的场景**：

- **不能对文件签名**。签名对象只有「签名文本框」里的字符串，没有文件上传口。要给文件签名得自己先算哈希再贴进来。
- **不能做生产用途的身份体系**。没有证书、没有 CA、没有 CRL/OCSP、没有密钥持久化，密钥只活在内存里，刷新即丢。
- 算法**固定为 RSA-2048 + PKCS#1 v1.5 + SHA-256**，页面上没有算法/ECC/Ed25519 的选择器。
- 手写画板**没有撤销、没有橡皮、没有压感**，画错了只能整体清空。

## 2. 快速开始

### 加密签名最短路径

1. **必须**用 `http://localhost` 或 HTTPS 打开本页。直接双击以 `file://` 打开时 `crypto.subtle` 不可用，生成密钥会直接报错（页面自身也写了这条提示，`:125`）。
   本地起服务示例：在项目目录执行 `python -m http.server 8000`，再访问 `http://localhost:8000/数字签名.html`。
2. 点 `生成新密钥对` → 公钥、私钥两个文本框自动填好，验证公钥框也自动填好。
3. 在「待签名 / 待验证的文本」里输入内容，点 `⚡ 生成签名` → 下方出现一长串 Base64。
4. 点 `🛡️ 验证签名` → `签名有效 ✅`。
5. 回第 3 步那个框里**改任意一个字**，再点 `🛡️ 验证签名` → `签名无效 ❌`。

### 手写签名最短路径

1. 点顶部 `🖊️ 手写签名` 标签。
2. 在白色画板上用鼠标写。
3. 点 `💾 导出 PNG`，得到 `我的签名.png`。

## 4. 功能操作详解

### 4.1 生成密钥对

1. 点 `生成新密钥对`。
2. 参数固定（`DEFAULT_ALGO`，`:215-220`）：`RSASSA-PKCS1-v1_5`、`modulusLength: 2048`、`publicExponent: 65537`、`hash: 'SHA-256'`。
3. 生成后公钥/私钥分别按 SPKI / PKCS#8 导出为 PEM，64 字符一行（`derToPem`，`:260-263`）。
4. 公钥同时被**自动复制进验证公钥框**，方便自测（`:321`）。
5. 再点一次会**直接覆盖**两个框，旧密钥不可恢复。

### 4.2 签名

1. 在 `signText` 输入文本（不能为空，否则提示 `请先输入要签名的内容`）。
2. 点 `⚡ 生成签名`。
3. 使用私钥的优先级（`:388-398`）：
   - 优先用内存里的 `savedKey`（本次生成或点过 `载入签名` 的）；
   - 否则读 `privPem` 框内容，必须包含字符串 `PRIVATE KEY` 才尝试导入；
   - 两者都没有 → 提示 `尚未生成或被载入私钥`。
4. 结果是一行 Base64（RSA-2048 固定 256 字节 → Base64 约 344 字符）。
5. **同样的文本 + 同一把私钥，每次签名结果相同**（PKCS#1 v1.5 是确定性签名，不是 PSS）。
6. `清空签名` 把结果区复位成 `—`。

### 4.3 验证

1. 把对方的公钥粘进 `verifyPub`（必须含 `PUBLIC KEY`，否则提示 `请粘贴有效的公钥（-----BEGIN PUBLIC KEY-----）`）。
2. 把签名 Base64 粘进 `verifySig`。
3. 确保 `signText` 里是**原始未改动**的文本。
4. 点 `🛡️ 验证签名`。三种结果：
   - `签名有效 ✅：文本未被篡改，且由对应私钥签名。`
   - `签名无效 ❌：文本被修改，或公钥/签名不匹配。`
   - `验证失败：<异常信息>`（Base64 非法、PEM 格式错等解析类错误走这里）。
5. 签名 Base64 里的空白字符会被容忍（`b64ToBuf` 先 `replace(/\s/g,'')`，`:279`），从微信/邮件里粘贴带换行的签名没问题。

### 4.4 复用已生成的密钥对

生成后 `.saved-keys` 区域出现一张卡片：

- `载入公钥验证`：把该公钥写入验证框。
- `载入签名`：把该私钥 `importKey` 成 `CryptoKey` 放进内存，之后签名优先用它。

这个区域**只保留最近一次生成的那一对**（`renderSavedKeys([pub, priv])` 每次覆盖，`:322`）。想切回更早的密钥，只能手工把 PEM 粘回 `privPem` 框。

### 4.5 下载 DigitalSignature.js

点 `⬇️ 下载工具类`：把页面里 `<script type="text/plain" id="libSource">` 的**原文**导出成 `DigitalSignature.js`（`:369-377`）。

- 该 UMD 模块支持 `module.exports` / AMD / 全局 `window.DigitalSignature` 三种接入。
- 页面本身就是靠 `Function(...)` 执行这段源码来加载类的（`:309`），所以**下载到的文件与页面实际用的代码逐字一致**。
- Node.js 用法（17+，需 `globalThis.crypto`）：
  ```js
  const DigitalSignature = require('./DigitalSignature.js');
  const ds = new DigitalSignature();
  const { publicKeyPem, privateKeyPem } = await ds.generateKeyPair();
  const sig = await ds.sign(privateKeyPem, 'hello');
  const ok  = await ds.verify(publicKeyPem, sig, 'hello');
  ```

### 4.6 手写签名与导出

1. 切到手写 Tab（切换时会调 `resizeCanvas()` 重设画板尺寸，`:305`）。
2. 选颜色、拖粗细，直接写。笔迹为圆头圆角连线（`lineCap/lineJoin = 'round'`），起笔补一个圆点避免点一下没痕迹。
3. 导出三种：

| 按钮 | 格式 | 背景 | 文件名 |
| ---- | ---- | ---- | ---- |
| `💾 导出 PNG` | PNG | **白底** | `我的签名.png` |
| `导出 JPG` | JPEG（质量 0.95） | 白底 | `我的签名.jpeg` |
| `裁剪空白导出` | PNG | **白底** | `我的签名.png` |

> ⚠️ **两处文案与实现不一致**（以源码为准）：
> 1. 页面说明写「导出为透明背景的 PNG」（`:174`），但画板初始化与清空都会 `fillStyle='#fff'` 铺满白底（`:447`），导出的 PNG **实际是白底不透明**。
> 2. `裁剪空白导出` 靠「alpha > 10」找内容边界（`:462`），而画布全区域 alpha 都是 255，因此边界永远等于整块画布 —— **该按钮目前等同于普通 PNG 导出，不会真的裁掉空白**。
>
> 想拿到真正的透明底签名，见第 10 章改法。
>
> 另外：窗口尺寸变化会触发 `resize` → `resizeCanvas()` → **清空已写的签名**（`:431`、`:429`）。写签名时别改窗口大小。

## 6. 支持的输入 / 输出格式

**输入**：

| 输入 | 格式 | 入口 |
| ---- | ---- | ---- |
| 待签名文本 | 任意 UTF-8 字符串（含空行、emoji） | `signText` 文本框 |
| 私钥 | PEM **PKCS#8**（`-----BEGIN PRIVATE KEY-----`） | `privPem` 或 `载入签名` |
| 公钥 | PEM **SPKI**（`-----BEGIN PUBLIC KEY-----`） | `verifyPub` |
| 签名 | Base64（容忍换行/空格） | `verifySig` |
| 手写笔迹 | 鼠标 / 触控笔 / 触屏（Pointer Events） | 画板 |

**输出**：

| 出口 | 格式 | 文件名 |
| ---- | ---- | ---- |
| 公钥 / 私钥 | PEM 文本，64 字符折行 | 复制到剪贴板 |
| 签名结果 | Base64 单行（256 字节 → 约 344 字符） | 复制到剪贴板 |
| 工具类 | JavaScript（UMD） | `DigitalSignature.js` |
| 手写签名 | PNG / JPEG(0.95) | `我的签名.png` / `我的签名.jpeg` |

**明确不支持**：上传文件并签名；输出 DER / JWS / JWS-JWT / PGP；导入 PKCS#1（`-----BEGIN RSA PRIVATE KEY-----`）格式的私钥；导入加密私钥（带 passphrase）；ECDSA / Ed25519 / RSA-PSS；签名时间戳；手写签名导出 SVG、PDF、透明底 PNG。

## 7. 数据与隐私

- **完全不联网**：源码中无 `<link>`、无 `@import`、无 `fetch`、无 `<script src>`、无任何外部域名。
- **零持久化**：源码中**没有任何 `localStorage` / `sessionStorage` / `IndexedDB` / Cookie 读写**。密钥只存在 JS 变量 `savedKey` 与 textarea 里，**刷新页面即彻底丢失**。
- 手写笔迹只存在于 Canvas 位图中，页面自身不留存。
- 复制功能用 `navigator.clipboard.writeText()`，失败时退到 `document.execCommand('copy')` —— 两者都是本地操作。
- **隐私提醒**：正因为没有持久化，「私钥永不上传」是真的；但也意味着**关掉页面 = 私钥永久丢失**，用签名做正式用途前必须立刻点 `复制私钥` 并自行安全保存。
- **清除方法**：无需清除，关闭标签页即清空全部状态。

## 8. 常见问题（FAQ）

**点「生成新密钥对」报「当前环境不支持 Web Crypto API」。**
`file://` 打开时浏览器不提供 `crypto.subtle`。用 `python -m http.server` 起本地服务后走 `http://localhost`，或部署到 HTTPS。**注意**：`http://127.0.0.1` 也算安全上下文，同样可用。

**`下载工具类` 在 `file://` 下能用吗？**
能。下载的是静态源码文本，不依赖 Web Crypto。但下载下来的 `DigitalSignature.js` 在 `file://` 页面里同样无法工作。

**签名结果每次不一样？**
若你中间点过 `生成新密钥对`，那是新的密钥，签名自然不同。同一对密钥下 PKCS#1 v1.5 是确定性的，同文本必得同签名。

**验签一直「签名无效」。**
按顺序排查：① `signText` 是否被改过（含首尾空格、换行 —— 都算不同内容）；② `verifyPub` 是否是**签名那把私钥对应的**公钥；③ 签名是否被截断（聊天软件可能吞掉长文本）；④ 是否用别的工具以不同算法（如 SHA-1、PSS）签的名 —— 本页只认 `RSASSA-PKCS1-v1_5 + SHA-256`。

**报「验证失败：…」而不是「签名无效」。**
属于解析异常：Base64 含非法字符、PEM 缺 `BEGIN/END` 行、或粘进来的是私钥却贴到了公钥框。

**导入别人给的 `-----BEGIN RSA PRIVATE KEY-----` 失败。**
那是 PKCS#1 格式，`importPrivateKey` 只走 `pkcs8`（`:241`）。转换：
`openssl pkcs8 -topk8 -inform PEM -in rsa.pem -outform PEM -nocrypt -out pkcs8.pem`

**手写画板写了没痕迹 / 笔迹错位。**
高分屏或缩放比例变化后，CSS 尺寸与位图尺寸可能不同步。切走 Tab 再切回来（会触发 `resizeCanvas()`）即可对齐。

**手写签名写好了一刷新就没了。**
设计如此，无任何自动保存。导出了才有。

**导出 PNG 想透明底结果带白底。**
见 4.6 的不一致说明，需要改代码。

## 9. 技术实现要点（开发者）

**用到的 Web API**：`crypto.subtle.generateKey / importKey / sign / verify / exportKey`、`TextEncoder`、`atob`/`btoa`（Node 下退到 `Buffer`）、`navigator.clipboard`、Pointer Events、Canvas 2D + `toDataURL`、`Blob` + `URL.createObjectURL`。

**双层结构（本页最值得注意的设计）**：

```
<script type="text/plain" id="libSource">   ← 不执行的纯文本，DigitalSignature.js 的唯一源码
        │
        ├─ Function(textContent)()  → 注册 window.DigitalSignature  → const DS = new ...  （页面自用）
        └─ Blob + a.download        → DigitalSignature.js            （给用户下载）
```

好处是「页面用的」与「用户拿到的」不可能漂移。代价是这段代码里**不能出现字面量 `</script>`**。

**加密数据流**：

```
generateKeyPair()  generateKey(algo, extractable=true, ['sign','verify'])
                   → exportKey('spki'|'pkcs8') → DER → base64 → 64 字折行 PEM

sign(privPem, text)  pemToDer(去 BEGIN/END 与空白 → atob) → importKey('pkcs8')
                     → subtle.sign('RSASSA-PKCS1-v1_5', key, TextEncoder(text))
                     → 256 字节 → base64

verify(pubPem, sigB64, text)  importKey('spki') → subtle.verify(...) → boolean
```

## 10. 二次修改指引（开发者）

**改算法或密钥长度**：`DEFAULT_ALGO`（`:215-220`）可被构造参数覆盖 —— `new DigitalSignature({ algo: { name:'RSA-PSS', modulusLength:4096, publicExponent:new Uint8Array([1,0,1]), hash:'SHA-256' } })`。但 `sign`/`verify` 里传的是 `this.algo.name`，**RSA-PSS 还需要 `saltLength`**，得给这两个方法补参数。页面上若要暴露算法选择，记得同步卡片一的说明文案（`:106`）。

**加「对文件签名」**：加一个 `<input type="file">`，`await file.arrayBuffer()` → `crypto.subtle.digest('SHA-256', buf)` → 把哈希转 hex 或 base64url 当作 `text` 去签。这样签名体积恒定、与文件大小无关，是通行做法。别直接把几百 MB 二进制塞进 `sign` 的 `TextEncoder`。

**支持 PKCS#1 私钥**：`importPrivateKey` 写死 `'pkcs8'`（`:241`）。浏览器 `importKey` **不接受 PKCS#1**，需要自己解析 ASN.1 外层再包 PKCS#8 头，或直接提示用户用 openssl 转换（见 FAQ）。建议后者。

**做透明底 PNG**：两处要一起改，只改一处无效：
1. `clearCanvas()`（`:447`）改成 `ctx.clearRect(...)`，让画布保持透明；
2. `exportImg(type, whiteBg, crop)` 里 PNG 分支本来就不铺白（`:468`），改完 1 就自然透明。
   代价：屏幕上手写区会变成透明格/继承页面底色，需要给 `#sigCanvas` 加 CSS 背景来维持观感（CSS 背景不会进 `toDataURL`）。

**让 `裁剪空白导出` 真的能裁**：当前用 alpha 判定，透明底改造后就能正常工作。若坚持白底，需要把判定条件从 `d[i+3] > 10` 改成「像素不等于纯白」，例如 `!(d[i]>250 && d[i+1]>250 && d[i+2]>250)`，并注意抗锯齿边缘导致的边界外扩（现有 `pad = max(8, w*0.005)` 可保留）。

**加撤销功能**：在每次 `pointerup` 前把 `ctx.getImageData` 压入栈（或存 `canvas.toDataURL()`，内存更大但实现简单），`Ctrl+Z` 时 `putImageData` 回滚。注意 `resizeCanvas()` 会重置画布，栈里的快照尺寸会失效，`resize` 时应清空栈。

**持久化密钥**：想加「记住密钥」，把 PEM 写 `localStorage` 是**不安全**的（私钥明文落盘）。真要持久化，应引导用户下载 PEM 文件而不是存浏览器。若只是演示，用 `sessionStorage` 比 `localStorage` 更合适（关标签页即失）。

**注意 `savedKey` 有两种类型**：`genKeys()` 里存的是 **PEM 字符串**（`:318`），`renderSavedKeys` 的 `载入签名` 里存的是 **CryptoKey 对象**（`:346`）。`DS.sign(key, text)` 内部用 `typeof key === 'string'` 区分（`:245`），所以能工作。你若扩展这个变量，务必保留这个双态约定，否则会在 `importPrivateKey` 处炸。

**注意 `resize` 会清空画板**：`:431` 无条件重设尺寸并 `clearCanvas()`。若要避免误清，应缓存 `toDataURL()` 并在 resize 后 `drawImage` 回去（注意 DPR 变化时的缩放补偿）。
