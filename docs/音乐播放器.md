# 无损音乐播放器 · 操作文档

> 源文件：[../音乐播放器.html](../音乐播放器.html)
> 页面标题：`无损音乐播放器 · Lossless Player`
> 一句话定位：把本地音频文件夹拖进浏览器，用 Web Audio 做 10 段均衡器与实时频谱可视化，配 LRC 歌词的**单文件播放器**。
>
> 本文所有键位、取值范围、格式清单与存储键均基于当前仓库源码核对。

## 1. 工具简介

它是一个**内存驻留**的播放器：文件通过 `<input type=file>` 或拖放进入，用 `URL.createObjectURL` 交给 `<audio>` 播放，页面**从不读取整文件内容入库**（除了解析头部 1MB 元信息和一次用于画波形的 `decodeAudioData`）。

三块核心能力：

- **元信息自研解析**：不依赖任何库，直接读文件头解析 FLAC / WAV / AIFF / MP4(M4A) / ID3 / Ogg 的格式、位深、采样率、声道、标题/艺术家/专辑与内嵌封面（`readMeta`，`:745-771`）。
- **10 段参量均衡器**：32Hz–16kHz，`peaking` 滤波器串联，±12dB，8 个预设（`:798-808`）。
- **三种可视化**：频谱柱 / 示波器 / 对称频谱，`AnalyserNode` + Canvas（`drawVis`，`:912-1005`）。

适合谁用：

- 想快速试听本地无损文件、并确认它到底是「真无损还是有损转的」（界面上有 `无损`/`有损` 标签与位深/采样率/码率芯片）。
- 想调 EQ 玩手感、不想装播放器的人。
- 有 LRC 歌词文件、想要卡拉OK式跟读的人。

**不适合的场景**：

- **不是曲库管理器**。播放列表只活在内存里，**刷新即清空**，没有 IndexedDB，没有收藏、评分、播放次数、排序。
- **`accept` 里列的 `.wma .ape .wv .dsf .dff` 实际播不了**（见第 6 章），DSD 与 APE/WavPack 浏览器根本不解码。
- 没有播放队列持久化、没有睡眠定时、没有淡入淡出、没有声道平衡、没有 10 段以外的滤波（无低通/高通/陷波）。
- 歌词只能**手工导入单个 .lrc**，不会自动找同名文件。

## 2. 快速开始

1. 双击 `音乐播放器.html`，用 Chrome 或 Edge 打开。
2. 把音乐文件（或**整个文件夹**）直接拖到窗口里，出现「松开以导入音乐」遮罩后松手。
3. 左侧列表出现曲目，底部提示 `已添加 N 首`。
4. 点任意一行开始播放（首次点击即用户手势，Web Audio 图在这一步建立）。
5. 主画布开始跳动频谱；按 `V` 换可视化，按 `E` 开 EQ 面板，按 `L` 开歌词。
6. 想加歌词：先播着这首歌，按 `L` 打开歌词面板 → 点面板右上角 `↥` → 选 `.lrc` 或 `.txt`。

## 4. 功能操作详解

### 4.1 导入音乐

三种入口：

1. **拖放**：拖文件或文件夹进窗口。走 `webkitGetAsEntry` 递归遍历目录（`:1506-1519`）。
   > ⚠️ **已知缺陷**：目录分支的 `do { batch = await readAll(); } while (batch === undefined);`（`:1517`）—— `readAll()` 从不返回值，`batch` 永远是 `undefined`，**循环不会退出**。所以**拖入文件夹目前会卡住，歌曲加不进来**。请改用下面的「添加文件夹」按钮。
2. **`▤` 添加文件夹**：走 `<input id="dirInput" webkitdirectory>`，浏览器给出该目录下全部文件，`addFiles` 内部按扩展名/MIME 过滤（`:1189-1192`），非音频被丢弃。
3. **`＋` 添加文件**：多选。

导入流程（`addFiles`，`:1188-1222`）：过滤 → 逐个 `readMeta(f)` 解析头 1MB → 标 `bad`（扩展名在 `UNSUPPORTED` 里）→ 若元信息里没有时长，用临时 `<audio>` 探测（`probeDuration`，最多等 4 秒）。

- 列表按**导入顺序**排列，无排序功能。
- 重复导入同一文件会**再插一条**，不去重。
- 移除：每行 `×` → `removeTrack`（`:1238-1258`），会释放 ObjectURL；删的是当前曲则自动播下一首，删空则复位。
- 搜索框按 `state.filter` 过滤显示（`visibleTracks`，`:1092`），**不改变真实索引**，点过滤结果仍跳到正确曲目。无匹配时显示 `没有匹配的曲目`。

### 4.2 播放与四种模式

点 `btnMode` 循环：`顺序播放 → 列表循环 → 单曲循环 → 随机播放`（`:1407-1413`），**初始是「列表循环」**（`state.mode = 'list'`，`:779`），toast 会报当前模式名。

| 模式 | 到列表末尾（自动切歌） | 手动点下一首 | 上一首到开头 |
| ---- | ---- | ---- | ---- |
| `order` 顺序播放 | **停下**（`nextIndex` 返回 −1） | 回第 1 首 | **停在第 1 首** |
| `list` 列表循环（默认） | 回第 1 首 | 回第 1 首 | 到最后一首 |
| `one` 单曲循环 | 重播当前（`ended` 里直接 `currentTime=0; play()`） | 下一首 | 到最后一首 |
| `shuffle` 随机 | 随机（保证不连续重复） | 同左 | 到最后一首 |

`上一首` 的通用规则：**播放超过 3 秒时按「上一首」是回到本曲开头**，不到 3 秒才真的切上一曲（`:1344`）。

> 已知缺陷：`MODE_ICON.order` 与 `MODE_ICON.list` 的 SVG path **完全相同**（`:789-790`），所以这两种模式**图标看不出区别**，只能靠 toast 文案和高亮状态（非 order 才高亮）区分。

### 4.3 进度与波形

- 进度条不是滑块，是 `#wave` 画布。鼠标按下即 seek，按住移动连续 seek；触摸同理（`:1396-1400`）。
- 首次播放某曲后，后台用临时 `AudioContext.decodeAudioData` 解码整曲，取**左声道**抽成 **360** 个峰值点绘制波形（`buildPeaks`，`:1015-1047`）。解码期间显示细线进度，完成后自动换成波形。
- 大文件（几百 MB 的 WAV）这一步会占较多内存与时间；解码失败则 `track.peaks = null`，永久退回细线进度。
- 峰值归一化到最大值，所以「响的歌」和「安静的歌」波形一样高 —— 它显示的是**包络形状**，不是绝对电平。

### 4.4 均衡器

1. 点 `EQ` 或按 `E` 展开面板。
2. 拖动任一滑块，范围 **−12 到 +12 dB**，`step=1`，默认 0；滑块上方数字实时显示。
3. 点预设一键套用：`平坦` `流行` `摇滚` `爵士` `古典` `人声` `低音增强` `高音增强`（值见 `EQ_PRESETS`，`:799-808`）。套用后对应预设按钮高亮；手工动任一滑块会**取消高亮**（`:860`）。
4. 再点 `EQ` 或按 `Esc` **只是收起面板**，均衡器仍然生效。想真正复位要点 `平坦`。

频点与滤波器：`32 / 64 / 125 / 250 / 500 / 1k / 2k / 4k / 8k / 16k` Hz，全部 `type='peaking'`、`Q=1.05`，串联在 `preGain` 之后（`:818-836`）。

> ⚠️ **重要限制**：Web Audio 图是**懒创建**的 —— 只有第一次播放（`loadTrack` 的 autoplay 分支或 `togglePlay`）才调 `ensureAudio()`（`:812-837`）。在**首次播放之前**调 EQ，滑块数字会变但 `eqNodes` 还是空数组，`if (eqNodes[i])` 静默跳过（`:859`、`:881`），**设置不会保留到播放时**。正确顺序是：**先随便播一下，再调 EQ**。

### 4.5 可视化

点 `◍` 或按 `V` 循环三种（toast 报名字）：

| 模式 | 内部值 | 画法 |
| ---- | ---- | ---- |
| 频谱柱 | `bars` | 80 根柱，底部向上，`Math.pow(i/N, 1.7)` 对数分布取 bin，带 0.85 衰减的峰值保持 |
| 示波器 | `wave` | `getByteTimeDomainData` 画一条带辉光的时域曲线 |
| 对称频谱 | `mirror` | 88 根柱，以 `H×0.66` 为轴上下对称 |

- `fftSize = 4096`、`smoothingTimeConstant = 0.82`（`:827-828`），只取前 **60%** 的频点（`maxBin = freqData.length * 0.6`）。
- 有**帧内自动增益**：`scale = mx > 0.04 ? min(2.6, 0.78/mx) : 1`（`:996`），弱信号也能撑满画面 —— 所以柱子高度**不能当电平表读**。
- 暂停或未建图时，画三条缓慢起伏的低透明度波纹（`:919-935`），不是静止黑屏。
- 配色取 CSS 变量 `--accent` / `--accent-2`，跟随主题色。
- 动画循环 `visRaf` 自续帧、**从不 cancel**（`:913`），页面常驻一帧循环。

### 4.6 歌词（LRC）

1. 先播放一首歌（否则提示 `请先播放一首歌`）。
2. 按 `L` 或点 `词` 打开面板。
3. 点面板右上 `↥` 选 `.lrc` 或 `.txt` 文件。
4. 成功提示 `歌词已载入 · N 行`；没有时间轴则 `未识别到歌词时间轴`。

支持的 LRC 语法（`parseLrc`，`:1536-1551`）：

- 时间标签正则 `\[(\d{1,3}):(\d{1,2})(?:[.:](\d{1,3}))?\]` —— 分可 1–3 位、秒 2 位、小数部分 1–3 位可选，分隔符 `.` 或 `:` 都认。
- **一行多标签**（`[00:12.00][01:30.00]副歌`）会展开成两条，共用同一段文字。
- 解析完按时间**重新排序**，所以原文件顺序乱也没关系。
- 空文本行显示为 `♪`。

**不支持**：`[ar:]` `[ti:]` `[al:]` `[by:]` `[offset:]` 等元数据标签**全部被忽略**，`[offset:]` 不会整体平移时间轴。若歌词整体偏早/偏晚，只能自己改文件。

- 点击任意一行**直接跳到该时间**（`:1570-1573`）。
- 当前行判定有 **+0.15 秒提前量**（`:1582`），高亮行会平滑滚动到面板中央（仅面板打开时滚动）。
- 歌词存在 `track.lrc` 上，**切歌会清空**，不会自动匹配同名 .lrc（面板占位文案「可导入同名 .lrc 文件」有误导性，实际必须手动选文件）。

### 4.7 主题色

点 `◐` 循环四套：`青碧 teal → 紫霞 violet → 琥珀 amber → 海蓝 blue`（`:1448-1449`）。写入 `localStorage`，下次打开自动恢复。

### 4.8 系统媒体控制

若浏览器支持 `MediaSession`，加载曲目时会设置元数据并注册 `play` `pause` `previoustrack` `nexttrack` `seekbackward`（−10s） `seekforward`（+10s）（`:1626-1641`）。因此系统的媒体浮窗、键盘媒体键、蓝牙耳机按键可控。

> 注意：MediaSession 的 seek 步长是 **10 秒**，键盘方向键是 **5 秒**，两者不一致。

## 5. 快捷键一览

源码中**只有一个** `keydown` 监听（`:1647-1663`），无 `keyup`/`keypress`/内联 `onkey*`。守卫：焦点在 `input` 或 `textarea` 上时**全部失效**（因此光标在搜索框里时快捷键都不能用，`Esc` 也不行）。按键区分大小写判断（`m`/`M` 各写了一次）。

| 按键 | 动作 | 备注 |
| ---- | ---- | ---- |
| `空格` | 播放 / 暂停 | 已 `preventDefault`；列表为空时 toast `请先添加音乐文件` |
| `→` | +5 秒 | 已 `preventDefault`，上限为 `duration` |
| `←` | −5 秒 | 已 `preventDefault`，下限 0 |
| `↑` | 音量 +0.05，**并自动取消静音** | 上限 1.0 |
| `↓` | 音量 −0.05 | 下限 0；**不会**自动取消静音 |
| `M` | 切换静音 | — |
| `N` | 下一首（按当前模式） | — |
| `P` | 上一首（>3s 则回本曲开头） | — |
| `L` | 开合歌词面板 | 等同点 `词` |
| `V` | 循环可视化模式 | 等同点 `◍` |
| `E` | 开合 EQ 面板 | 等同点 `EQ`，**不是旁通** |
| `Esc` | **只关 EQ 面板** | 不关歌词面板、不停播放 |

未在源码中确认的键位：`F` 全屏、`S` 搜索聚焦、`+/-` 音量、`J/K` 跳转、`Ctrl+方向键` 切歌 —— 均无绑定。

## 6. 支持的输入 / 输出格式

**输入 — 音频**（能真正解码播放的取决于浏览器，不是 `accept`）：

| 扩展名 | 元信息解析 | 能否播放 | 说明 |
| ---- | ---- | ---- | ---- |
| `.flac` | ✅ `parseFlac`（含位深/采样率/声道/Vorbis 注释/封面） | ✅ | 无损 |
| `.wav` | ✅ `parseWav` | ✅ | 无损 PCM |
| `.aif` `.aiff` | ✅ `parseAiff` | ✅ | 无损 |
| `.m4a` `.mp4` `.aac` | ✅ `parseMp4` | ✅ | AAC 有损 |
| `.mp3` | ✅ `parseId3`（ID3v2 标签 + 封面） | ✅ | 有损 |
| `.ogg` `.oga` | ✅ `parseOgg`（区分 Opus / Vorbis / OGG FLAC） | ✅ | — |
| `.opus` | 同 Ogg 路径 | ✅ | — |
| `.wma` | ❌ 仅按扩展名标格式 | ❌ 在 `UNSUPPORTED` | 浏览器不解码 |
| `.ape` `.wv` `.tta` | ❌ | ❌ 在 `UNSUPPORTED` | 浏览器不解码 |
| `.dsf` `.dff` | ❌ | ❌ 在 `UNSUPPORTED` | DSD，浏览器不解码 |
| `.aifc` `.caf` | ❌ | ❌ 在 `UNSUPPORTED` | — |

> **`accept` 与能力不一致**：文件选择框 `accept` 把 `.wma .ape .wv .dsf .dff` 都列了出来（`:452`），但它们在 `UNSUPPORTED`（`:469`）里，导入后会被标 `bad`，曲目行加灰、芯片显示 `浏览器不支持该编码`，点击播放 toast `浏览器无法解码 XXX，请转换为 FLAC / WAV`（`:1276`）。**这是源码的表述差异，不是你的文件坏了。**

**输入 — 歌词**：`.lrc`、`.txt`（UTF-8 文本，走 `file.text()`）。

**输入 — 封面**：只认音频文件**内嵌**封面（FLAC PICTURE block / ID3 APIC / MP4 covr），不读外部 `cover.jpg`。

**输出**：**没有任何导出功能**。不能导出播放列表、不能导出歌词、不能录制、不能导出频谱图。唯一的「产出」是屏幕上的画面与声音。

## 7. 数据与隐私

- **完全不联网**：源码中无 `<link>`、无 `@import`、无 `fetch`、无 `<script src>`、无任何外部域名。封面用 `URL.createObjectURL` 从本地 Blob 生成。
- **持久化只有 2 个 `localStorage` 键**：

| 键 | 值 | 写 | 读 |
| ---- | ---- | ---- | ---- |
| `mp-accent` | `teal` / `violet` / `amber` / `blue` | `:1455` | `:1669` |
| `mp-vol` | 音量字符串，如 `"0.85"` | `:1685` | `:1674` |

- **播放列表、歌词、EQ 设置、可视化模式、播放模式全部不持久化**，刷新即回到初始值（EQ 归零、模式回「列表循环」、可视化回「频谱柱」）。
- 不使用 `IndexedDB`、`sessionStorage`、Cookie。
- **音量持久化不完整**：只在 `volR` 的 `change` 事件（松手那一刻）写入，用 `↑`/`↓` 改的音量**不会保存**。
- **隐私提醒**：文件本体始终在你磁盘上，页面只持有 `File` 引用与 ObjectURL；关闭标签页即彻底释放。但 `decodeAudioData` 会把整曲 PCM 读进内存，大文件期间内存占用可观。
- **清除方法**：删 `localStorage` 里的 `mp-accent`、`mp-vol` 两个键即可，其余本来就不落盘。

## 8. 常见问题（FAQ）

**拖一个文件夹进去，什么都没发生。**
已知缺陷（见 4.1）。改用侧栏的 `▤` 按钮选文件夹。

**导入后提示「没有可识别的音频文件」。**
`addFiles` 的过滤条件要求 MIME 以 `audio/` 开头**或**扩展名在 `EXT_NAME`/`LOSSLESS_EXT`/`LOSSY_EXT` 三个表里（`:1189-1192`）。扩展名大小写不敏感（已 `toLowerCase`），但无扩展名的文件会被丢掉。

**点了播放没声音。**
按顺序查：① 该曲是否被标 `bad`（灰行 + `浏览器不支持该编码` 芯片）；② 音量是否为 0 或静音（`↑` 或 `M`）；③ 浏览器是否被系统静音；④ 若 toast 是 `无法播放：play() failed`，是自动播放策略问题，再点一次 `btnPlay`。

**EQ 调了完全没变化。**
首次播放前调的不生效（见 4.4 的懒建图说明）。先播一下再调。另外 `EQ` 按钮只是开合面板，不是开关 —— 面板关了 EQ 仍在起作用，觉得声音怪就点 `平坦` 复位。

**频谱不动 / 一直是几条淡波纹。**
那是暂停态的装饰波纹。播放中仍如此说明 Web Audio 图没建起来，刷新页面重新点播一次。

**波形一直是条细线，不出柱状。**
`buildPeaks` 的 `decodeAudioData` 失败了（该格式浏览器能流式播但无法整段解码，或文件过大超时），`track.peaks` 置 null 后不再重试。刷新重试或换格式。

**歌词不跟随 / 一直偏几秒。**
① 确认歌词面板是开着的（关闭时不滚动，但仍会高亮）；② `[offset:]` 标签**不被支持**，需手工改时间标签；③ 判定有 0.15 秒提前量，属正常。

**换了首歌歌词没了。**
歌词挂在具体曲目对象上且不落盘。每首歌都要重新导一次 .lrc。

**刷新后列表全空。**
设计如此，无持久化。想留列表只能下次重新拖。

**音量下次打开又变回 85%。**
用滑块拖到目标值并**松手**才会写 `mp-vol`；用 `↑`/`↓` 改的不保存。

**占了很多内存 / 页面变卡。**
每首解码过波形的曲目都持有 360 点 Float32Array（很小），但 `File` 引用与 ObjectURL 会累积。用行尾 `×` 移除不再听的曲目可释放。

## 9. 技术实现要点（开发者）

**用到的 Web API**：`<audio>` + `URL.createObjectURL`、`AudioContext` / `MediaElementAudioSourceNode` / `GainNode` / `BiquadFilterNode`×10 / `AnalyserNode`、`decodeAudioData`、Canvas 2D（含 `devicePixelRatio` 适配，上限 2）、`File.slice` + `DataView` 手写二进制头解析、`webkitGetAsEntry` 目录遍历、`webkitdirectory`、`navigator.mediaSession`、Fullscreen API、`localStorage`。

**Web Audio 图**（`ensureAudio`，`:812-837`，**懒创建、只建一次**）：

```
<audio> ──createMediaElementSource──▶ srcNode
            └─▶ preGain(gain=1，未使用)
                  └─▶ biquad[32Hz] ▶ biquad[64Hz] ▶ … ▶ biquad[16kHz]   (peaking, Q=1.05)
                        └─▶ analyser(fftSize=4096, smoothing=0.82)
                              └─▶ actx.destination
```

`freqData = Uint8Array(frequencyBinCount=2048)`，`timeData = Uint8Array(fftSize=4096)`。**没有压缩器**（`createDynamicsCompressor` 未使用），EQ 拉满可能削顶。

**数据流**：

```
File[] ─▶ addFiles()（1188）
          ├─ 扩展名/MIME 过滤
          ├─ readMeta(file)（745）→ 读前 1MB → parseFlac|Wav|Aiff|Mp4|Id3|Ogg 依次尝试
          ├─ UNSUPPORTED 判定 → track.bad
          ├─ probeDuration(f)（1224，临时 audio，4s 超时兜底）
          └─ state.tracks.push(track) → renderList()

playIndex(i) ─▶ loadTrack(i, autoplay)（1272）
          ├─ revokeObjectURL 旧 URL → createObjectURL → audio.src

          ├─ buildPeaks(t) 异步（临时 AudioContext 整段解码 → 360 峰值）

audio.timeupdate ─▶ tCur 文本 + drawWave() + syncLyrics(currentTime)
```

## 10. 二次修改指引（开发者）

**修「拖文件夹卡死」**：`walk` 的目录分支（`:1512-1517`）里 `readAll()` 从不 resolve 出值。`FileSystemReader.readEntries` 每次最多返回约 100 条，**必须循环读到空数组**才结束。正确写法是让 `readAll` 返回本批条目：

```js
const readAll = () => new Promise(res => {
  const acc = [];
  const step = () => reader.readEntries(async ents => {
    if (!ents.length) { res(acc); return; }
    for (const en of ents) await walk(en);
    step();
  }, () => res(acc));
  step();
});
await readAll();
```

改完把外层 `do…while` 删掉。**这是本页最该修的一处。**

**修 order/list 图标**：给 `MODE_ICON.order` 或 `.list` 换一个不同的 SVG path（`:789-790`）。想更明显可给 `list` 加一个循环箭头 path。

**修「首次播放前 EQ 无效」**：把 `ensureAudio()` 提到 `boot()` 里调用一次即可。但要注意 `createMediaElementSource` 之后 `<audio>` 的输出**必须**经音频图，若音频图被挂起就会完全无声 —— 所以同时要在 `boot()` 里不要 `resume()`，并在 `togglePlay` 保留现有的 `actx.state === 'suspended' → resume()` 逻辑（`:1317`）。若不想承担这个风险，另一种做法是把滑块值缓存到 `state.eqGains[10]`，`ensureAudio()` 建完节点后回填 `gain.value`。

**让 EQ / 播放模式 / 列表持久化**：
- EQ：新增 `mp-eq` 键存 10 个整数数组，`buildEq` 的 `input` 回调与 `applyPreset` 里写入，`boot()` 里读回（**必须在 `ensureAudio` 之后或配合上一条的缓存方案**）。
- 播放模式：存 `state.mode` 到 `mp-mode`，`boot()` 里回写 `icoMode` 图标与高亮。
- 列表：`File` 对象**无法**存进 IndexedDB 后还能读（实际上 Chrome 支持结构化克隆 `File`，但重开页面后文件句柄可能失效）。稳妥方案是改用 **File System Access API**（`showDirectoryPicker`）存 `FileSystemHandle` 进 IndexedDB，重新授权后可恢复列表。

**支持外部同名 .lrc**：`addFiles` 时若用户同时拖进了 `.lrc`，可按 `baseName` 建索引并挂到同名 track 的 `lrc` 上（`parseLrc` 已可直接复用）。这是当前最实用的一个增强点。

**支持 `[offset:]`**：在 `parseLrc` 里额外扫 `/^\[offset:\s*(-?\d+)\]/i`，取毫秒数，最后 `out.forEach(l => l.t += offset/1000)`。注意符号约定（LRC 规范里正值表示歌词**提前**）。

**加低通/高通/陷波**：`ensureAudio` 的 `eqNodes` 生成处（`:818-825`）把 `b.type` 改为可选。若要加「高切」，在 `prev.connect(analyser)` 之前插一个 `lowpass` 节点即可，注意它不属于 `eqNodes`，不受滑块控制。

**加压缩器防爆音**：在 `prev.connect(analyser)` 与 `analyser` 之间插 `createDynamicsCompressor()`（阈值 −12、比 12、 knee 12、attack 0.003、release 0.25）。EQ 全拉 +12 时目前会硬削顶。

**改可视化**：`state.vis` 加第四个值，在 `btnVis` 的 `order` 数组（`:1441`）与 `drawVis` 的分支（`:942` / `:986`）各加一处。柱数 `N` 目前写死 80/88（`:943`）；`peaks` 数组只在 `!peaks.length` 时按当前 N 初始化（`:946`），**切换柱数不同的模式不会重建 `peaks`**，会出现一帧错位 —— 若加新模式建议顺手在切换时 `peaks = []`。

**注意硬编码颜色**：`drawVis` 里有 `rgba(255,255,255,.05)` 底纹、示波器 `shadowColor` 之外的部分常量，主题色只走 `--accent`/`--accent-2`（`:906-910`）。新增绘制分支请统一用 `accentColors()`，否则换主题色会出现不协调的色块。

**注意 `visRaf` 从不 cancel**：`drawVis` 每帧自己 `requestAnimationFrame(drawVis)` 且 `boot()` 里启动了初始调用（`:1681`）。若你加「性能模式」开关，需要保存 `visRaf` 并 `cancelAnimationFrame`，目前这个变量已经存了但没人用它做取消。

**注意 `#wave` 不是滑块**：它没有键盘可达性，也不能用 `↑↓` 微调。若要做无障碍进度条，需换成 `role="slider"` + `aria-valuenow` 并补 `keydown`，注意别和全局快捷键冲突（全局守卫只排除 `input`/`textarea`）。
