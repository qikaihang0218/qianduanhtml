# 文件对比

> 源文件：[../文件对比.html](../文件对比.html)
> 页面标题：`File Diff · 文件对比工具`
> 一句话定位：把两份文本并排摆出来，标出哪几行改了、改的是哪几个词，并能把某一处差异整块搬到另一侧。
> 本文所有键位、取值范围、格式清单与存储键均基于当前仓库源码核对。

## 1. 工具简介

它是一个**文本 / 文件差异对比器**，工作模型和 Git 的 diff、VS Code 的「Compare Files」一致：给两份内容，它告诉你从旧版到新版改了什么。

适合这些场景：

- 手上有两个版本的配置文件 / Markdown / SQL，想知道到底动了哪几行。
- 别人发来的改动，需要贴成一份 `@@ -x,y +a,b @@` 格式的差异报告发给同事。
- 两份长文档看起来一样，但要确认是否**逐字相同**（相似度会直接显示 100% 或不到 100%）。
- 想把右侧的新写法批量回填到左侧旧文件里。

**不该用它的情况**：

| 需求 | 原因 | 建议 |
| ---- | ---- | ---- |
| 对比二进制文件（图片、zip、exe） | 只做文本对比，读到 `\u0000` 直接拒绝 | 用专门的二进制对比器 |
| 对比整个目录 / 多个文件 | 一次只吃两份内容，没有目录树 | 用 Git、Beyond Compare |
| 对比后直接写回本地文件 | 浏览器无写权限，改动只存在于页面内的文本框 | 复制结果或下载 `.diff` 后手工合并 |
| 单侧超过 2 MB 的巨型日志 | 有硬上限，会拒绝载入 | 先按时间段截一段再对比 |
| 需要语义级对比（如格式化后的 JSON 是否等价） | 只做行级 + 词级文本比较，不解析语法 | 先在 [全能格式化工具箱](./全能格式化工具箱.md) 里把两边格式化统一，再丢进来对比 |

## 2. 快速开始

**最短路径（30 秒看到结果）**

1. 双击 `文件对比.html` 用浏览器打开。
2. 点空屏中间的「载入示例」，或直接把两个文件分别拖到左右两侧。
3. 差异立刻出来：左侧红底是删除，右侧绿底是新增，同一行左右都有内容的是「修改」，行内还会把具体变化的词再高亮一层。
4. 底部状态栏显示差异处数、`+ / − / ~` 行数、相似度和耗时。

**用粘贴的方式**

1. 点工具栏「✎ 编辑」，屏幕切成左右两个文本框。
2. 左侧粘旧内容，右侧粘新内容。
3. 点「✓ 完成」或按 `Esc` 回到对比视图。输入停止 300 ms 后也会自动重算，不必手动触发。

**只想确认两段文本是否完全一样**

粘完两边，看标题栏右侧的胶囊：显示「内容完全一致」就是逐字相同；显示「N 个差异」则点「↓」逐个跳过去看。

### 3.3 面板头（Original / Modified）

每侧一行：状态圆点（有内容绿色、空为灰色）、固定名称、`N 行 · M 字符` 统计、`📂` 选择本地文件、`⧉` 复制本侧全文。

### 3.4 显示设置面板（`⚙`）

| 项 | 范围 / 默认 | 影响 |
| ---- | ---- | ---- |
| 上下文行数 | `1`–`10`，默认 `3` | 差异块上下各保留几行相同内容；同时决定折叠条隐藏多少行、`.diff` 报告的 hunk 上下文 |
| 字号 | `11`–`20` px，默认 `13` | 只改对比区与文本框字号（CSS 变量 `--fs`） |
| 自动换行 | 默认开 | 关掉后长行不折行，可横向滚动，左右两栏滚动位置同步 |
| 折叠相同行 | 默认开 | 关掉后所有相同行全部平铺 |
| 显示行号 | 默认开 | 关掉隐藏左侧行号栏 |
| 只读 | 默认关 | 勾上后两个文本框 `disabled`，防止误改 |

### 3.5 状态栏

`差异 N 处` · `+新增 / −删除 / ~修改` · `相似度 xx.x%` · 算法标记 · 行尾符标记 · 耗时。

- **相似度** = 相同行数 ÷ 总显示行数 × 100%。
- 算法标记：`Myers 精确匹配`（绿）或 `快速对齐（超出精确算法上限）`（黄）。出现黄色时结果仍可读，但配对质量下降，见第 8 章。
- 行尾符标记：两侧统一时显示 `行尾符 CRLF` 或 `行尾符 LF`；混用时显示 `行尾符混用（CRLF / LF）`。对比本身已统一换行，这个提示只是告诉你源文件换行风格不一致。

## 4. 功能操作详解

### 4.1 三种查看器的真实区别

同一份差异，三种排版。**只有「并排」会把修改行的新旧两行对齐在同一行**。

| 布局 | 修改行怎么显示 | 适合 |
| ---- | ---- | ---- |
| 并排查看器 `split` | 一行两栏：左栏旧内容标红，右栏新内容标绿，行内词级高亮生效 | 逐行核对，最省纵向空间 |
| 统一查看器 `unified` | 拆成两行：先一行 `- 旧内容`，再一行 `+ 新内容`，单栏带 `+` / `-` / 空格标记 | 和 Git 输出对齐、贴到别处给人看 |
| 内联查看器 `inline` | 也拆成两行，但仍在左右两栏里：删除行落在左栏（右栏留空），新增行落在右栏（左栏留空） | 既想一行一事、又想让左右内容在视觉上分栏归属 |

行号规则：并排视图左右各自显示自己那一侧的行号；空位（纯新增 / 纯删除）留空。统一视图每行只显示一个行号，`+` 行显示的是**右侧**行号，`-` 行与相同行显示**左侧**行号。

### 4.2 忽略规则

规则作用在「比较键」上，显示出来的仍是原文，只有判定是否相同用键值。

1. **忽略大小写**：`Hello` 与 `hello` 视为相同。
2. **忽略空白差异**：连续空白压成一个空格并去首尾，缩进不同、空格多寡不同都视为相同。
3. **忽略行尾空格**：只去掉行尾空格 / Tab。
4. **忽略空行**：空行（含只有空格的行）在比较前整行剔除，因此不会出现「多一个空行」的差异。
5. **忽略大小写与空白**：1 + 2 的组合。

注意：**除了 `不忽略`，其余规则下「采用右侧 / 采用左侧」按钮会被禁用**。因为被忽略的差异（如仅大小写不同）在按钮看来是「相同行」，拿不到可搬运的行号区间，硬搬会产生错误结果。要合并内容请先切回 `不忽略`。

### 4.3 词级高亮

行级 diff 判定「这一行变了」之后，再对变化行做一次 token 级 diff，把真正变动的字词高亮：

1. `高亮显示单词`：英文按连续字母数字下划线切，中文按**单字**切，空白与其它符号各自成 token。
2. `高亮显示字符`：按 Unicode 码点逐字符切，比单词模式更细（中文场景下与单词模式接近）。
3. `关闭词级高亮`：整行底色，不标局部。

单行 token 数超过 4000 时跳过词级对比，退化为整行高亮，避免超长行卡住。

### 4.4 载入文件

三条路：

1. 面板头 `📂` → 选择文件，按 UTF-8 读取。
2. **编辑屏**里把文件直接拖到某个文本框上，该框接收。
3. **对比屏**里把文件拖到结果区：左侧为空则填左侧，否则右侧为空填右侧，两侧都有内容时会提示「请点 ✎ 编辑 后拖到指定一侧」。

限制：单文件超过 **2 MB** 拒绝；读到的内容包含 `\u0000` 判为二进制并拒绝。

### 4.5 导航与选中差异块

1. 按 `Alt+↓` / `Alt+↑` 或点 `↓` `↑`，视图滚动到目标差异并居中，短暂蓝色闪烁。
2. 循环跳转：最后一处之后回到第一处。
3. 直接点结果区任意一行，即选中它所属的差异块（整块描蓝框），胶囊同步更新为 `N / 总数`。
4. **差异块** = 连续的非相同行合并成的一块。中间只要隔了一行相同内容，就算两处差异。

### 4.6 折叠与展开

开启「折叠相同行」后，两个差异之间超过 `上下文行数 × 2 + 1` 行的相同区会被压成一条 `⋯ 展开 N 行相同内容`。

1. 点折叠条 → 就地展开该区间的行。
2. 展开状态是临时的：任何一次重新对比（改内容、改忽略规则、改词级模式）都会重置全部折叠。切换布局、字号、换行、行号不会重置。

### 4.7 把差异搬到另一侧

1. 确认忽略规则是 `不忽略`。
2. 点某处差异的任意一行，让它出现蓝框（选中）。
3. 点 `← 采用右侧`：把右侧这块的行覆盖到左侧对应位置，或点 `采用左侧 →` 反向覆盖。
4. 纯新增块（左侧没有对应行）会**插入**到左侧上一处相同行之后；纯删除块同理插入到右侧。
5. 覆盖后自动重算，差异处数减少 1。

写入的是页面内文本框的内容，**不会写回你拖进来的本地文件**。要落地就复制该侧全文或下载 `.diff`。

### 4.8 复制与下载差异报告

`复制差异` 与 `下载 .diff` 输出同一份内容，不受渲染上限与折叠影响：

```
--- Original (before.md)
+++ Modified (after.md)
# 差异 5 处：新增 2 行，删除 0 行，修改 3 行，相同 12 行
@@ -1,15 +1,17 @@
-## 4.1 执行时机
+## 4.1 执行时机（一共有 7 种）
 
 | 输入框内容变化 | 400ms 防抖 | :1604 |
+| 勾选展开嵌套 | 立即 | :1672 |
```

- 前两行是标准 unified 头，括号里是载入过的文件名（没文件名就不带括号）。
- 第三行 `#` 是统计注释，`patch` / `git apply` 会忽略。
- hunk 的上下文行数跟随「上下文行数」设置；两个差异块之间的相同行不超过 `2 × 上下文 + 1` 行时，会合并进同一个 hunk。
- 修改行输出为「一行 `-` 紧跟一行 `+`」。
- 上下文行数改动后重新导出即可，无需重新对比。

| ---- | ---- | ---- |

## 6. 支持的输入 / 输出格式

**输入**

- 任意**纯文本**，不做语法解析。面板头的文件选择器预置扩展名：`.txt .md .json .js .ts .java .py .html .css .sql .xml .yaml .yml .csv .log .ini .conf .sh .properties .po .diff`（可多选其它类型，但输入框本身不限制）。
- 编码按 **UTF-8** 读取。GBK / GB2312 / UTF-16 文件会出现乱码，需先在别处转成 UTF-8。
- 换行 `\r\n` / `\r` / `\n` 全部归一为 `\n` 后比较。
- 无扩展名、无后缀的文件同样可读；含 `\u0000` 的内容判为二进制拒绝。

**输出**

| 出口 | 内容 |
| ---- | ---- |
| 复制差异 / 下载 `.diff` | unified diff 文本（见 4.8），UTF-8，无 BOM |
| 面板头 `⧉` | 该侧全文原样（保留原有换行风格） |

**明确不支持**

- 二进制文件、加密内容、单侧 > 2 MB 文本。
- 目录对比、三向合并（base / ours / theirs）、多于两份内容。
- 语法感知对比（JSON 键序不同但语义相同，会判为差异）。
- 直接写回本地文件。

## 7. 数据与隐私

- **零网络请求**：源码中没有 `fetch` / `XMLHttpRequest` / `<link>` 外链 / 外部字体，所有资源内联。
- **零持久化**：不写 `localStorage`、`sessionStorage`、`IndexedDB`、`cookie`，也不写文件。刷新或关闭页面内容即消失。
- 内容只存在于当前标签页的内存（两个 `<textarea>` 的 `value` 与内存中的行数组）。
- `file://` 双击直接可用，无需起本地服务。
- 剪贴板：在安全上下文（HTTPS / `localhost`）走 `navigator.clipboard`；`file://` 等非安全上下文自动回落到隐藏 `<textarea>` + `document.execCommand('copy')`，Chrome / Edge 下可用，失败会提示「复制失败，请手动选中」。
- 下载走 `Blob` + `URL.createObjectURL`，不经过任何服务器。

**注意**：差异报告会包含两份文本的变化行原文。把 `.diff` 发给别人前，确认里面没有密钥、口令、内网地址。

## 8. 常见问题（FAQ）

**Q：状态栏出现黄色「快速对齐（超出精确算法上限）」，结果还准吗？**
A：差异**位置**不会错，但**配对质量**下降。快速对齐按相同下标逐行比，不同就同时记一删一增，所以同一处改动可能被拆成上下两个块、`~修改` 数变成 0。触发黄色标记的只有两种情况：两侧总行数 > 20000；或编辑距离 > 1500（改动行数极多，如整个文件重写）。想恢复精确匹配：把无关段落先删掉只留关注区间，或按章节拆成几段分别对比。

另有一处**不会**亮黄灯的降级：单个连续增删块的「删除行数 × 新增行数 > 40000」时，`matchBlock` 放弃精确配对改为顺序一一配对，此时 `~修改` 仍可能有值但配对不一定符合直觉。

**Q：明明只差一个空格，为什么显示成一删一增两行而不是「修改」？**
A：「修改」需要新旧行足够相似（相似度 ≥ 0.5，按公共前缀 + 公共后缀占较长行长度的比例算）。差异太大时配对会误导，就按纯删除 + 纯新增显示。想让它们配对：切「忽略空白差异」，或接受当前显示。

**Q：中文内容点「高亮显示单词」，感觉整行都变色了？**
A：中文按**单字**切 token，一句话改了语序就会大面积标记，这是预期行为。想只看整行变化，选「关闭词级高亮」。

**Q：拖进去的文件是乱码。**
A：按 UTF-8 读的。GBK / GB2312 / UTF-16 需先转码（记事本「另存为」时选 UTF-8）。

**Q：两侧明明一样，相似度却不是 100%。**
A：看状态栏右侧有没有「行尾符混用」提示之外的隐藏差异：行尾空格、Tab 与空格混用、不可见字符。开「忽略空白差异」再试；若开「忽略空白差异」后差异归零，说明原文件缩进确实不同。

**Q：「采用右侧」按钮是灰的。**
A：三个条件缺一个就禁用：① 存在差异；② 已点选某处差异（有蓝框）；③ 忽略规则为 `不忽略`。见 4.2 末尾说明。

**Q：结果区显示「⋯ 结果过长，已省略 N 项」。**
A：单次最多渲染 3000 行。`复制差异` / `下载 .diff` 仍是完整的。想看全部，缩小对比范围或关掉折叠后分段查看。

**Q：改内容后没反应。**
A：输入后 300 ms 才重算（防抖）。按 `Ctrl+Enter` 立即重算。若勾了「只读」，文本框已锁定，改不了内容。

**Q：能对比两份很长的日志，只想知道多了哪几行吗？**
A：可以，但先把两份都截到同一段区间，否则容易触发快速对齐降级。

## 9. 技术实现要点（开发者）

### 9.1 数据流

```
textarea.value
  → prepare()      归一换行 / 拆行 / 按忽略规则生成 key
  → myersDiff()    key 序列的编辑脚本（eq / del / add）
  → 编号回填        按游标把 key 结果映射回原文与本侧行号
  → pairChanges()  连续 del/add 块做相似度配对 → mod 行
  → applyInline()  mod 行做 token 级 diff → ha / hb 高亮 HTML
  → visualLines()  按布局决定 mod 行是否拆成两行
  → buildDisplay() 折叠相同行，插入 gap
  → render()       生成 DOM（上限 RENDER_LIMIT）
```

### 9.2 关键常量（脚本顶部）

| 常量 | 值 | 含义 |
| ---- | ---- | ---- |
| `MAX_D` | `1500` | Myers 最大编辑距离，超出即降级 |
| `FALLBACK_LINES` | `20000` | 两侧总行数超过此值直接走快速对齐 |
| `RENDER_LIMIT` | `3000` | 单次渲染上限（行 / 折叠条合并计数） |
| `MAX_FILE` | `2 * 1024 * 1024` | 单文件载入上限 |
| `MATCH_THRESHOLD` | `0.5` | 判定「修改」所需的最低行相似度 |

Myers 的 V 数组偏移量 `off = MAX_D + 2`，数组长度 `2 * MAX_D + 5`，改 `MAX_D` 时这两处自动跟随。

### 9.3 关键函数

| 函数 | 位置职责 |
| ---- | ---- |
| `myersDiff(a, b)` | 主入口，先裁公共前缀 / 后缀，中段交给 `myersCore` |
| `myersCore(a, b)` | O(ND) 贪心 + 路径记录，失败置 `degraded` 并转 `fallbackAlign` |
| `backtrack(trace, a, b, dEnd, off)` | 从 trace 回溯出操作序列 |
| `fallbackAlign(a, b)` | O(N) 按下标逐行比，兜底 |
| `lineSim(a, b)` | `(公共前缀 + 公共后缀) / 较长行长度` |
| `matchBlock(dels, adds, th)` | Needleman-Wunsch 变体做保序配对，`m * n > 40000` 退化为顺序配对 |
| `tokenize` / `renderInline` | 词级 / 字符级高亮，输出 `<del>` / `<ins>` |
| `prepare(text)` | 生成 `{text, key, no}` 行对象，忽略规则全在这里 |
| `pairChanges(raw)` | 把 key 级操作序列转成带原文与双侧行号的显示行 |
| `visualLines(view)` | 三种布局的排版差异集中在这里，`mod` 行在非 split 布局拆成 `del` + `add`/`addB` |
| `buildDisplay(vl)` | 折叠逻辑，产出 `{kind:'row'|'gap'}` |
| `buildReport()` | unified 报告，先用 `keep` 数组按上下文行数标记要输出的行，再切成 hunk |
| `applyChange(toRight)` | 按选中差异块的行号区间对目标侧做 `splice` 替换 / 插入 |

### 9.4 用到的 Web API

`FileReader.readAsText`、`DataTransfer.files`（拖放）、`Blob` + `URL.createObjectURL`、`navigator.clipboard`（带 `execCommand` 回退）、`Element.scrollIntoView`、`performance.now`、`Int32Array` / `Float64Array` / `Uint8Array`。

**未使用**：`fetch`、`localStorage`、`IndexedDB`、`Web Worker`、`history` / hash 路由、任何外部库与字体。

### 9.5 行号语义

`an` 是原文（左侧）1-based 行号，`bn` 是修改文（右侧）1-based 行号。行号始终基于**原始文本**，与「忽略空行」等规则无关：忽略规则只在比较阶段剔除行，不会重编号，所以忽略空行后行号仍与编辑器对齐。末尾空行在拆行后统一丢弃，不计入行号。

## 10. 二次修改指引（开发者）

整个工具是一个 IIFE，无全局污染，可直接整文件复制改造。

**改配色 / 做浅色主题**
只改 `:root` 里的 CSS 变量：`--bg / --bg2 / --bg3 / --line / --fg / --fg-dim / --accent` 以及 `--add-bg / --add-bg2 / --add-mark / --del-bg / --del-bg2 / --del-mark`。行内高亮的 `<ins>` / `<del>` 底色在 `.tx ins` / `.tx del` 两条规则里，是写死的 `rgba`，需一并改。

**加一种忽略规则**
1. 在 `#ignoreSel` 加 `<option value="xxx">`。
2. 在 `prepare()` 的 key 生成分支里加对应处理。
3. 若该规则会让「相同」不再等价于原文相同，把它加进 `updateNav()` 里对采用按钮的禁用判断（当前只放行 `none`）。

**调差异配对的松紧**
改 `MATCH_THRESHOLD`：调低（如 `0.3`）更容易判成「修改」，配对更激进；调高（如 `0.8`）更多显示为一删一增。改 `matchBlock` 里的 `40000` 可放宽大块的精确配对上限，代价是 `m × n` 的 DP 变慢，谨慎上调。

**换差异算法**
`myersCore` 是唯一产生操作序列的地方，替换成其它算法（如 Histogram diff）只要保持返回 `{type:'eq'|'del'|'add', a?, b?}` 数组即可，上层 `pairChanges` 与所有视图无需改动。`degraded` 标志用于状态栏提示，降级路径请一并设置。

**改折叠策略**
`buildDisplay()` 里的判定是 `len <= ctx * 2 + 1` 就不折叠。想改成「按空行分段折叠」或「默认全展开」，只需改这一处；展开状态存在 `expanded` 对象，键由 `'g' + i + '_' + j` 生成，改折叠区间算法时注意键要保持稳定，否则一次渲染就会「自动展开」。

**加导出格式（如 HTML 报告 / side-by-side CSV）**
`buildReport()` 是唯一出口，`copyUniBtn` 与 `dlBtn` 共用它。新增格式建议加独立函数，导出扩展名在 `dlBtn` 的 `download('diff_' + Date.now() + '.diff', ...)` 处改。

**注意这几个坑**

- 三个视图共用一份 `rows`，`visualLines()` 会为 `unified` / `inline` 生成**新的行对象**（拆 `mod` 行），不要在这些对象上写回状态。
- `render()` 用 `innerHTML` 全量重建，任何在结果区上的临时 DOM 状态（选中框、闪烁动画、横向滚动位置）都会丢；持久状态必须存在 JS 变量里。
- 关闭「自动换行」后的左右滚动同步靠 `scroll` 捕获阶段代理，选择器写死了 `.tx` 与其父层级（`parentElement.parentElement`），改 DOM 结构时要同步。
- 词级高亮输出的是拼好的 HTML 字符串，原文已经过 `esc()`。若新增任何把原文拼进 HTML 的路径，必须同样过 `esc()`，否则会有 XSS 风险。
- 想在 `file://` 下测剪贴板，必须走 `execCommand` 分支：`window.isSecureContext` 为 `false`，这是预期路径而不是 bug。
