# 图片压缩台

> 源文件：[../图片压缩台.html](../图片压缩台.html)
> 页面标题：`图片压缩台 · Image Optimizer`
> 一句话定位：批量图片压缩与格式转换，可锁定输出体积上限，结果打成一个 ZIP 下载，全程不上传一个字节

## 1. 工具简介

发微信要压到 2 MB 以内、上传头像要求「不超过 100 KB」、给网站换张首图得转成 WebP——这类活计的通用做法是搜「在线图片压缩」，然后把一堆私人照片交给一个不知道会不会留存的服务器。

本工具把这些收进一个单 HTML 文件：**零网络请求**，图片只在浏览器内存里被解码、重绘、重编码，`file://` 双击即用。

四类能力：

| 类别 | 包含 | 说明 |
| --- | --- | --- |
| **压缩** | 质量重编码、限制尺寸 | 批量按统一参数重编码，逐行给出压缩率 |
| **转格式** | JPEG / PNG / WebP / 保持原格式 | 透明图自动判断，必要时用指定底色填充 |
| **定体积** | 目标体积 KB 上限 | 自动搜索质量；最低质量仍超标时按比例缩尺寸重试 |
| **打包** | ZIP 下载 | 结果打成一个 `.zip`，ZIP 用「存储」模式不二次压缩 |

**三个别处不容易一次做到的点**

- **目标体积是真去够，够不到会明说**。开启「目标体积」后，质量滑块被接管，工具用**已探测点插值引导**的方式反复编码，直到结果 ≤ 上限。若最低质量仍超标，会按超标比例缩小尺寸再试（最多 3 轮），最终仍不够时**输出当前能拿到的最小结果，并在「参数」视图与批次提示里写清「已缩到 W×H，仍超过目标 X KB」**——不静默给一个超标文件当成功。
- **大比例缩放不糊**。`drawScaled()` 采用**逐级减半降采样**：每次先缩到一半，反复到接近目标尺寸，最后一刀精修。一步把 4000 px 拉到 400 px 常见的锯齿与摩尔纹，这样做基本看不到。
- **ZIP 不重复压缩**。JPEG / WebP / PNG 本身已是压缩格式，再 deflate 一遍纯属浪费 CPU 且几乎不省体积。`buildZip()` 直接写 `method=0`（存储）模式，6 张约 630 KB 的结果打包耗时接近瞬时。

**适合谁用**

- 要一次压几十张图发给客户 / 传后台，参数统一、想看到每张省了多少
- 手上只有 PNG，页面需要 WebP 或带底色的 JPEG
- 上传接口写死「不超过 N KB」，需要精确压到线内
- 在意隐私，不接受把身份证 / 合同 / 家人照片传给陌生网站

**什么时候不该用它**

- **要保留 EXIF**：重编码后 EXIF 全部丢失（含 GPS、拍摄时间、相机参数）。方向已按 EXIF 自动转正，但其他元数据不保留。要留元数据请用 ImageMagick / exiftool。
- **要极致压缩率**：不做有损调色板量化（PNG8 / oxipng 级别）、不做抠图、不做 MozJPEG 级别的优化。本工具只做「重编码 + 缩放」，不改变像素内容。
- **PNG 想压小**：`canvas.toBlob` 对 `image/png` **忽略质量参数**，PNG 只能靠限制尺寸压。选 PNG 时质量滑块会自动禁用并提示。
- **HEIC / HEIF / 部分 AVIF**：能否解码完全看浏览器，解不开会在列表标「解不开」并给出原因，不会静默产出空图。
- **动图**：GIF 只取首帧，重编码后变成静态图。

## 2. 快速开始

1. **双击 `图片压缩台.html`**。单文件，无同级依赖。
2. 看标题栏右侧徽标，形如 `WebP 编码 可用 · ImageBitmap · 零上传`。**「WebP 编码 不可用」时选 WebP 会自动退回 JPEG**，并在结果说明里写明。
3. 拖图片进左半区（或点 **添加图片**，或 **Ctrl+V** 粘贴截图）。列表立刻出现，「原尺寸」列先是「读取中」，解码完成后补上真实尺寸。
4. 在选项条选输出格式（默认 **JPEG**）与质量（默认 **80**）。
5. 点 **开始处理**（或 **Ctrl+Enter**）。进度条走动，每张完成后「新大小」和「压缩率」列即时填充，右侧「对比」视图并排显示原图与结果。
6. 全绿之后点 **下载 ZIP** 一次性取走；只想拿当前这一张，按 **Ctrl+S**。
7. 输出文件名默认是 `原名-opt.jpg`，避免覆盖原图。想保持原名，勾选项条末尾的 **保持原文件名**。

## 4. 功能操作详解

### 4.1 批量压缩到统一质量

1. 拖入一批图片（单次列表上限 **200 张**，单文件上限 **50 MB**）。
2. 输出选 `JPEG`，拖动质量滑块。经验值：网页配图 78~85，邮件附件 65~75，纯存档 88~92。
3. **Ctrl+Enter** 开始。默认 **3 张并发**，逐张增量刷新，不必等全部完成。
4. 看表尾统计确认整体收益；某张反而变大（红字）时，单独删掉它不用即可。

### 4.2 压到指定体积（如「不超过 100 KB」）

1. 勾选 **目标体积**，填 `100`。质量滑块立即变灰。
2. 开始处理。工具自动搜索质量，命中后「说明」形如：
   `搜索 image/jpeg 质量 22 → 58 KB ≤ 目标 60 KB`
3. 若原图太大，质量压到底仍超标，工具会自动缩尺寸再试（最多 3 轮，尺寸下限为原图 6%，短边不低于 64 px）。最终仍不够时：
   `最低质量仍有 1.1 KB，已缩到 96×72，仍超过目标 1.0 KB`
   结果仍会产出，但**明确告知未达标**，需要人工放宽目标或另存小图。
4. 目标体积模式对 **PNG 无效**（PNG 无质量参数）。此时输出仍是 PNG，「说明」写 `PNG 无质量参数，目标体积未生效，结果 …`。要给 PNG 定体积，请改输出为 JPEG / WebP，或配合「限制尺寸」。

### 4.3 转成 WebP

1. 先看标题栏徽标是 `WebP 编码 可用`。
2. 输出选 `WebP`，正常设质量。
3. 若徽标为不可用，工具**不会报错**，而是自动按 JPEG 输出，并在「说明」写 `本浏览器不能编码 WebP，已退回 JPEG`，输出文件扩展名同步为 `.jpg`。

### 4.4 带透明通道的图转 JPEG

1. 输出选 `JPEG`，选项条出现 **透明底色** 选择器。
2. 是否需要填底色由 `hasAlpha()` **实际采样**决定（最多取 200×200 个像素，任一 alpha < 250 判为含透明），不是按文件扩展名或 MIME 猜。
3. 「参数」视图的 **含透明像素** 行显示判定结果；透明区域在结果里被填成所选底色。
4. 想保留透明，输出请选 `PNG` 或 `WebP`。

### 4.5 限制尺寸

1. 勾选 **限制尺寸**，填宽 / 高上限。
2. 按 `min(maxW/原宽, maxH/原高)` 等比缩放，**只缩不放**：原图本来就小于框，尺寸不变。
3. 缩放走逐级减半，2400×1600 → 640×427 这类大幅缩减边缘依然干净。
4. 限制尺寸与目标体积可同时开启：先按限制尺寸定基准尺寸，再在此基础上搜索质量 / 进一步缩小。

### 4.6 打包下载

1. 至少有一张已完成，**下载 ZIP** 点亮。
2. 点击后浏览器下载 `图片压缩结果-YYYYMMDD-HHMM.zip`。
3. 输出名重复时（例如两张同名图），ZIP 内自动改成 `xxx-opt(2).jpg`、`xxx-opt(3).jpg`，不会互相覆盖。
4. 只想取一张：选中该行按 **Ctrl+S**，直接下载该结果文件。

### 4.7 停止与重试

- 处理中点 **停止** 或按 **Esc**：当前这一张做完即停，已完成的结果保留。
- 失败项（如损坏文件）在列表标红「失败」，鼠标悬停显示原因；它们会被计入「待处理」，修正参数后可直接再次 **开始处理**。

## 6. 支持的输入 / 输出格式

### 6.1 输入

准入判定在 `acceptFile()`：MIME 以 `image/` 开头，或扩展名为 `svg`；空文件与超过 50 MB 的文件拒绝并说明原因。

| 格式 | 解码路径 | 说明 |
| --- | --- | --- |
| JPEG / PNG / WebP / BMP / GIF | `createImageBitmap`（无此能力时 `<img>`） | GIF 取首帧；EXIF 方向自动转正 |
| AVIF | 同上 | 取决于浏览器是否内置 AVIF 解码器 |
| SVG | **强制走 `<img>`** | `createImageBitmap` 对未显式声明宽高的 SVG 会失败 |
| HEIC / HEIF | 取决于浏览器 | 解不开时列表显示「解不开」，说明为 `浏览器无法解码该格式（HEIC / AVIF 等）` |

另有 **总像素上限 40,000,000**（4000 万像素）。超限直接报错并提示先缩尺寸——canvas 面积超浏览器硬上限时会画出全黑图，宁可提前拒绝。

### 6.2 输出

只有三种：`image/jpeg`（`.jpg`）、`image/webp`（`.webp`）、`image/png`（`.png`）。

选「**保持原格式**」时由 `resolveFmt()` 决定：

| 原始类型 | 输出 |
| --- | --- |
| PNG | PNG |
| WebP（且浏览器可编码 WebP） | WebP |
| JPEG | JPEG |
| 其他（GIF / BMP / SVG / AVIF…） | 含透明 → WebP（不可用则 PNG）；不含透明 → JPEG |

显式选 WebP 但浏览器不支持编码时，一律退回 **JPEG**。

### 6.3 明确不支持

- 输出 GIF / BMP / ICO / HEIC / SVG
- 保留 EXIF、ICC 色彩描述文件、多帧动画
- 抠图、裁剪、旋转、加水印、调色板量化

## 7. 数据与隐私

- **零网络请求**：全文无 `fetch` / `XMLHttpRequest` / 外部 `src`，无外部 CSS、JS、字体。
- **图片不落任何存储**：原图与结果只以 `Blob` + `Object URL` 形式存在于内存，关页面即消失。删除单行与「清空」都会显式 `revokeObjectURL`。
- **唯一持久化项**：选项条的参数，写入 `localStorage` 键 **`imgopt.prefs.v1`**，内容形如

  ```json
  {"fmt":"image/jpeg","quality":80,"resize":false,"maxW":1920,"maxH":1080,
   "target":false,"targetKB":200,"bg":"#ffffff","keepName":false}
  ```

  **不含任何图片数据或文件名**。清除方式：浏览器控制台执行 `localStorage.removeItem('imgopt.prefs.v1')`，或清除该站点数据。隐私模式下 `setItem` 失败会被静默忽略，功能不受影响。
- 剪贴板图片、复制文件名走 `navigator.clipboard`，不可用时回落 `document.execCommand('copy')`，`file://` 下仍可用。

## 8. 常见问题（FAQ）

**Q：明明选了 WebP，下载下来是 `.jpg`？**
A：本浏览器不能编码 WebP，工具自动退回 JPEG 并在「参数 → 说明」里写明。看标题栏徽标即可确认。想编 WebP，换 Chrome / Edge 较新版本。

**Q：选了 PNG 为什么质量滑块灰掉、目标体积也不生效？**
A：`canvas.toBlob` 对 `image/png` 忽略 quality 参数，这是平台限制。PNG 想压小只能靠「限制尺寸」，或改输出为 JPEG / WebP。

**Q：目标体积填了 1 KB，结果还是 1.1 KB？**
A：JPEG 编码有固有开销（表头 + 最小 MCU），极低分辨率下也压不进任意小的体积。工具已自动缩到 96×72 并把质量降到最低仍不够，会明确报告「仍超过目标」。把目标放宽到 3~5 KB 以上更容易命中。

**Q：结果比原图还大（压缩率红字）？**
A：正常。原图可能已经是高压缩率的低质量 JPEG，按质量 80 重编码只会变大。删掉这一行不用即可；或降低质量、开启限制尺寸。

**Q：目标体积模式怎么这么慢？**
A：慢在大图单次 JPEG 编码本身就要约 1 秒，目标体积需要多次试编码。1600×1200 实测：目标 60 KB 约 11 秒，目标 200 KB 约 10 秒，够不到的极端目标（1 KB）约 21 秒。想快就开「限制尺寸」先把尺寸压下来——搜索空间小了，每轮编码也快了。

**Q：照片的拍摄时间、GPS 没了？**
A：重编码必然丢 EXIF，这是当前版本的明确边界。方向已自动转正，但需要保留元数据请改用 ImageMagick / exiftool。

**Q：拖进来显示「解不开」？**
A：多为 HEIC / HEIF（iPhone 默认格式）或损坏文件。HEIC 请先在系统里转成 JPEG，或用截图（`Ctrl+V` 粘贴）的方式进来。

**Q：一次能处理多少？**
A：列表上限 200 张，单文件 50 MB，单张总像素 4000 万。默认 3 张并发。

**Q：处理到一半想改参数？**
A：先 **停止**，改完参数再 **开始处理**。注意：已完成的项目不会被重算，只有「待处理」和「失败」的会重跑。想全部按新参数重来，先把它们删掉重新添加。

## 9. 技术实现要点（开发者）

### 9.1 用到的 Web API

| API | 用途 | 缺失时 |
| --- | --- | --- |
| `canvas.toBlob(mime, quality)` | 唯一编码出口（`encodeCanvas`） | 返回 `null` 时抛「浏览器拒绝了这次编码」 |
| `canvas.toDataURL('image/webp')` | 探测 WebP 编码能力 | 判为不可用，选 WebP 自动退 JPEG |
| `createImageBitmap(blob, {imageOrientation:'from-image'})` | 首选解码 + EXIF 转正 | 回落 `<img>` + Object URL |
| `Image` + `URL.createObjectURL` | SVG 解码、`createImageBitmap` 不可用时的解码 | — |
| `getImageData`（`{willReadFrequently:true}`） | `hasAlpha()` 采样透明像素 | 读取失败时按「含透明」保守处理 |
| `FileReader` | 未使用（直接 `blob.arrayBuffer()`） | — |
| `localStorage` | 参数持久化 | 隐私模式下静默忽略 |

### 9.3 目标体积搜索（`processItem` 内 `tryScale`）

不是纯二分。体积对质量近似单调，因此维护一个**已探测点集合** `pts = [{q, size}]`：

1. `nextQ()` 在所有「一个点 ≤ 上限、另一个点 > 上限」的组合里，挑区间跨度最小的一对做**线性插值**，落点夹在 `[lo, hi]` 内；没有可用区间时退回中点。
2. 每轮编码后更新 `lo` / `hi`；命中且富余 ≤ `max(上限×3%, 1024 B)` 立即返回，不再多编码一次。
3. 首轮最多 `TARGET_TRIES = 5` 次编码，缩尺寸后的轮次只允许 3 次。
4. 一轮结束仍未命中：取本轮**最小编积** `minProbe`，按 `scale × (limit/size)^0.75 × 0.95` 缩小基准尺寸（JPEG 体积近似正比于像素数，0.75 次幂比 `sqrt` 收敛更快又不易缩过头），最多 `TARGET_SHRINK_ROUNDS = 3` 轮。
5. 兜底停止条件：`scale ≤ 0.06`、缩后短边 < 64 px，或轮数用尽。

改成纯二分实测 1600×1200 压到 60 KB 需 14.3 秒，插值引导后 11.0 秒；极端目标从 70.3 秒降到 21.3 秒。

### 9.4 并发与资源释放

`runBatch()` 起 `min(CONCURRENCY, queue.length)` 个 worker，各自从共享下标 `idx` 取任务，形成简单的工作窃取队列。`abort` 标志在每个 `await` 点检查，因此停止粒度是「当前这一张做完」。

`processItem` 把解码结果挂在 `it._img`，无论成功（`.then`）还是失败（`.catch`）都调用 `releaseImg()`：`ImageBitmap.close()` 释放解码位图，`URL.revokeObjectURL()` 释放 SVG / `<img>` 路径的 Object URL。**漏掉这一步，几十张大图会把内存吃满。**

### 9.5 ZIP 结构

手写而非引入 JSZip。每条目：

- 本地文件头 30 字节：签名 `0x04034b50`、版本 20、通用位 `0x0800`（文件名为 UTF-8）、**压缩方式 0（存储）**、DOS 时间日期、CRC-32、压缩后 = 原始大小。
- 中央目录项 46 字节：同上再加注释长度 / 磁盘号 / 外部属性 / 本地头偏移。
- 末尾 EOCD 22 字节：条目数、中央目录大小与偏移。

因为 `method=0`，「压缩后大小」直接等于原始字节数，CRC 一次遍历即可，无需 deflate 实现。实测 6 条目 ZIP 解析回来逐条比对 CRC 与大小全部一致。

## 10. 二次修改指引（开发者）

### 10.1 加输出格式

1. 在选项条 `<select id="optFmt">` 加 `<option value="image/avif">`。
2. 在 `FMT_EXT` 加扩展名映射（`'image/avif': 'avif'`）。
3. 在 `detectEncodeCap()` 里照 WebP 的写法加一项能力探测，并让 `resolveFmt()` 处理不可用时的回退。
4. 若该格式无质量参数，记得在 `syncOpts()` 里像 PNG 一样禁用滑块并给出提示。

### 10.2 调压缩策略

- 想更省编码次数：调小 `TARGET_TRIES`（当前 5）或放大 `TARGET_SLACK`（当前 0.03，即允许结果比目标小 3% 以内就收手）。代价是命中率与体积精度下降。
- 想更容易够到极小目标：调大 `TARGET_SHRINK_ROUNDS`（当前 3）或放宽 `shrinkOrGiveUp()` 里的 `scale <= 0.06` 与 `< 64` 下限。
- 缩放质量不满意：`drawScaled()` 里的减半条件是 `cw/2 > tw && ch/2 > th`，改成 `>=` 会多减一级。

### 10.3 改命名与打包

- 输出名规则集中在 `outNameFor()` 一处，改后缀、加日期、加尺寸都在这里。`safeName()` 决定非法字符与 120 字符截断。
- ZIP 若要真正压缩，需把 `method` 从 0 改为 8 并自行实现 deflate——浏览器没有同步 deflate API，只能走 `CompressionStream('deflate-raw')`（异步且需拼装 raw 流），成本远高于收益。图片场景不建议做。
- ZIP 文件名去重在 `downloadZip()` 的 `used` 字典里，改成子目录结构需同步修改中央目录项的文件名字段。

### 10.4 注意事项

- 保持 **零依赖零网络**。不要引入 CDN 上的 `jszip`、`browser-image-compression`——本工具的价值就在离线可用与可审计。
- **不要绕过 `releaseImg()`**。`ImageBitmap` 不 `close()` 会持续占解码内存，批量场景几百 MB 就没了。
- **不要用 MIME 代替 `hasAlpha()` 判断透明**。`image/png` 未必透明，`image/webp` 未必透明，判错会让 JPEG 出现黑底或给不透明图白留通道。
- 改并发数 `CONCURRENCY` 要谨慎：`toBlob` 在多数浏览器里部分跑在共享线程上，超过 3~4 反而变慢，且目标体积模式下并发数直接决定「同时有多少张在做多轮试编码」，内存与卡顿都会上升。
- 任何「压不进去」的情况必须保留**明确报告**的行为。静默输出一个超标文件，比报错更糟。
