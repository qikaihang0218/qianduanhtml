## 1. 工具简介

日常开发里有一类活计，说不上难，但每次都要临时搜「在线 base64 解码」，然后忍受三层广告和一个不知道会不会把你粘贴内容上传的后台：

- 把一段 token 拆开看 `exp` 到没到期
- 收到一串 `c4e3bac3a1a2`，不知道它是 GBK 还是 Big5
- 算个 MD5 校验下载文件，本机却没装任何工具
- HMAC 签名对不上，要逐段确认是密钥错还是内容被改

本工具把这些收进一个单 HTML 文件，**零网络请求**，粘贴进去的内容只待在浏览器内存里。

四类模式：

| 类别 | 包含 | 说明 |
| --- | --- | --- |
| **编码** | Base64、Base64URL、URL、Hex、`\uXXXX`、HTML 实体、字节解码 | 前 6 种支持编码 / 解码双向切换 |
| **摘要** | 哈希、HMAC | MD5 为页面内置实现，SHA 系列走 Web Crypto |
| **JWT** | JWT 解析 | 拆 header / payload，人性化时间字段，HMAC 本地验签 |
| **随机** | 随机串 | `crypto.getRandomValues` 密码 / Token、UUID v4 |

**三个别的在线工具做不到的点**

- **「字节解码」模式**：同一份字节，同时用 UTF-8 / GB18030 / GBK / Big5 / Shift_JIS / EUC-KR / UTF-16LE / UTF-16BE / Windows-1252 / ISO-8859-1 解出来并排放在一起，按「U+FFFD 数 × 4 + 控制符数」打分排序，最优的一行标「推荐」。看到乱码不用一个个编码去试。
- **解码宽容但不装懂**。Base64 自动容忍空白、缺失的 `=`、Base64URL 字母表；Hex 自动吃掉空格 / `:` / `-` / 逗号 / `0x` 前缀；URL 遇到非法百分号转义会逐段尽力解，解不了的原样保留。所有被忽略、被丢弃、被替换的部分**都会在结果区上方明确写出数量与具体字符**，不静默吞掉。
- **JWT 验签是重算而不是比对缓存**。填了密钥就用 `crypto.subtle` 重新算一遍 HMAC，和 token 第三段做**定长逐字符比较**（不用 `===`，避免时序侧信道）。密钥错、内容被改、`alg=none` 三种情况分别给出不同结论。

**适合谁用**

- 联调时看接口返回的 token 还差多久过期、payload 里到底塞了什么
- 处理老系统导出的乱码文本，需要快速判断原始编码
- 对接需要 MD5 / HMAC 签名的开放平台，本地反复验算
- 生成随机密码或 UUID，不想让第三方网站过一遍

**什么时候不该用它**

- **需要「文本 → GBK 字节」**：浏览器 `TextEncoder` 只实现 UTF-8，GBK / Big5 等只能**解码不能编码**。这是平台限制，不是工具偷懒，方向选错时结果区会提示改用「字节解码」。
- **需要验 RS256 / ES256 等非对称 JWT**：这类算法要导入公钥，本工具只解析 header / payload 并明确标注「未验签」，不会给一个假的「通过」。
- **需要工业级 HTML 实体全表**：内置 56 个常用命名实体，未收录的 `&xxx;` 原样保留不猜。要全表请用浏览器 DOM 的 `textarea.innerHTML` 技巧或专业库。
- **拿 MD5 / SHA-1 做安全用途**：两者已被证实碰撞可构造，本工具提供它们只为对接存量系统，新设计的完整性校验请直接用 SHA-256 及以上。

## 2. 快速开始

1. **双击 `编码转换台.html`**。单文件，无同级依赖，`file://` 直接可用（`file://` 下浏览器仍视为安全上下文，`crypto.subtle` 正常可用）。
2. 首次打开是空的。点工具栏 **「示例」**，会按当前模式填入一条针对性样例——JWT 模式自动填好示例密钥 `your-256-bit-secret`（结论「签名校验通过」），HMAC 模式自动填好 RFC 4231 Test Case 1 的密钥与算法（结论可与官方给出的一串直接对照）。
3. 编码类模式默认是**编码方向**（文本 → 编码文本），点 **「→ 编码」** 按钮切到 **「← 解码」**，或直接按**空格**。
4. 结果区上方若出现黄色提示条，说明解码过程中有内容被忽略 / 丢弃 / 替换，**先看提示再决定要不要用这个结果**。
5. 右侧 **「附加信息」** 标签存放结构化数据：Base64 / Hex 解码给出字节数与 U+FFFD 计数，摘要模式列出各算法结果表格，JWT 逐字段列出 header / payload 与验签结论，字节解码列出各编码的评分明细。
6. 想验证自己算得对不对：点 **「结果 → 输入」**，把当前结果原样填回输入框，配合方向切换做一次往返自检。

## 3. 界面与功能分区

页面自上而下：标题栏、工具栏、选项条、（可选）错误条、左右双栏主体、状态栏。

### 3.1 标题栏

- 左侧标题与副标题，列出全部能力关键词。
- 右侧 **「能力检测」** 徽标实时显示三项：`WebCrypto 可用/不可用`、`GBK 解码 可用/不可用`、`MD5 内置`。这三项决定 SHA / HMAC / JWT 验签、GBK 系解码是否可用；MD5 不依赖 Web Crypto，任何环境都能算。

### 3.2 工具栏

| 控件 | 作用 |
| --- | --- |
| 编码 / 摘要 / JWT / 随机 | 四个大类，切换后第二行按钮随之变化 |
| 第二行动态按钮 | 当前大类下的具体模式，共 11 个 |
| `→ 编码` / `← 解码` | 仅编码类的 6 个双向模式显示，摘要 / JWT / 随机模式隐藏 |
| 结果 → 输入 | 把结果框内容填回输入框并重算，仅双向模式显示 |
| 示例 | 载入当前模式样例；随机模式下等价于「重新生成」 |
| 复制 / 下载 | 复制结果 / 下载为 txt（文件名含模式与时间戳，带 UTF-8 BOM） |
| 帮助 | 弹出使用说明、快捷键与能力边界 |

### 3.3 选项条

随模式变化，只显示当前模式相关的选项组。完整清单见第 6 章。

### 3.4 错误条

红色横条，只在**当前输入完全无法处理**时出现，例如 Hex 去掉分隔符后是奇数个字符、JWT 段数不对、`TextDecoder` 构造失败。有错误条时结果区清空。

与黄色提示条的区别：**红条 = 没结果，黄条 = 有结果但有损**。

### 3.5 左栏：输入

- 底部实时显示 `N 字符`；编码 / 摘要类同时显示 UTF-8 字节数。
- 可把 `.txt` 文件直接拖到页面任意位置载入（上限 4 MB，检测到 `\u0000` 判定为二进制并拒绝）。
- 随机模式下输入框禁用，改显示一行说明——该模式不读输入。

### 3.6 右栏：结果 / 附加信息

- **结果**：只读文本域，可选中复制。超过 30 万字符只渲染前 30 万，但黄条会说明「复制与下载仍是完整内容」。
- **附加信息**：三种表格形态——键值对（Base64 / Hex 解码统计、JWT 字段、随机参数）、摘要表（算法 / 值 / 长度）、编码评分表（编码 / U+FFFD / 控制符 / 可打印 / 前 120 字预览，最优行绿底标「推荐」）。

### 3.7 状态栏

左侧是当前模式名与方向；右侧是本次计算的核心指标，例如：

- `12 字节 → 最佳候选 GB18030`
- `HS256 · 签名校验通过`（通过为绿色，失败为红色）
- `SHA-256 · 输入 10 字节`
- `5 条 × 20 字符 · 字符池 62 个`

## 4. 功能操作详解

### 4.1 Base64 / Base64URL

**编码方向**可选：

- `每 76 字符换行`（Base64）：按 MIME 规范插入 `\r\n`，用于邮件头、PEM 之类场景。
- `填充：去掉 = / 补齐 =`（Base64URL）：默认去掉，符合 JWT / cookie 惯例。

**解码方向**不需要任何设置，自动处理：空白与换行、缺失或多余的 `=`、Base64URL 的 `-` `_`、以及混入的非法字符。

解码结果按 UTF-8 解释。若原文其实是 GBK 等编码，会出现 U+FFFD，此时提示条会引导你改用「字节解码」模式。

**长度不合规怎么办**：Base64 每 4 字符对应 3 字节。`5L2g5aW` 这类末尾余 3 个 6 位组（18 位）不足一字节，工具会取满字节、丢弃残余，并提示「末尾 3 个 6 位组不足一字节，已丢弃」——这是 RFC 4648 的标准行为，不是错误。

### 4.2 URL 百分号编码

编码提供三种口径：

| 方式 | 保留字符 | 用途 |
| --- | --- | --- |
| `encodeURIComponent`（默认） | `A-Za-z0-9 - _ . ! ~ * ' ( )` | 编码查询参数的**值** |
| `encodeURI` | 额外保留 `; , / ? : @ & = + $ #` | 编码**完整 URL**，不破坏结构 |
| 全部字节 | 仅 `A-Za-z0-9 - _ . ~` | 严格 RFC 3986，做安全过滤时用 |

解码方向的 `解码时把 + 当空格` 对应 `application/x-www-form-urlencoded` 语义（`+` 表示空格）；纯 URI 场景不要勾，否则 `a+b` 会被错解成 `a b`。

**遇到非法转义**：`%E4%B8%AD%ZZ%20x` 中 `%ZZ` 不合法，工具不会整条失败，而是按连续的 `%XX` 分段解码，能解的解、不能解的原样保留，并提示「N 个残缺的 % 原样保留」。

### 4.3 Hex

编码可选分隔符（无 / 空格 / 冒号 / 短横线 / 换行）与大小写。

解码自动忽略空格、`:`、`-`、`,`、`;` 以及 `0x` / `0X` 前缀，因此 `0x48 0x69, E4B8AD` 这种混合写法可以直接粘。

若清理后是奇数个字符，直接报错而不是猜最后半个字节——这是唯一会因长度失败的情况。

### 4.4 `\uXXXX` 转义

编码范围：

- `仅非 ASCII`（默认）：可打印 ASCII 原样保留，可读性最好。
- `所有字符`：连 `a` 也转成 `\x61`，用于生成必须纯 ASCII 的源码 / 配置文件。

转义规则：`< 0x100` 用 `\xHH`，BMP 内用 `\uXXXX`，**BMP 外（emoji 等）用 `\u{1F600}`**。后者是 ES6 语法，`JSON.parse` 与多数语言的解析器不认识，工具会专门提示。反斜杠本身固定输出 `\x5c`，避免二次转义歧义。

解码支持 `\uXXXX`、`\u{XXXXX}`、`\xHH`，以及 `\n` `\r` `\t`；无法识别的序列原样保留并计数。

### 4.5 HTML 实体

编码范围：

- `& < > " '`（默认）：只做 XSS 基本防护需要的 5 个字符。
- 上述 + 非 ASCII：非 ASCII 转成十六进制数字实体 `&#x4E2D;`，用于生成纯 ASCII 的 HTML。

解码支持十进制 `&#20013;`、十六进制 `&#x4E2D;`，以及内置 56 个命名实体（`&amp;` `&nbsp;` `&mdash;` `&hellip;` `&alpha;` 等）。

两条边界行为：

- 码点落在**代理区 `D800–DFFF`** 的数字实体，按 HTML 规范替换为 U+FFFD 并提示数量（这类实体本身是错误产物）。
- 超出 `U+10FFFF` 的原样保留。

### 4.6 字节解码（乱码定位）

这是最实用的一个模式。输入一串字节（Hex 或 Base64），工具用 10 种编码各解一遍，右侧表格并排给出：

| 列 | 含义 |
| --- | --- |
| U+FFFD | 解码失败被替换的字符数，**越低越可能是正确编码** |
| 控制符 | 解出的不可打印字符数（Tab / LF / CR 不计） |
| 可打印 | 正常字符数 |
| 解码结果 | 前 120 字预览，换行制表符显示为 `·` |

排序分数 = `U+FFFD × 4 + 控制符数`，最低分的行绿底标 **「推荐」**，状态栏同步给出 `12 字节 → 最佳候选 GB18030`。

输入格式默认**自动识别**：清理后若全为十六进制字符且长度为偶数，按 Hex；否则按 Base64。识别结果会在提示条说明。

> 注意：评分只是启发式。像 GBK 这类双字节编码解英文文本时 U+FFFD 也是 0，需要**结合预览人工确认**。表格的作用是给你 10 个候选并排序，不是替你下结论。

### 4.7 哈希

| 选项 | 取值 |
| --- | --- |
| 算法 | MD5（内置实现）、SHA-1、SHA-256、SHA-384、SHA-512 |
| 输出 | 十六进制小写 / Base64 / Base64URL |
| 字节来源 | 输入按 UTF-8 文本（默认）/ 按 Hex 字节 / 按 Base64 字节 |
| 一次列出全部算法 | 勾选后忽略算法下拉，5 个算法竖排列出 |

**「字节来源」是算文件哈希的关键**。要校验一个二进制文件的哈希，得先把文件转成 Base64（可用本工具 Base64 模式，或 `certutil -encode`），再把来源切到「按 Base64 字节」——直接粘二进制原文是不行的。

**空输入是有结果的**。摘要模式是唯一允许输入为空的模式，`MD5("")= d41d8cd98f00b204e9800998ecf8427e`。其他模式空输入直接显示「等待输入」。

**MD5 为什么是自己写的**：`crypto.subtle` 明确不支持 MD5（`NotSupportedError`）。页面内置一份纯 JS MD5（RFC 1321），已用 .NET `System.Security.Cryptography.MD5` 逐向量核对一致，包括空串、中文、56 字节长边界向量。

### 4.8 HMAC

需要密钥，密钥输入框支持三种自身编码：`UTF-8` / `Hex` / `Base64`——很多 SDK 给的密钥是 Base64 串，选错编码会算出完全不同的结果，这是对接签名问题最常见的原因。

已用 RFC 4231 Test Case 1 核对：key = `0b×20`、data = `Hi There` → HMAC-SHA256 = `b0344c61d8db38535ca8afceaf0bf12b881dc200c9833da726e9376c2e32cff7`。点 **「示例」** 会自动填入这组密钥、密钥编码 `Hex` 与算法 `SHA-256`，结果应与上面这串完全一致——可用来确认工具与你的环境没问题。

依赖 Web Crypto，非安全上下文下会明确报错而不是静默失败。

### 4.9 JWT 解析

粘贴时 `Bearer ` 前缀、内部换行与空格都会被清掉，段数不是 2 或 3 直接报错。

结果框是格式化后的 `{ header, payload }`；附加信息表逐字段列出，并对三个时间claim做人性化处理：

- `exp` → `1516239022 2018/1/18 09:30:22 · 已过期 3228.3 天`
- `nbf` → 未生效时显示剩余时长
- `iat` → 显示距今多久

`exp` 已过期时该行标红。

**验签规则**（填了密钥才执行）：

| `alg` | 行为 |
| --- | --- |
| `HS256` / `HS384` / `HS512` | 用密钥重算 HMAC，与第三段定长比较，给出「通过 / 不通过」 |
| `none` 或缺失 | 直接判定「无签名保护，任何内容都可伪造」 |
| `RS*` / `PS*` / `ES*` | 只解析，明确标注「属于非对称算法，需要导入公钥，本工具只解析不验签」 |
| 无签名段 | 标注「token 没有签名段，无法验签」 |

示例 token 的签名由独立工具（.NET `HMACSHA256`）生成，页面验签结论为「通过」，可用来确认工具本身没算错。

### 4.10 随机串

- 长度 4–128，条数 1–200。
- 字符池可选 `a-z` `A-Z` `0-9` 符号；勾选「排除易混淆」剔除 `iIlLoO01`。
- 勾选了数字 / 大写 / 小写时，会**强制**在随机位置放入对应一类字符，保证生成的密码不会碰巧不含数字。
- 取值用**拒绝采样**：`Math.floor(256 / n) * n` 以上的随机数丢弃重取，避免 `randomBytes % poolLength` 的取模偏置。这是安全随机与非安全随机的实际分界，不是形式主义。
- 输出格式：每行一个 / JSON 数组 / JS 字符串字面量。
- **UUID v4** 按钮优先用 `crypto.randomUUID()`，不支持时退回 `getRandomValues` 手工置 version / variant 位。

## 6. 支持的输入 / 输出格式

### 6.1 输入

- 文本框粘贴，或拖入 `.txt` 文件（UTF-8 读取，含 `\u0000` 视为二进制拒绝）。
- 编码类：任意文本。解码方向容忍格式混杂（空白、多余填充、非法字符），但会如实报告损失。
- 摘要类：文本，或按 Hex / Base64 表达的字节。
- JWT：三段式 token，可带 `Bearer ` 前缀。
- 随机：不读输入。

### 6.2 内置上限（源码常量）

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `TEXT_LIMIT` | 200 000 字符 | 输入字符上限，超出直接报错 |
| `BYTES_MAX` | 4 MB | 字节类解码 / 摘要的字节上限 |
| `OUT_LIMIT` | 300 000 字符 | 结果区**显示**上限，复制与下载不受限 |
| `FILE_MAX` | 4 MB | 拖入文件大小上限 |
| `TEXT_SAVE_MAX` | 50 000 字符 | 超过此长度的输入**不写入** localStorage |

### 6.3 输出

- 结果框：纯文本。
- 下载：`{模式名}_{YYYYMMDD-HHmmss}.txt`，带 UTF-8 BOM，Windows 记事本直接打开不乱码。
- 附加信息：结构化表格，仅屏显，不可下载。

### 6.4 持久化内容

存储键 `codeclab.prefs.v1`，写入内容有：当前大类 / 模式 / 方向 / 标签页、全部选项值（**含 HMAC 与 JWT 密钥**）、以及不超过 5 万字符的输入文本。输入超过 5 万字符时只存选项不存正文。

## 7. 数据与隐私

- **零网络请求**。全文无 `fetch` / `XMLHttpRequest` / 外部 `<script>` / `<link>` / 字体 / 图片引用，源码中唯一出现的 `https://` 是 URL 模式的示例文本字符串。
- 所有内容在浏览器内存中处理，关闭页面即消失。
- 唯一持久化是 `localStorage` 的 `codeclab.prefs.v1`，只写在本机当前浏览器 profile 内。清除浏览器站点数据即可彻底抹掉。
- **风险提示**：HMAC 密钥与 JWT 密钥会以明文存在 localStorage 里，方便下次打开继续用。公共电脑上请清空浏览器数据，或用完立刻删掉输入。要绝对不留痕，可先手动清一次 `localStorage.removeItem('codeclab.prefs.v1')`。
- 处理真实生产密钥、含个人信息的 token 前，请确认这符合你所在组织的数据处理规范——本工具不联网，但浏览器进程、剪贴板历史、截屏等仍在你本机正常运作。

## 8. 常见问题（FAQ）

**Q：Base64 解出来一堆 `?`，是工具错了吗？**
不是。原字节多半不是 UTF-8。切到「字节解码」模式，把格式设为 Base64，看表格里哪个编码 U+FFFD 为 0。

**Q：为什么没有「文本 → GBK」？**
浏览器只提供 UTF-8 的 `TextEncoder`，GBK / Big5 / Shift_JIS 等只能解码（`TextDecoder` 支持）不能编码。要生成 GBK 字节请用 PowerShell、Python 或 `iconv`。

**Q：`0x48 0x69` 能解，`486` 为什么报错？**
Hex 必须两两成字节。`486` 清理后 3 个字符，工具拒绝猜最后半个字节。

**Q：JWT 明明密钥对了，却说「不通过」？**
按概率排序检查三件事：① 密钥自身编码选错（`utf8` / `hex` / `base64` 三种下拉）；② token 中间被换行截断过（工具会清空白，但复制时若漏了字符就无解）；③ 服务端用的是 RS256，本工具不验非对称签名。

**Q：`alg: none` 的 token 能用吗？**
不能当身份凭证。工具会直接告诉你「无签名保护，任何内容都可伪造」。

**Q：MD5 准不准？**
已与 .NET 的 `MD5` 实现逐向量核对（空串、`a`、`abc`、`message`、`Hello, world`、56 字节长句、中文）。但 MD5 抗碰撞性已被攻破，只适合做**非安全用途的指纹**或对接老系统。

**Q：SHA-1 呢？**
SHA-1 碰撞（SHAttered）也已公开。同样只用于对接存量系统。

**Q：结果框和「复制」的内容不一样？**
结果超过 30 万字符时框内只显示前 30 万，黄条会写明总长度；复制与下载拿到的始终是完整结果。

**Q：`file://` 下 SHA / HMAC 会不会不可用？**
Chrome / Edge 把 `file://` 视为安全上下文，`crypto.subtle` 可用，标题栏徽标会实时确认。若某浏览器判定为不可用，SHA / HMAC / JWT 验签会明确报错，MD5 与全部编码功能不受影响。

**Q：随机密码够安全吗？**
取值来自 `crypto.getRandomValues`（CSPRNG），并用拒绝采样消除取模偏置，可用于一般密码场景。20 位混合大小写数字约 118 bit 熵；要更高请加长长度而不是勾更多符号。

## 9. 技术实现要点（开发者）

### 9.1 统一的字节层

所有模式共用一套自写的字节工具，不依赖 `btoa` / `atob`：

- `bytesToB64` / `b64ToBytes`：手写查表，同时支持标准与 URL 安全字母表；解码时逐字符判定，能精确统计被忽略的字符集合。
- `bytesToHex` / `hexToBytes`：解码前先 `replace(/0[xX]/g,'')` 再去分隔符，因此 `0x` 前缀与分隔符可任意混用。
- `srcBytes(src, fmt)`：把「文本 / Hex / Base64 → 字节」的三种来源收敛成一个入口，摘要与 HMAC 共用。

不用 `atob` 的原因是它对非法字符抛异常且无法告知错在哪，而本工具的核心要求是「宽容但如实报告」。

### 9.2 MD5 实现要点

`md5Bytes` 按 RFC 1321：

- 填充长度用 `DataView.setUint32` 分低 / 高 32 位写小端，`Math.floor(len / 536870912)` 取高位，避免 JS 位运算在 >2 GB 时的溢出。
- `MD5_K` 由 `Math.floor(Math.abs(Math.sin(i+1)) * 2^32)` 预生成一次并缓存为 `Int32Array`，不在每次调用里重算。
- 输出按小端逐字节转 hex，与参考实现一致。

### 9.3 info 结构统一

`renderInfo` 只认一种形状：`{ kind: 'kv' | 'digest' | 'sniff', rows: [...] }`。

- `kv`：字段 / 值两列（Base64 / Hex 解码统计、JWT 字段、随机参数）
- `digest`：项 / 值 / 长度三列（哈希、HMAC）
- `sniff`：编码评分五列表（字节解码），按 `score` 排序、`pick` 行加推荐标记

历史上这里传过裸数组和数组套数组，导致渲染分支取 `undefined.replace` 报错。新增模式时务必返回带 `kind` 与 `rows` 的对象。

### 9.4 异步与竞态

摘要 / HMAC / JWT 验签走 Web Crypto，是 Promise。`recompute()` 用自增的 `seq` 做竞态守卫：只有 `my === seq` 的结果才允许落地，避免用户连续改动时旧结果覆盖新结果。同步模式直接返回对象，`recompute` 用 `typeof res.then === 'function'` 区分两条路径。

### 9.5 转义与 XSS

所有写入 DOM 的动态内容（结果、错误条、表格单元格、实体预览）统一过 `esc()`，包括错误消息里回显的用户输入。JWT 的 payload 值可能含 `<`，表格预览可能含任意字节，不做转义会被当标签解析。

### 9.6 定长比较

`constantTimeEq` 用 `diff |= a.charCodeAt(i) ^ b.charCodeAt(i)` 遍历完再判 `diff === 0`，不用 `===` 短路。对本地工具的 JWT 验签而言这更多是习惯养成——真正的时序风险在服务器端，但既然写了验签就按正确姿势写。

### 9.7 时间字段人性化

`humanSpan(sec)` 按 秒 / 分钟 / 小时 / 天 四档给中文描述，配合 `toLocaleString()` 输出本地时区的绝对时间。跨天以上只保留一位小数，不假装精确。

## 10. 二次修改指引（开发者）

### 10.1 加一个新编码模式

1. 在 `MODES` 数组加一项 `{ id, cat, name }`。若要双向，把 id 加进 `DIR_MODES`。
2. 在 `SAMPLES` 加示例文本（随机类留空）。
3. 写 `runXxx(src, enc)`，返回 `{ out, notes, meta, info }`：
   - `notes` 是黄色提示条的数组，**任何有损处理都必须写进来**
   - `meta` 是状态栏右侧的一句话
   - `info` 用 `{ kind, rows }` 结构，不需要就 `null`
4. 在 `dispatch()` 的 `switch` 里接上。
5. 有选项的话，在选项条加 `<div class="grp" data-modes="xxx">`，并把控件 id 加进 `OPT_IDS`——加进去就自动获得持久化，不用写额外代码。

### 10.2 给字节解码加编码

往 `SNIFF_LABELS` 追加 label，并在 `SNIFF_NAMES` 加显示名。`TextDecoder` 构造失败（`TypeError`）会被捕获成「浏览器不支持该编码」一行灰字，不会中断整个表格。

### 10.3 加新摘要算法

`runHash` 里的 `optAlg` / `optAll` 列表加一项即可。若 `crypto.subtle` 不支持（如 SHA3 在部分浏览器），`subtleDigest` 的 reject 分支会把错误变成表格里的一行文字，不会让整个页面挂掉。

### 10.4 注意事项

- 保持**零依赖零网络**。不要引入 CDN 上的 `crypto-js`、`js-base64`，本工具的价值就在于离线可用与可审计。
- 新增命名实体直接往 `NAMED_ENT` 加；帮助弹层里的「56 个」是硬编码文案，记得同步。
- `OUT_LIMIT` 调大要谨慎：结果框是 `<textarea>`，百万级字符会明显掉帧。真要处理大文本，应该做分页而不是抬高上限。
- 修改任何解码容错逻辑时，**保持「有损必报」原则**：静默修正错误输入是这类工具最容易毁掉信任的地方。
