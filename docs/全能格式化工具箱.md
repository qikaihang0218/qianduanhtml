# 全能格式化工具箱 · 操作文档

> 源文件：[../全能格式化工具箱.html](../全能格式化工具箱.html)
> 页面标题：`🧰 全能格式化工具箱 · 嵌套 JSON 增强版`
> 一句话定位：**8 个格式化工具共用一套「粘贴 → 自动美化 → 复制/下载」流程**，核心卖点是能把字段里塞着的 JSON 字符串递归展开成真正的嵌套结构，全程离线、零存储。
>
> 本文所有键位、取值范围、格式清单与存储结论均基于当前仓库源码核对。

## 1. 工具简介

顶栏下面一排 8 个模式按钮：**JSON / XML / HTML / CSS / SQL / URL / Base64 / 日志**。左边输入框粘贴，右边输出框出结果，四个通用按钮（执行 / 复制 / 下载 / 清空）对所有模式生效。

真正让它区别于同类在线格式器的，是那个默认勾选的 **「展开嵌套 JSON 字符串」**（`:666`）：

后端接口返回里常见的 `{"extendInfo":"{\"a\":1}"}` 这种「字符串里套 JSON」，甚至套三四层，普通格式器只会给你一长串带 `\"` 的字符串。这里会递归 `JSON.parse` 每一层字符串值，把它变成真正的对象再整体美化（`:781-816`），**递归深度上限 20 层**（`:783`）。这个能力同时作用于 JSON 模式和日志模式。

其他值得一提的：

- **日志模式**是「在日志里捞 JSON」：扫描整段文本，用括号配对 + 字符串/转义状态机找出所有**平衡的** `{...}` 片段，逐个原地美化，**日志原文的时间戳、级别、消息全部保留**（`:1395-1451`）。找不到 JSON 时会退一步尝试把整段当 JSON 格式化。
- **自动执行默认开启**，粘贴完 400ms 后自己出结果（`:1604-1618`），基本不需要点「执行」。
- **输出框可下载成带正确后缀的文件**（`.json` / `.xml` / `.html` / `.css` / `.sql` / `.txt`）。

**不适合的场景 / 明确没有的能力**：

- ❌ **无撤销**。`清空` 直接清掉输入框，误按 `Ctrl+Shift+K` 只能靠剪贴板历史找回。
- ❌ **无历史记录**、无最近使用、无收藏示例。
- ❌ **不压缩**（只有美化，没有 Minify）、无 JSON ↔ YAML / XML / CSV 互转、无 JSONPath / JSON Schema 生成。
- ❌ **不校验业务结构**：JSON 只判合法性，不做 schema 校验；SQL 不做语法解析。
- ❌ **无语法高亮**，输出框是纯 `textarea`；**无行号**、**无折叠**。
- ⚠️ **CSS 格式化输出不跟随「缩进」设置**（固定 1 空格），是本版本确认的缺陷，见 FAQ 与第 10 章②。
- ⚠️ **HTML 模式会改写内容**：文本节点内的 `<` `>` `&` 被重新转义、属性引号统一成双引号、自闭合标签被展开成 `<br></br>` 形式 —— 它不是无损格式器。

## 2. 快速开始

1. 双击 `全能格式化工具箱.html` 打开，**完全离线可用**，无任何外部请求。
2. 默认停在 **JSON** 模式。把内容粘进左侧输入框 —— 什么都不用点，约 0.4 秒后右侧自动出现美化结果，状态栏变绿显示 `JSON 格式化成功`。
3. 想按字母序重排字段 → 勾 **按键名排序**（会立即重跑）。
4. 不想展开字符串里的 JSON → 取消 **展开嵌套 JSON 字符串**（默认是勾上的）。
5. 换缩进 → 右侧下拉选 2 空格 / 4 空格 / 1 空格 / Tab。
6. 点 **复制**（或 `Ctrl+Enter` 后 `Ctrl+Shift+C`… 不，剪贴板没有快捷键，只能点按钮）→ toast `📋 已复制到剪贴板`。
7. 要存文件 → 点 **下载**，得到 `output_时间戳.json`。
8. 换工具：点上排任意模式按钮。**输入内容不会被清空**，会自动按新模式重跑一次。

**日志场景最短路径**：切到 `日志` 模式 → 整段日志粘进去 → 只看状态栏 `成功解析 N 个 JSON 片段（已展开嵌套）` → 复制整段。

## 4. 功能操作详解

### 4.1 执行时机（一共有 7 种）

理解「什么时候会自动跑」比记快捷键更重要。自动执行开启时，以下任一动作都会触发处理：

| 触发 | 延迟 | 源码 |
| ---- | ---- | ---- |
| 输入框内容变化 | **400ms** 防抖 | `:1604-1618` |
| 切换模式 | 30ms | `:1592-1594` |
| 切换编码/解码 | 立即 | `:1601` |
| 改缩进 | 立即 | `:1664-1666` |
| 勾选/取消「按键名排序」 | 立即 | `:1668-1670` |
| 勾选/取消「展开嵌套」 | 立即 | `:1672-1674` |
| 打开「自动执行」开关 | 立即（若已有内容） | `:1660-1662` |

**关掉自动执行后**，以上全部失效，只有 `✨ 执行` 按钮和 `Ctrl+Enter` 会处理。改缩进、改排序**也不会重跑** —— 这是最容易踩的坑：关了自动执行，调完缩进发现输出没变，其实只是没重新执行。

**输入变空**时（自动执行开着）：清空输出、状态回到 `等待输入...`、计数归零（`:1611-1616`）。

### 4.2 JSON 模式

`JSON.parse` → （可选）递归展开嵌套 → （可选）按键名排序 → `JSON.stringify(…, indent)`（`:819-829`）。

**展开嵌套的规则**（`:781-816`）：

- 只对**字符串值**尝试；先 `trim`，再要求**同时**以 `{`/`}` 或 `[`/`]` 首尾包围，才尝试 `JSON.parse`；
- 解析结果是对象/数组才替换，解析失败**静默保留原字符串**（不报错、不提示）；
- 递归处理数组元素和对象所有字段，`depth > 20` 时停止（`:783`）。

**由此产生的两个可见后果**：

1. **数字型字符串不受影响**：`"123"` 不会被转成 `123`（首字符不是 `{`/`[`）。
2. **`"null"`、`"true"` 也不受影响**，同理。但 **`"[1,2]"` 会被展开成数组** —— 如果你本来就想保留这个字符串（例如它是某个签名原文的一部分），必须取消勾选。

**按键名排序**是**递归**的（`:769-777`）：所有层级的对象键都按 `Array.prototype.sort()` 默认（UTF-16 码点）排序，**数组顺序保持不变**。中文键按码点排，不是拼音序。

**排序与展开的先后**：先展开、后排序（`:823-827`）→ 展开出来的新对象也会被排序。

**失败时**：输出框清空、输入框变红、状态栏显示 `处理失败：Unexpected token … in JSON at position …`（浏览器原生 `JSON.parse` 的报错文案，Chrome 会给出出错位置，很有用）。

### 4.3 XML 模式

`DOMParser('text/xml')` → 递归重排（`:832-909`）。

- 若开头有 `<?xml … ?>`，先摘出来单独占一行（`:836-841`）。
- 有 `parsererror` 就抛错，只取错误信息**第一行**（`:847`）—— XML 原生报错常是多行的，只看到第一行有时定位不到。
- 排版规则：空元素 → `<a></a>`；**只有一个文本子节点 → `<a>文本</a>` 同行**；其余情况子节点各占一行。
- 注释 `<!-- -->` 保留，但**内部空白原样输出**（`:860`）。
- **CDATA 节点被丢弃**（`formatNode` 只处理 TEXT / COMMENT / ELEMENT，`:854-862`，子节点收集同理 `:876-884`）—— 含 `<![CDATA[…]]>` 的 XML 格式化后内容会**丢失**。
- **属性顺序保持原样**（按 `node.attributes` 遍历），不受「按键名排序」影响（该选项在 XML 模式已隐藏）。
- 属性值**原样输出**，不重新转义（`:870`）→ 原本转义过的保持转义。

### 4.4 HTML 模式

`DOMParser('text/html')` → 递归重排（`:912-1002`）。

**这是全工具里最需要小心的一个模式**，因为它是「解析后重新序列化」，不是纯文本排版：

| 行为 | 说明 |
| ---- | ---- |
| 文本节点重新转义 | `&` `<` `>` 被替换成实体（`:935`、`:979`、`:986`）→ 原本写 `&amp;` 的仍是 `&amp;`，但**已经写成 `&lt;` 的会变成 `&amp;lt;`**（双重转义风险） |
| 属性统一双引号 | 值内 `"` 转成 `&quot;`（`:955`），单引号属性变双引号 |
| 空白文本节点删除 | `trim()` 后为空的文本节点直接不输出 → **`<span>a</span><span>b</span>` 之间的手写空格会消失** |
| 空元素展开 | 非 void 的空元素输出成 `<div></div>`；**void 标签**（`area base br col embed hr img input link meta param source track wbr`，`:924-927`）输出成 `<br>`，原本写 `<br/>` 或 `<br />` 的斜杠被去掉 |
| `<!DOCTYPE>` | 只输出 `<!DOCTYPE html>`，**丢失 publicId / systemId**（`:999`）→ XHTML 的完整 doctype 会被简化 |
| 缺失标签被补全 | `text/html` 解析器会自动补 `<html><head><body>` —— 粘一段 `<div>…</div>` 片段进去，输出会**多出 html/head/body 三层** |
| `<script>` / `<style>` 内容 | 作为普通元素子节点处理，内部代码会被 `trim` 并参与重排，**多行 JS 的排版可能被破坏** |

**结论**：HTML 模式适合**看结构**，不适合**格式化后要粘回去继续用**的场合（尤其含内联脚本/大量手写空格的排版）。想安全格式化，用 XML 模式（前提是标签本身闭合规范）。

另外 `:918-921` 那段 `parsererror` 检查在 `text/html` 下**永远不会命中**（HTML 解析不产生 `parsererror` 元素），所以 HTML 模式**不会报「解析错误」**，任何输入都会「成功」并给你一个可能被改写的结果。

### 4.5 CSS 模式

手写词法分析 + 重排（`:1005-1136`）：识别注释、引号字符串、空白、单字符四类 token，然后按规则输出。

**会做的**：`{` 后换行、`}` 回退缩进、`;` 后换行、**选择器列表的 `,` 后换行**（`:1109-1114`）、注释单独成行、**合并 3 个以上连续空行为 1 个**（`:1134`）。字符串（含引号内的 `;` `{`）原样保留，注释原样保留。

**⚠️ 确认的缺陷 —— 缩进不受「缩进」下拉控制**：

`formatCSS` 在 `:1049` 取了 `indentStr = getIndentStr()`，但这个变量**只被 `addIndent()` 之外的语法引用**，实际负责缩进的 `addIndent()`（`:1055-1057`）用的是 `indentStr.repeat(indentLevel)` —— 而**声明块内的每一条声明前面根本没有调用 `addIndent()`**；换行由 `;` 分支的 `output += ';\n'`（`:1103`）产生，下一条声明直接从行首开始。

所以实际输出是这样的（无论缩进选 2/4/1/Tab）：

```css
.a {
 color: red;
 background: blue;
}
```

即**声明行只有源码里原本残留的那点空白被吃掉后剩下的零缩进**（一个空格都没有，词法阶段所有 `space` token 被跳过）。嵌套 `@media` 内的规则选择器同样没有缩进。

**其他局限**：

- **`,` 无条件换行** → `background: linear-gradient(red, blue)` 这类**函数内的逗号也会被换行**，产生：
  ```css
  .a {
  background: linear-gradient(red,
   blue);
  }
  ```
  这是最容易让人觉得「格式化坏了」的一点。缓解见第 10 章③。
- 不识别 `!important`、`url()` 里的裸括号、`@supports` 里的条件括号 —— 靠通用括号处理，一般没问题但极端写法可能错位。
- 不做属性排序、不去重、不合并规则、不校验属性名。

### 4.6 SQL 模式

手写词法 + 关键词大写 + 子句换行（`:1139-1362`）。

- **关键词表约 120 个**（`:1142-1160`），命中即**整词大写**（`:1246`）→ `select a from t` → `SELECT a FROM t`。表名/字段名/字符串**大小写保持不变**。
- **换行关键词**是其中一个子集（`:1255-1263`）：`SELECT FROM WHERE AND OR GROUP HAVING ORDER LIMIT OFFSET INSERT INTO VALUES UPDATE SET DELETE CREATE TABLE ALTER DROP INDEX VIEW JOIN LEFT RIGHT INNER OUTER ON UNION ALL EXCEPT INTERSECT WITH AS CASE WHEN THEN ELSE END BEGIN COMMIT ROLLBACK GRANT REVOKE`。
  - `AND` / `OR` **无条件换行**；
  - `ON` **仅当当前行超过 60 字符**才换行（`:1295`）；
  - 其余换行关键词只要当前行非空就换行。
- **`(` 会递增缩进层级、`)` 递减**（`:1299-1311`）→ 子查询和 `IN (...)` 列表能缩进去。
- **`;` 强制结束一行**（`:1317-1325`）→ 多条语句自动分行。
- **字符串识别支持三种引号**：`'…'`（支持 `''` 双写转义和 `\` 转义）、`"…"`、`` `…` ``（MySQL 反引号）（`:1176-1200`）。
- **注释支持** `-- 行注释` 和 `/* 块注释 */`，各占一行（`:1202-1217`、`:1279-1287`）。

**局限**：

- 这不是真正的 SQL 解析器，是**基于关键词的启发式排版**。`SELECT` 出现在字符串里不会被大写（好），但**同名的字段/别名会被大写**（`SELECT "order" AS "FROM"` 里的字符串安全，但 `` `order` `` 反引号内也安全；裸写的 `AS end` 会变成 `AS END`）。
- **不做子句对齐**（`SELECT` 下方列不会对齐），不格式化 `JOIN … ON` 成多行（除非行超 60 字符）。
- 逗号**不换行**（与 CSS 相反）→ 长 `SELECT a,b,c` 仍是一行。
- 不识别 `$$` 引用、`[方括号标识符]`（SQL Server）、`#临时表`（会被当普通词，一般没问题）。

### 4.7 URL 模式

只有两个动作，**整段一次性处理**（`:1365-1372`）：

- **编码** = `encodeURIComponent(raw)` —— 会保留 `A-Z a-z 0-9 - _ . ! ~ * ' ( )`，**其余全部转义**。
  - ⚠️ **它会把 URL 本身也整个转义**：输入 `https://a.com?x=1 2` → `https%3A%2F%2Fa.com%3Fx%3D1%202`。想只转 query 值不转结构，得自己拆。
  - ⚠️ **空格 → `%20`**（不是 `+`）。表单编码场景需要 `+` 的话这里做不到。
- **解码** = `decodeURIComponent(raw)`，**失败时降级**为逐 `%XX` 的 `String.fromCharCode`（`:1370`）。
  - 降级分支是**按字节直接转字符**，对 UTF-8 多字节（中文）会得到乱码（如 `%E4%B8%AD` → `ä¸­`），但它至少能让你看出「这里原本是 3 个字节」。正常 UTF-8 输入走主分支，中文正确还原。
  - 真正的 `decodeURIComponent` 失败常见原因：输入里有**裸的 `%`**（如 `50%折扣`）→ 抛 `URIError` → 走降级。

**不做**：URL 结构解析、query 参数表格化、增删参数、base URL 拼接、host 编解码（Punycode）。

### 4.8 Base64 模式

**编码**（`:1377-1381`）：`TextEncoder` → UTF-8 字节 → `btoa`。**支持中文和 emoji**，输出标准 Base64（含 `+/`，末尾 `=` 填充）。

**解码**（`:1382-1391`）：先 `replace(/\s/g,'')` **去掉所有空白**（所以从邮件/日志里粘贴的自动换行 Base64 能正常解），再 `atob` → `TextDecoder` 还原 UTF-8。失败抛 `Base64 解码失败：…`。

**局限（重要）**：

- **只能解「内容是文本」的 Base64**。二进制（图片、zip）解出来会被 `TextDecoder` 按 UTF-8 强行解码 → 得到 U+FFFD 替换字符，**不可逆**。想看图要先用 `data:` 前缀或换工具。
- **不解 URL-safe Base64**：`-` `_` 会直接让 `atob` 抛错。需先手动把 `-`→`+`、`_`→`/`（可先用 URL 模式或全局替换）。
- **不校验长度/字符集**，输入 `abc` 这种非 4 倍数长度会报 `InvalidCharacterError`。
- 不做 Hex ↔ Base64、不做压缩、不做分段。

### 4.9 日志模式

**扫描算法**（`extractJsonFragments`，`:1395-1431`）：

- 从左往右找 `{`，然后逐字符扫描，维护 `depth`、`inString`、`escape` 三个状态 → 找到**配对闭合**的 `}`；
- 对截出的子串 `JSON.parse`，成功且是对象才登记为片段；
- **找到后从闭合位置继续**（`:1421`），所以一行日志里两个 JSON 都能抓到；
- **未闭合的 `{`** 会一路扫到文本末尾再放弃，`i++` 继续（`:1427`）—— 大段残缺 JSON 会让扫描变慢但不会崩。

**替换方式**：按 `start` **倒序**替换（`:1437`），保证前面的偏移不被后面的替换破坏。**日志的非 JSON 部分一字不动**。

**每个片段独立应用**「展开嵌套」和「按键名排序」（`:1442-1445`）。

**美化后的片段会顶到行首**：

```
2024-01-01 10:00:00 INFO  request {"a":1,"b":{"c":2}} done
```
→
```
2024-01-01 10:00:00 INFO  request {
  "a": 1,
  "b": {
    "c": 2
  }
} done
```

即 JSON 从它原来的列位置开始换行，后续行**没有额外缩进**。这是设计如此（保持原文位置），但读起来不如专门的多行日志查看器整齐。

**兜底逻辑**（`:1492-1502`）：一个片段都没找到时，尝试把**整段输入当 JSON** 格式化；成功则状态显示 `未检测到日志格式，但整体是合法 JSON，已直接格式化`；仍失败则状态显示 `未检测到可解析的 JSON 片段`，并**把原文原样放进输出框**（不丢弃你的内容，方便直接复制走）。

**只识别 `{}` 对象，不识别裸的 `[...]`**（扫描入口只判断 `{`，`:1400`）→ 一行只有数组的日志（如 `[1,2,3]`）不会被格式化。

### 4.10 复制 / 下载 / 清空

**复制**（`:1523-1542`）：优先 `navigator.clipboard.writeText`，被拒（`file://` 非安全上下文常见）则降级到隐藏 `textarea` + `document.execCommand('copy')`。两条路都有 toast。

> `file://` 双击打开时 `navigator.clipboard` 往往不存在或 `writeText` 被拒 —— 这里的降级链正是为这个场景准备的，实测能复制成功。

**下载**（`:1544-1559`）：`Blob(['text/plain;charset=utf-8'])` → `a.download` → **文件名 `output_<Date.now()>.<ext>`**。

后缀映射（`:1547`）：

| 模式 | json | xml | html | css | sql | url | base64 | log |
| ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| 后缀 | `.json` | `.xml` | `.html` | `.css` | `.sql` | `.txt` | `.txt` | `.txt` |

MIME 恒为 `text/plain;charset=utf-8`（即使 `.html`/`.xml`）→ 下载的文件不会被浏览器当成可执行页面，双击是文本编辑器打开，安全。

**清空**（`:1561-1568`）：清两个框 + 移除校验色 + 状态 `已清空` + 计数归零 + **聚焦输入框**。**无确认弹窗、无撤销**。

### 4.11 错误与校验反馈汇总

| 情况 | 状态栏 | 输入框 | 输出框 |
| ---- | ---- | ---- | ---- |
| 输入为空（点执行） | `❌ 请输入内容` | 红 | 清空 |
| 解析/处理抛错 | `❌ 处理失败：<原始 error.message>` | 红 | **清空** |
| 日志模式无 JSON 且整体非 JSON | `❌ 未检测到可解析的 JSON 片段` | 红 | **保留原文** |
| 成功 | `✅ …成功` | 绿 | 绿 |
| 自动执行下清空输入 | `💡 等待输入...` | 无色 | 清空 |

注意第二行：**抛错时输出框会被清空**（`:1515`）。如果你的流程是「先格式化成功 → 手动改改输入 → 改错了报错」，上一次的正确输出就没了。稳妥做法是成功一次先点复制。

## 6. 支持的输入 / 输出格式

### 输入（按模式）

| 模式 | 接受的输入 | 判定方式 | 失败表现 |
| ---- | ---- | ---- | ---- |
| JSON | 任意合法 JSON（对象/数组/字符串/数字/`true`/`false`/`null` 均可作为顶层） | `JSON.parse` | `Unexpected token … in JSON at position N` |
| XML | 良构 XML，可含 `<?xml?>` 声明 | `DOMParser('text/xml')` + `parsererror` 检测 | `XML 解析错误：<第一行>` |
| HTML | 任意字符串（**永不报错**） | `DOMParser('text/html')` | 不报错，但结果可能被改写 |
| CSS | 任意字符串（**永不报错**，也不校验语法） | 自有词法分析 | 不报错，极端输入下排版可能错乱 |
| SQL | 任意字符串（**永不报错**） | 自有词法分析 | 不报错 |
| URL | 任意字符串（编码）/ 任意字符串（解码，失败降级） | `encodeURIComponent` / `decodeURIComponent` | 解码失败**不报错**，走降级分支 |
| Base64 | 编码：任意文本；解码：标准 Base64（可含空白） | `btoa` / `atob` | `Base64 解码失败：<原因>` |
| 日志 | 任意文本，含 0~N 个 `{…}` 片段 | 括号配对 + `JSON.parse` 验证 | 无片段且整体非法 → `未检测到可解析的 JSON 片段` |

**无大小限制**：源码没有长度上限校验、没有截断、没有分块。实际上限就是浏览器 `textarea` 与主线程的承受能力 —— **几 MB 的 JSON 会明显卡顿**（自动执行 400ms 防抖 + 主线程同步解析），几十 MB 可能假死。大文件建议关掉「自动执行」。

**不接收**：文件拖放（**无 drop 区**）、文件选择（**无 `<input type=file>`**）、URL 抓取（无网络）、剪贴板自动读取（要手动 `Ctrl+V`）、YAML / TOML / INI / CSV / Protobuf / Markdown / JS 对象字面量（`{a:1}` 无引号键**会 JSON 报错**）、带注释的 JSON（`JSON5` 风格 `//` 注释会报错）。

### 输出

| 项 | 值 |
| ---- | ---- |
| 展示形态 | 纯文本 `textarea`（只读），**无高亮 / 行号 / 折叠** |
| 缩进选项 | `2 空格`（默认） / `4 空格` / `1 空格` / `Tab`（JSON / XML / HTML / SQL / 日志 生效；**CSS 无效**） |
| 复制 | 输出全文到剪贴板，`clipboard` 失败自动降级 `execCommand` |
| 下载文件名 | `output_<毫秒时间戳>.<后缀>`，后缀见 §4.10 表 |
| 下载 MIME | 恒为 `text/plain;charset=utf-8` |
| 编码 | UTF-8 |

**没有的输出**：压缩后的单行结果、Minify、格式化回原缩进风格、diff 对比、结构树视图、字段路径（如 `a.b[0].c`）复制、JSON Schema / TypeScript interface / Go struct 生成、统计报告（键数量、嵌套深度、体积占比）。

## 7. 数据与隐私

**这是全项目隐私最干净的类型之一 —— 零存储、零网络。**

### 7.1 网络

**全文检索无任何网络出口**：无 `fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` / `EventSource`；无 `<link href>`；无 `<script src>`；无 `@import`；无外链图片/字体。

唯一匹配到 `http://` 的是 CSS 里 `background-image: url("data:image/svg+xml,…")` 中的 **`xmlns='http://www.w3.org/2000/svg'` 命名空间声明**（`:455`）—— 它是 XML 命名空间标识符，**浏览器不会为它发起任何请求**，而且整个 SVG 是 `data:` 内联的。

**没有 favicon**（浏览器会自动请求 `/favicon.ico`，那是浏览器行为不是页面代码）。

→ **断网、内网、涉密环境可直接双击使用**。

### 7.2 存储

| 项 | 结论 |
| ---- | ---- |
| `localStorage` | **不使用** |
| `sessionStorage` | **不使用** |
| `IndexedDB` | **不使用** |
| Cookie | **不读写** |
| Service Worker / Cache API | **不使用** |

**所有状态只存在于内存**：`currentMode`、`currentAction`、两个 `textarea` 的值、4 个选项的勾选状态、缩进选择 —— **刷新页面全部回到初始值**（JSON 模式 / 编码 / 2 空格 / 自动执行开 / 展开嵌套开 / 排序关）。

**由此带来的两个后果**：

1. **优点**：不留痕。在公用电脑、客户机器上处理敏感报文（含 token、手机号、身份证的接口返回）后，关掉页面即无残留，无需清理。
2. **代价**：**没有偏好记忆**。习惯 4 空格 + 关自动执行的人，每次打开都要重新设置（要改默认值只能改源码，见第 10 章①）。

### 7.3 其它

- **剪贴板**：只写不读（`writeText` / `execCommand('copy')`），不读取剪贴板内容。
- **不使用** `navigator.geolocation`、摄像头、麦克风、`crypto`、`navigator.share`、`Notification`。
- **无埋点、无统计、无广告 SDK。**
- **XSS 面很小但有一处需注意**：所有输出都写进 `textarea.value`（不解析 HTML），安全。但 **XML / HTML 模式内部用 `DOMParser` 解析用户输入** —— 解析本身不执行脚本（`DOMParser` 的文档未挂载到活动文档，`<script>` 不会运行），不过 `:955`、`:870` 这类**属性值拼接进字符串**的逻辑，如果将来有人改成 `innerHTML` 输出就会变成注入点。当前版本无泄露路径。

## 8. 常见问题（FAQ）

**CSS 格式化后声明挤在行首，缩进下拉怎么调都没用。**

不是你的问题，是这版代码的缺陷。`formatCSS` 声明了 `indentStr` 却没在每条声明前调用 `addIndent()`（`:1049-1057`、`:1102-1107`），所以缩进层级只体现在「`}` 的回落」上，声明行始终零缩进。临时接受方案：格式化后编辑器全选重排。彻底修法见第 10 章②（3 行改动）。

**`background: linear-gradient(red, blue)` 被逗号拆到两行了。**

`,` 分支（`:1109-1114`）**无条件换行**，不区分「选择器列表的逗号」和「函数参数里的逗号」。当前版本的实用规避：格式化前把函数内的逗号临时替换成一个占位符（如 `__COMMA__`），格式化后再全局替换回 `,`。或者按第 10 章③加一个「括号深度 > 0 则不换行」的判断（2 行）。

**粘进去没反应，要点「执行」才出结果。**

先看「自动执行」有没有被取消勾选（默认是勾上的）。如果它是开着的：输入变化有 **400ms 防抖**，粘贴超大文本时解析本身耗时，可能要 1 秒以上。另外注意 —— **改缩进/排序后没重跑**，说明自动执行是关的（那两个选项只在自动执行开启时才触发处理，`:1664-1674`）。

**JSON 明明是对的，却报 `Unexpected token`。**

按概率排查：

1. **键没加引号**（JS 对象字面量 `{a:1}`）→ 本工具不是 JSON5，不支持。
2. **有注释**（`//` 或 `/* */`）→ `JSON.parse` 直接拒绝。
3. **末尾多一个逗号** `{...}]` 前后。
4. **单引号**字符串 `'abc'`。
5. **不可见字符**：从 Word/网页复制带进零宽空格 U+200B、BOM U+FEFF、不间断空格 U+00A0。切到 **Base64 编码**看输出，或状态栏字符数与肉眼预期对比。
6. **被日志文本包裹** → 别用 JSON 模式，用**日志模式**。

Chrome 的报错带 `at position N`，在输入框里按 `Ctrl+Home` 后数过去，或直接相信位置数。

**字段里的 JSON 没被展开。**

`expandNestedJson`（`:785-801`）要求字符串 `trim` 后**同时**满足：首字符是 `{` 或 `[`，**且**尾字符是对应的 `}` 或 `]`，**且** `JSON.parse` 成功。以下都不会展开：

- 字符串两侧有多余文字：`"data={\"a\":1}"`（首字符是 `d`）；
- **被 URL 编码过**：`%7B%22a%22%3A1%7D` → 先用 URL 模式解码，再回来；
- **被 Base64 编码过** → 先 Base64 解码；
- 内层 JSON 本身非法（少引号、多逗号）→ **静默保留原字符串，不报错**；
- 套超过 **20 层**（`:783` 深度上限）。
- 「展开嵌套 JSON 字符串」勾掉了（该选项只在 JSON / 日志模式可见，切到别的模式它是**隐藏但保留状态**，不是关闭）。

**展开后数据变了 —— 我的签名校验不过了。**

预期行为：展开是 `JSON.parse` + `JSON.stringify`，会**丢掉原始键顺序**（若还勾了排序）、**规范化数字**（`1.0` → `1`）、**规范化转义**。任何涉及签名/摘要校验的场景，**请先取消勾选「展开嵌套 JSON 字符串」**，只看不改。

**HTML 格式化后页面效果不对了。**

因为 HTML 模式是「解析后重序列化」，会做四件改写内容的事（见 §4.4 表格）：删空白文本节点（**手写空格丢失**）、文本重新转义（可能双重转义）、属性统一双引号、补全 `html/head/body`。含内联 `<script>` 的片段风险最大。

安全替代：① 用 XML 模式（要求标签严格闭合、属性带引号）；② 只格式化不含脚本的纯结构片段；③ 格式化后逐处 diff 检查。

**XML 里 `<![CDATA[ … ]]>` 的内容不见了。**

确认的行为：`formatNode` 只处理 TEXT / COMMENT / ELEMENT 三类节点（`:854-862`、`:876-884`），CDATA 节点被静默跳过。**格式化含 CDATA 的 XML 会丢内容**，请手动核对。修法见第 10 章④。

**日志模式说「未检测到可解析的 JSON 片段」。**

三种情况：

1. 日志里根本没有 `{...}`；
2. **JSON 不闭合**（日志被截断/换行打断）→ 括号配对永远不闭合，扫描放弃；
3. 是**裸数组** `[{...},{...}]` —— 扫描入口只从 `{` 开始（`:1400`），但注意**数组内部的第一个 `{` 仍会被抓到**，所以数组元素会被逐个美化（只是外层 `[ ]` 保持原样）。想整体美化数组，直接切 JSON 模式粘数组。

**Base64 解出来是乱码 / 一堆 ``。**

解码固定走 `TextDecoder`（UTF-8，`:1387`）→ 只适合**原文是文本**的 Base64。图片、序列化对象、gzip 二进制解出来必然坏掉，且**不可逆**（别拿输出再编回去当校验）。图片请直接用 `data:image/png;base64,…` 前缀粘到地址栏。

**Base64 解码报 `InvalidCharacterError`。**

- 输入是 **URL-safe Base64**（含 `-` `_`）→ 先替换成 `+` `/`；
- 长度不是 4 的倍数且无 `=` 填充 → 补 `=`；
- 含中文、空格以外的非法字符（空白会被自动去掉，`:1384`，所以换行不是问题）。

**URL 解码后中文变成 `ä¸­` 这种怪字符。**

说明 `decodeURIComponent` 抛错并走了降级分支（`:1370`），降级是按单字节 `String.fromCharCode`，多字节 UTF-8 必然错乱。抛错的常见原因是输入里有**裸 `%`**（如 `进度50%完成`）。把那个 `%` 手动改成 `%25` 再解。

**URL 编码把 `://` 和 `?` 也转了。**

`encodeURIComponent` 是「值级」编码，本来就该转义整个 URL 结构。要保留结构只能自己分段处理（本工具无「仅编码 query 值」功能）。

**能不能记住我常用的 4 空格 + 关闭自动执行？**

界面上不能。所有状态不落盘（第 7 章）。两种办法：① 每次手动设；② 改源码把默认值改掉 —— 把 `:672-675` 的 `selected` 从 2 空格挪到 4 空格，把 `:679` 的 `checked` 从 `autoFormat` 挪走。见第 10 章①。

**大 JSON（几 MB）卡住不动。**

正常，全部处理在主线程同步完成。关掉「自动执行」再粘贴，然后手动 `Ctrl+Enter`，至少避免边打字边重解析。另外**取消「展开嵌套」**能显著提速（它要遍历整棵树并对每个字符串试 `JSON.parse`）。

**误按 `Ctrl+Shift+K`，输入的内容没了。**

无撤销、无确认（`:1681-1683` 直接调 `doClear`）。如果内容原本是复制进来的，用系统剪贴板历史（`Win+V`）找回。想加保险，见第 10 章⑤（给清空加确认）。

## 9. 技术实现要点（开发者）

**结构**：1721 行，单 `<style>`（`:7-603`，约 600 行）+ 单 `<script>`（`:712-1719`，约 1000 行，**整体一个 IIFE**，无全局污染）。DOM 仅 100 行（`:605-711`）。

**用到的 Web API**：`JSON`、`DOMParser`（`text/xml` + `text/html`）、`TextEncoder` / `TextDecoder`、`btoa` / `atob`、`encodeURIComponent` / `decodeURIComponent`、`navigator.clipboard`（+ `execCommand` 降级）、`Blob` + `URL.createObjectURL`、`Node` 常量族。

**不使用**：`fetch`、`localStorage`、`IndexedDB`、`requestAnimationFrame`、`crypto`、任何第三方库。

### 关键设计

- **`getIndent()` vs `getIndentStr()` 是两个不同契约**：前者返回 number 或 `'\t'`（`JSON.stringify` 接受），后者返回字符串（手写排版用）。新增格式化器时别混用。`getIndent` 的 `parseInt(val,10) || 2` 兜底意味着**异常值一律退回 2 空格**（`:760`）。
- **`expandNestedJson` 是纯函数**（返回新对象，不改原树）→ 关掉选项即可完全还原，无副作用残留。它对**空对象 `{}`、空数组 `[]` 字符串**也会展开（`"{}"` → `{}`）。
- **日志替换必须倒序**（`:1437` 的 `sort((a,b)=>b.start-a.start)`）—— 正序会让后续片段的 `start/end` 偏移失效。改动这段时务必保持倒序。
- **`extractJsonFragments` 的字符串状态只跟踪 `"`**（`:1407`），不跟踪 `'` —— 日志里出现单引号包裹、内含 `{` 的文本会导致 `depth` 计数错乱（虽然最终 `JSON.parse` 会拒绝，不至于产出错误结果，但可能漏掉真正的片段）。
- **`doProcess` 是唯一入口，所有模式共用一套 try/catch** → 新增模式只需在 `:1469-1507` 的 if-else 链加分支 + `extMap` 加后缀 + `hints` 加文案 + `switchMode` 加选项显隐。**四处**，漏 `extMap` 会退回 `.txt`，漏 `hints` 提示区会空白。
- **模式列表三处硬编码需同步**：DOM `:620-627`、`hints` `:1574-1583`、`extMap` `:1547`。
- **选项显隐集中在 `switchMode`**（`:1586-1588`）：新增只在某模式生效的选项，在这里加一行 `style.display`。
- **自动执行的 6 个触发点分散在各监听里**（`:1592`、`:1601`、`:1660-1674`），都是同一段 `if (autoFormat.checked && inputArea.value.trim()) doProcess()`。想统一可以抽个 `maybeAutoProcess()`。
- **`toast` 复用同一个 DOM 节点**（`:749-755`），`className` 整体重置后再 `add('show')` → 同时只能有一个 toast，`toastTimer` 保证快速连点不闪烁。
- **`updateStats(inputText, outputText)` 的 `outputText` 是可选参数**（`:1626` 有 `!== undefined` 判断）→ 输入变化时只更新输入侧计数，避免每敲一键都读一次可能很大的输出框。
- 事件绑定统计：4 个顶部按钮、8 个模式按钮、2 个 action 按钮、`input` 事件、4 个选项 change、`document.keydown`、`inputArea.keydown`。共 21 个监听，全部在 `bindEvents()` 内，无内联 `onclick`。
- 校验色用 `classList.add/remove('error','valid')`（`:1636-1639`），`hideError()` 在每次处理开头调用（`:1455`）—— 加新状态时记得同步清理。

### 性能特征

- 全部**同步单线程**。JSON 模式复杂度 = `JSON.parse` + O(节点数 × 字符串长度) 的展开扫描 + `JSON.stringify`。
- 展开是**最贵的步骤**：对每个字符串值做 `trim()` + 首尾判断（便宜）+ 可能的 `JSON.parse`（贵）。字段全是长字符串的报文（如 base64 图片字段）会明显变慢 —— 好在有首尾 `{[` 判断挡掉了绝大多数。
- 日志模式对**每个未闭合的 `{`** 都会扫到文本末尾（`:1403` 的内层 for 无提前退出），所以「大量 `{` 且不闭合」的输入是 O(n²) 最坏情况。
- 400ms 防抖（`:1617`）是唯一的节流手段。

## 10. 二次修改指引（开发者）

按需求频率排序，每条给出确切位置。

**① 改默认偏好（最多人想要）**

纯 HTML 属性调整，`:661-681`：

```html
<!-- 默认 4 空格：把 selected 挪到 4 -->
<option value="4" selected>4 空格</option>
<!-- 默认关闭自动执行：删掉 autoFormat 上的 checked -->
<input type="checkbox" id="autoFormat" />
<!-- 默认不展开嵌套：删掉 expandNested 的 checked -->
```

想真正记住偏好，在 `init()`（`:1710`）里读写 localStorage：

```js
const PREF_KEY = 'toolbox-prefs';
try {
  const p = JSON.parse(localStorage.getItem(PREF_KEY) || 'null');
  if (p) { indentSelect.value = p.indent || '2'; autoFormat.checked = p.auto !== false;
           sortKeys.checked = !!p.sort; expandNested.checked = p.expand !== false; switchMode(p.mode || 'json'); }
} catch (_) { /* ignore unavailable local storage */ }
['change'].forEach(ev => [indentSelect, autoFormat, sortKeys, expandNested].forEach(el =>
  el.addEventListener(ev, () => { try { localStorage.setItem(PREF_KEY, JSON.stringify({
    indent: indentSelect.value, auto: autoFormat.checked, sort: sortKeys.checked,
    expand: expandNested.checked, mode: currentMode })); } catch (_) {} })));
```

注意这会**改变第 7 章的「零存储」结论**，需要同步更新本文与根 README。

**② 修 CSS 缩进 bug（3 行，建议优先）**

`formatCSS` 里，把 `;` 分支产生的换行补上缩进：

```js
// :1102-1107，原为 output += ';\n'
if (ch === ';') {
  output += ';\n';
  i2++;
  while (i2 < n && tokens[i2].type === 'space') i2++;
  if (i2 < n && tokens[i2].value !== '}') addIndent();   // ← 加这一行
  continue;
}
```

`{` 分支（`:1083-1089`）同理，在跳过空白后补 `addIndent()`，让第一条声明也有缩进。改完 `indentStr` 就真的跟着下拉走了。

**③ 修 CSS 函数内逗号换行**

`formatCSS` 维护一个括号深度，`,` 只在深度 0 换行：

```js
// 循环外：let parenDepth = 0;
// 在 ch === '(' 时 parenDepth++，ch === ')' 时 parenDepth--
if (ch === ',') {
  if (parenDepth > 0) { output += ', '; i2++; continue; }   // ← 函数内：同行
  output += ',\n';                                           // ← 选择器列表：换行
  i2++; while (i2 < n && tokens[i2].type === 'space') i2++;
  continue;
}
```

同理可给 `;` 加深度判断（`@media` 内不会有 `;`，风险低）。

**④ 修 XML 丢 CDATA**

`formatXML` 的 `formatNode`（`:852` 起）加一个分支，并在子节点收集处（`:881`）同步放行：

```js

// :881 的判断加上 || child.nodeType === Node.CDATA_SECTION_NODE
```

`formatHTML` 无 CDATA 概念，不用改。

**⑤ 给清空加保护**

`:1681-1683` 和 `clearBtn` 都调 `doClear`，在 `doClear`（`:1561`）开头加：

```js
if (inputArea.value.trim() && !confirm('确认清空输入与输出？此操作不可撤销。')) return;
```

更友好的做法是保留一份 `previousInput`，再加一个 `Ctrl+Z` 恢复 —— 但要注意 `confirm` 会打断 `Ctrl+Shift+K` 的流畅性，建议只在输入超过一定长度时弹。

**⑥ 加一个模式（以 YAML 为例）**

四处都要动，缺一处就表现为「点了没反应 / 下载后缀不对 / 提示区空白」：

2. `doProcess` 的 if-else 链 `:1507` 后加 `else if (currentMode === 'yaml') { result = formatYAML(raw); statusMsg = '…'; }`；
3. `extMap` `:1547` 加 `yaml: 'yaml'`；
4. `hints` `:1583` 后加文案。

**注意：项目定位是零依赖**，加 YAML/JSON5 需要自己写解析器，**不要**顺手引 CDN —— 二维码工坊和储物间导航已经因为 CDN 破坏了离线可用性，别再增加一例。

**⑦ 加压缩（Minify）按钮**

`formatJSON` 已有全部中间结果，最小改动：

```js
// 复制 formatJSON，把最后一行改成 JSON.stringify(parsed)（不传 indent）
```

再在选项行加个「压缩」复选框，`doProcess` 里三元选择。XML/HTML 的压缩则是在 `formatNode` 里跳过换行与缩进（改 `pad`/`join(' ')`）。

**⑧ 别踩的坑**

- **`formatHTML` 里的 `parsererror` 检查是死代码**（`:918-921`）—— `text/html` 解析不产生该节点。别指望它报错，也别在它上面加逻辑。
- **`getIndentStr()` 在 `formatCSS` 中形同虚设**（`:1049`，见 ②）—— 改 CSS 逻辑前先确认这一点，否则会以为缩进已经生效。
- **`:1116` 的 `if (ch === ' ' || ch === '\t')` 永远不成立** —— 空白在词法阶段已被归为 `type: 'space'` 并在 `:1062` 提前 `continue`，`char` token 不可能是空白。这段是死分支，读代码时别被误导（要清理可以删，但不影响行为）。
- **日志替换必须倒序**（`:1437`）。改成 `for (const frag of fragments)` 正序遍历会静默产出错位结果，很难发现。
- **`expandNestedJson` 会把字符串形式的数组/对象「真的」转成结构** —— 任何涉及**签名、摘要、原文比对**的使用场景都必须关闭该选项；二次开发时别把它设成不可关闭。
- **`sortObjectKeys` 用默认 `sort()`**（`:773`）→ 按 UTF-16 码点，**大写键排在小写键前面**（`"B" < "a"`），不是大小写无关排序。想要人类直觉的顺序得改成 `localeCompare`（注意中文键会走 ICU 规则，性能略降）。
- **`switchMode` 会强制 `setAction('encode')`**（`:1590`）→ 用户从「解码」切走再切回 URL 模式，方向悄悄变了。想保留上次方向，把 `currentAction` 存起来并在 `switchMode` 里判断恢复。
- **HTML 模式的文本转义（`:935`/`:979`/`:986`）是「先 unescape 再 escape」的单向操作** —— DOMParser 已把 `&amp;` 解成 `&`，再 escape 回 `&amp;`，正常；但源码里写 `&lt;` 的会先解成 `<` 再 escape 成 `&lt;`（正确），而源码里**写错的双重转义 `&amp;amp;`** 会一路保留。总体安全，但别把它当无损工具宣传。
- **`inputArea` 的 Tab 处理直接改 `value`，不派发 `input` 事件**（`:1703-1705`）→ 自动执行不会被 Tab 触发。想让它触发，改成 `document.execCommand('insertText', false, '  ')`（保留原生撤销栈，还能顺带解决 `Ctrl+Z` 失效）。
- **`doProcess` 抛错会清空输出**（`:1515`）—— 用户上一次的正确结果会丢。改成「保留上次输出 + 只标红」体验更好，但要注意日志模式已经特意保留了原文（`:1499`），两条路径行为不一致，改动时统一一下。
- **`updateStats` 的行数只按 `\n` 计**（`:1622`）→ 老 Mac 风格的 `\r` 换行算 1 行。
- **模式列表三处硬编码**（DOM / `hints` / `extMap`）—— 加模式漏改是本项目最容易出现的 bug，改完务必逐个模式点一遍并下载一次验证后缀。
