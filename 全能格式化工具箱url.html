    ① 五个字段（顺序固定，用空格分隔）

    位置字段范围说明
    1分钟 minute0-59一小时内的第几分钟
    2小时 hour0-230 = 午夜 0 点，12 = 中午
    3日 day of month1-31一个月中的第几号
    4月 month1-12也可用 JAN-DEC
    5星期 day of week0-70 和 7 都是周日，1=周一…6=周六；也可用 SUN-SAT

    完整一行格式：分 时 日 月 周  要执行的命令，例如 0 2 * * * /opt/backup.sh。本工具只生成前 5 段。

    ② 特殊符号

    符号含义示例
    *任意值（每个单位都匹配）* * * * * 每分钟
    ,列举多个值0 9 * * 1,3,5 周一/三/五 9 点
    -连续区间（含两端）0 9 * * 1-5 工作日 9 点
    /步长，每 N 个单位*/5 * * * * 每 5 分钟
    组合区间 + 步长0 9-18/2 * * * 9-18 点每 2 小时

    */5 从 0 开始（0、5、10…），不是从当前时间开始；3/5 表示从 3 起每 5 个单位（Vixie cron 支持，部分实现不支持）。

    ③ @别名（@reboot 无周期性时间）

    别名等价表达式
    @reboot系统启动时执行一次（无下次执行时间）
    @yearly / @annually0 0 1 1 *

    ④ 常见坑

    • 最短粒度是 1 分钟，Linux crontab 没有「秒」字段；* * * * * 就是每分钟，不是每秒。
    • 日与星期同时限定时是 OR 而不是 AND：0 0 1 * 1 表示「每月 1 号 或 每个周一」都会执行。只要其中一个字段是 * 才按 AND。
    • 时区按服务器时区（可用 CRON_TZ=Asia/Shanghai），本工具预览用的是本机浏览器时区。
    • 命令里的 % 必须转义成 \%，否则会被当作换行/标准输入分隔符。
    • 不存在的日期永不触发，如 0 0 30 2 *（2 月 30 日）。
    • crontab 文件末尾要保留换行；改完用 crontab -l 确认，日志通常在 /var/log/cron。
    • Spring / Quartz 是 6~7 字段（首位是秒），且支持 ? L W #；这些是 Quartz 专有语法，Linux crontab 不支持，本工具也不支持。

    📖 使用说明 · 秒与毫秒 / 时区 / 支持的日期格式（点击展开）

    ① 自动识别规则

    • 纯数字：位数 ≥ 12 视为毫秒，否则视为秒；也可用上方「输入单位」强制指定。
    • 日期字符串：支持 2024-01-01 08:00:00、2024/01/01、2024-01-01T00:00:00Z、带 +08:00 偏移的 ISO 8601。
    • 不带时区的字符串按本机时区解析；带 Z 或 ±HH:MM 的按自身偏移解析。
    • 一次可粘贴多行，逐行输出换算结果；无法识别的行会明确标注。

    ② 输出内容

    • Unix 秒 / 毫秒、所选时区的完整时间、UTC 时间、ISO 8601、星期、相对现在的时间差。
    • 「日期加减」对第一行结果运算，可算 N 天后 / N 小时前的时间戳。

    ③ 常见坑

    • 秒是 10 位、毫秒是 13 位。Java / Python 常给毫秒，MySQL UNIX_TIMESTAMP() 与 PHP 常给秒；搞错会算到 1970 年或 5 万年后。
    • 数据库存的若为 DATETIME，其数值取决于数据库时区，与浏览器本机时区可能不同。
    • JavaScript 的 Date.getTime() 是毫秒；Unix date +%s 是秒。
    • 2038 年问题只影响 32 位有符号秒级存储，JS 使用双精度毫秒，无此限制。
    • 时区换算基于浏览器内置 Intl 数据，历史夏令时规则以本机 ICU 版本为准。

    ④ 离线说明

    全部使用原生 Date / Intl.DateTimeFormat，不请求任何网络时间服务器；时钟取的是本机系统时间。

    📖 使用说明 · 操作可叠加 / 撤销 / 命名风格切词规则（点击展开）

    ① 怎么用最顺手

    • 左侧粘贴 → 点上方任意按钮，结果立即出现在右侧；再点一个按钮会在结果上继续叠加，可串联多步。
    • 「↶ 撤销」可回退最多 30 步；「⇄ 结果送回输入」方便把中间结果当新输入。
    • 右侧结果框可直接手工编辑，之后的操作以编辑后的内容为准。
    • 过滤词支持关键字或正则；「提取匹配片段」会把所有命中片段逐行列出。

    ② 命名风格切词规则

    • 按非字母数字分隔，并识别已有驼峰边界：user_name / userName / user-name 都会切成 user + name。
    • 连续中文视为一个词；纯中文行不会被拆成单字。
    • 转换只作用于文本行，不会改动空行。

    ③ 实用组合

    • 字段清单 → 去首尾空白 → 去空行 → 去重 → SQL IN 列表，直接贴进 SQL。
    • 接口字段批量改名：camelCase → 加前缀 → 加后缀。
    • 日志清洗：按正则保留（如 ERROR|WARN）→ 去行尾空格 → 去重。
    • 「自然排序」按内嵌数字比较，item2 会排在 item10 前面。

    ④ 边界

    单次处理上限 5 万行 / 200 万字符，超出会提示，避免卡住页面。文本全程只在本机内存中处理，不上传、不保存。

    ① 六个 flag

    flag含义

    ② 替换串语法

    • $1 $2：第 n 个捕获组；$<name>：命名捕获组。
    • $&：整个匹配；$` / $'：匹配前 / 后的文本。
    • $$：字面量 $。替换串本身不写正则。

    ③ 性能保护（重要）

    • 测试文本超过 2 万字符会自动截断并提示；匹配条数上限 3000 条。
    • 检测到嵌套量词（如 (a+)+、(a*)*）会给出灾难性回溯警告。
    • JS 正则在主线程同步执行，无法强制中断；遇到疑似卡死的表达式请缩小测试文本。本工具不会把表达式发到任何服务器。

    ④ 语法差异

    使用浏览器原生 RegExp（JavaScript 方言），与 Python / PCRE / Java 略有差别：不支持反向断言以外的占有量词、\p{...} 需开 u。复制表达式到其他语言前请留意转义层数。

    📖 使用说明 · 算法清单 / JWT 验签范围 / 安全边界（点击展开）

    ① 哈希算法（纯 JS 内联实现）

    • MD5（128 位）、SHA-1（160 位）、SHA-256、SHA-512、CRC32。
    • 文本按 UTF-8 编码计算；文件按原始字节计算，结果与 md5sum / sha256sum / Node crypto 一致。
    • MD5 / SHA-1 已不抗碰撞，仅用于校验文件完整性、缓存键，不要用于密码存储或签名。
    • 密码存储请用 bcrypt / scrypt / Argon2（服务端），本工具不提供。

    ② JWT 解析

    • Base64URL 解出 header / payload 并格式化，自动把 exp iat nbf 转成本地时间，标出是否已过期。
    • 填入密钥后可校验 HS256 / HS384 / HS512 签名（HMAC + 常量时间比较）。
    • RS256 / ES256 等非对称算法只解码不验签，页面会明确提示；本工具不解析证书、不联网取 JWKS。
    • 解码不等于可信：没有验签的 payload 可以任意伪造。

    ③ HMAC 与随机串

    • HMAC 支持 MD5 / SHA-1 / SHA-256 / SHA-512，输出 Hex 或标准 Base64；可用于校验回调签名、生成简单 token。
    • 随机性来自 crypto.getRandomValues（密码学安全）；UUID v4、ULID（时间有序）、NanoID、随机密码同源。
    • ULID 前 10 位是毫秒时间戳（Crockford Base32），后 16 位是随机串，按时间大致有序。

    ④ 安全边界

    所有运算在浏览器内完成，无任何网络请求；密钥、token、明文不写入 localStorage、不持久化、刷新即清空。生成结果仅停留在当前页面，请自行妥善保存。本工具不替代服务端鉴权与密钥管理。

    📖 算法说明与边界（点击展开）

    ① 路由公式（与线上强绑定，未改动）

    • hashCode = String.hashCode(key)：h = 31·h + charAt(i)，按 32 位有符号 int 溢出。
    • hashCodeAb = Math.abs(int)（Integer.MIN_VALUE 时仍为负，逐字保留）。
    • 库：hashCodeAb % 32；表：(hashCodeAb / 32) % N；N 为 32（实例表）或 8（订单表）。
    • 完整路由：库名前缀 + 库号 + "." + 表名前缀 + 表号。

    ② 使用边界

    • 不要清洗输入：trim / 去 +86 / 去空格 / 改大小写都会改变 hashCode，导致库表与线上不一致。
    • 手机号模式仅做格式判断（^1[3-9]\d{9}$），不改写；虚拟号 / 订单号不校验。
    • 空串 hashCode = 0，恒落 0 库 0 表。
    • 路由仅依赖 hash 低 10 位（高 22 位丢弃），此为原实现特征，已保留。
    • 表名 / 库名前缀仅允许字母数字下划线且不以数字开头。
